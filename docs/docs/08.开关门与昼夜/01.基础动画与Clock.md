# 基础动画与 Clock：让 3D 场景"动起来"的底层机制

stage-07 之前的小屋是**静态**的——渲染一帧就停在那里，门永远关着、灯永远不亮、天空永远蓝天白云。从 stage-08 开始，我们要让它"活"起来：门能开能关、灯能亮能灭、天空会从白天变到黑夜。这一切的底层都依赖同一个机制：**渲染循环 + 时钟**。

本节是 stage-08 的"理论基石"：先讲清楚为什么 3D 应用必须"每帧重绘"，再讲清楚为什么不能简单用 `setInterval` 而要用 `requestAnimationFrame`，最后讲清楚为什么有了 `requestAnimationFrame` 还需要 `THREE.Clock` 来保证"帧率无关"。理解这三层之后，开关门和昼夜循环的代码就只是在这些基础上的"应用题"。

## 一、为什么需要渲染循环

### 1. 静态渲染 vs 动态渲染

stage-01 到 stage-07 的 `HouseScene.vue` 里其实已经有渲染循环，但因为场景不变化，你可能没注意到它的存在。我们看一段最简化的对比：

```js
import * as THREE from "three";

// 【静态渲染】只渲染一帧就结束（适合截图、生成静态图）
function renderOnce() {
  renderer.render(scene, camera);
}
renderOnce(); // 调用一次，画面就停在那里

// 【动态渲染】每帧都重新渲染（适合动画、交互）
function animate() {
  requestAnimationFrame(animate); // 关键：请求浏览器在下一帧再次调用本函数
  // 每帧更新场景状态（旋转、平移、改颜色...）
  cube.rotation.x += 0.01;
  renderer.render(scene, camera);
}
animate(); // 启动循环
```

关键区别在第 8 行的 `requestAnimationFrame(animate)`——这行代码告诉浏览器："请在下一次重绘之前，再调用一次 `animate` 函数"。于是 `animate` 函数会被反复调用，形成无限循环，每秒大约 60 次（与显示器刷新率一致）。

### 2. 浏览器的重绘机制

显示器每秒刷新 60 次（60Hz，部分高端显示器 120Hz / 144Hz）。浏览器在每次刷新之间会有一个"绘制窗口"，`requestAnimationFrame` 的回调就在这个窗口里执行：

```
时间轴（60Hz 显示器，每帧约 16.67ms）：
帧1: [执行 rAF 回调 → 渲染 → 显示]  帧间空隙
帧2: [执行 rAF 回调 → 渲染 → 显示]  帧间空隙
帧3: [执行 rAF 回调 → 渲染 → 显示]  ...
```

每帧 16.67ms 内，浏览器会：执行 JS 回调 → 计算 CSS → 布局 → 绘制 → 合成 → 显示。`requestAnimationFrame` 的回调执行时机就在"执行 JS"阶段，**与浏览器刷新同步**，这是它比 `setInterval` 更优秀的根本原因。

::: tip 类比理解
- `setInterval(fn, 16)` 像一个不管三七二十一每 16ms 就敲一次门的闹钟，哪怕浏览器正在忙别的也照敲
- `requestAnimationFrame(fn)` 像一个懂礼貌的助理，知道浏览器什么时候方便接见，只在合适时机来敲门
:::

## 二、requestAnimationFrame vs setInterval

### 1. 为什么不直接用 setInterval

新手最容易犯的错误是用 `setInterval` 来驱动动画：

```js
// ❌ 反面教材：用 setInterval 驱动 3D 动画
setInterval(() => {
  cube.rotation.x += 0.01;
  renderer.render(scene, camera);
}, 16); // 试图每 16ms 一次 ≈ 60fps
```

这种写法有几个严重问题：

| 问题 | setInterval | requestAnimationFrame |
|------|-------------|----------------------|
| 与显示器同步 | ❌ 不同步，会丢帧/撕裂 | ✅ 同步，无撕裂 |
| 后台标签页 | ❌ 继续跑，浪费 CPU/GPU | ✅ 自动暂停（一般降到 1fps） |
| 节流能力 | ❌ 无，会卡死主线程 | ✅ 浏览器自动节流 |
| 帧丢失处理 | ❌ 会"堆叠"回调 | ✅ 不会堆叠 |
| 移动端省电 | ❌ 不省电 | ✅ 省电 |

### 2. 正确的 rAF 写法

```js
// ✅ 正确写法：用 requestAnimationFrame 驱动
let animationId = null;

function animate() {
  // 关键：在函数开头请求下一帧，确保即使下面代码出错也能继续循环
  animationId = requestAnimationFrame(animate);

  // 更新场景状态
  cube.rotation.x += 0.01;

  // 渲染
  renderer.render(scene, camera);
}

animate(); // 启动

// 需要停止时（如组件卸载）
function stop() {
  if (animationId) cancelAnimationFrame(animationId);
}
```

::: warning 别忘了 cancelAnimationFrame
在 Vue 组件 `onUnmounted` 中一定要调用 `cancelAnimationFrame` 取消循环。否则组件销毁后回调还在跑，会报"webgl context lost"错误，而且持续占用 GPU。stage-08 的 `HouseScene.vue` 在 `disposeScene()` 里就做了这件事：

```js
const disposeScene = () => {
  if (animationId) cancelAnimationFrame(animationId);
  // ...其他清理
};
```
:::

## 三、为什么需要 THREE.Clock：帧率无关

### 1. 帧率问题演示

假设我们写一段"每帧旋转 0.01 弧度"的代码：

```js
function animate() {
  requestAnimationFrame(animate);
  cube.rotation.x += 0.01; // 每帧固定 +0.01
  renderer.render(scene, camera);
}
```

在 60fps 显示器上，每秒旋转 `0.01 * 60 = 0.6` 弧度；在 30fps 显示器（或浏览器卡顿时）上，每秒只旋转 `0.01 * 30 = 0.3` 弧度——**动画速度慢了一半**！这就是"帧率相关"动画的问题：同样的代码在不同设备上速度不同。

### 2. 用 Clock 解决：基于时间而不是基于帧

`THREE.Clock` 提供了 `getDelta()` 方法，返回**距离上一帧的真实时间间隔**（秒）。用它就能写出"帧率无关"的动画：

```js
import * as THREE from "three";

const clock = new THREE.Clock();

function animate() {
  requestAnimationFrame(animate);
  // getDelta() 返回距离上次调用 getDelta() 的时间间隔（秒）
  const dt = clock.getDelta(); // 60fps 下 ≈ 0.0167s，30fps 下 ≈ 0.0333s

  // 关键：用"角速度 × dt"代替"每帧固定角度"
  // 0.6 弧度/秒 × dt：60fps 下每帧 0.6×0.0167=0.01，30fps 下每帧 0.6×0.0333=0.02
  // 但每秒累计都是 0.6 弧度！动画速度一致
  cube.rotation.x += 0.6 * dt; // 0.6 弧度/秒

  renderer.render(scene, camera);
}
```

::: tip 公式：帧率无关动画
任何基于"速度"的动画都该写成：

```
position += speed * dt;
```

而不是：

```
position += stepPerFrame; // ❌ 帧率相关
```

其中 `dt = clock.getDelta()`，`speed` 是"每秒变化量"。
:::

### 3. Clock 的几个常用方法

| 方法 | 返回值 | 用途 |
|------|--------|------|
| `getDelta()` | 距上次调用 `getDelta()` 的时间（秒） | 帧率无关动画的核心 |
| `getElapsedTime()` | 自 `Clock` 创建以来的总时间（秒） | 周期性动画（如 `Math.sin(t)`） |
| `start()` / `stop()` | 无 | 手动启停 |
| `getElapsedTime()` 配合 sin | 周期值 | 做往复运动 |

```js
const clock = new THREE.Clock();

function animate() {
  requestAnimationFrame(animate);
  const t = clock.getElapsedTime(); // 累计总时间
  // 用 sin 做往复运动：振幅 1，周期 2 秒
  cube.position.y = Math.sin(t * Math.PI) * 1.0; // 上下浮动
  renderer.render(scene, camera);
}
```

::: warning getDelta 的副作用
`getDelta()` 内部会重置"上次时间"，所以**每帧只能调用一次**。如果你在 `animate` 里多次调用，第二次以后的返回值会非常小（接近 0）。stage-08 的 `HouseScene.vue` 里只在 `animate` 顶部调用一次 `clock.getDelta()`，然后把 `dt` 传给各个更新函数：

```js
const animate = () => {
  animationId = requestAnimationFrame(animate);
  const dt = clock.getDelta(); // 整帧只调用一次
  controls.update();
  updateDoor(dt);       // 门动画用 dt
  updateLamp(dt);       // 灯动画用 dt
  updateDayNight(dt);   // 昼夜循环用 dt
  renderer.render(scene, camera);
};
```
:::

## 四、lerp：平滑过渡的万能公式

### 1. 线性插值 lerp 是什么

`lerp`（linear interpolation，线性插值）是动画系统里出现频率最高的函数。它的核心思想是：**让一个值平滑地接近另一个值，而不是瞬间跳变**。

```js
import * as THREE from "three";

// 通用 lerp 公式：让 current 向 target 移动 factor 比例
function lerp(current, target, factor) {
  return current + (target - current) * factor;
}

// Three.js 内置：
// THREE.MathUtils.lerp(current, target, t)
// 颜色专门有 Color.lerp(color2, t)
// 向量专门有 Vector3.lerp(v2, t)
```

`factor` 是 [0, 1] 之间的比例：0 表示不动，1 表示一步到位，0.1 表示每次移动剩余距离的 10%。

### 2. lerp 的"指数衰减"特性

`lerp` 的一个重要特性是"指数衰减"——每帧移动剩余距离的固定比例，所以越接近目标移动越慢，呈现自然的"减速到停止"效果：

```js
// 假设 current=0, target=1, factor=0.1
// 第 1 帧：0 + (1-0)*0.1 = 0.1
// 第 2 帧：0.1 + (1-0.1)*0.1 = 0.19
// 第 3 帧：0.19 + (1-0.19)*0.1 = 0.271
// ...
// 永远到不了 1，但越来越接近
```

这种"无限接近但永不到达"的特性在视觉上很自然，门慢慢停下、灯光慢慢变亮，都靠它。

### 3. 帧率无关的 lerp

但 `lerp` 有个和"每帧固定步进"一样的帧率问题——不同帧率下衰减速度不同。解决方法是用 `dt` 调整 `factor`：

```js
// 帧率相关 lerp（不同帧率速度不同）
current = THREE.MathUtils.lerp(current, target, 0.1);

// 帧率无关 lerp（推荐）
// speed 越大越快，10 表示约 0.1 秒到位
const speed = 8;
const factor = Math.min(1, speed * dt); // 限制在 [0,1]
current = THREE.MathUtils.lerp(current, target, factor);
```

stage-08 的门动画和灯动画都用了这个模式：

```js
// 来自 HouseScene.vue 的 updateDoor
const updateDoor = (dt) => {
  if (!doorGroup) return;
  const targetAngle = doorState * (Math.PI / 2); // 0 或 90°
  const speed = 8; // 速度因子
  doorAngle += (targetAngle - doorAngle) * Math.min(1, speed * dt);
  doorGroup.rotation.y = doorAngle;
};
```

::: tip 为什么不直接用 t = 1 瞬间到位
如果 `factor = 1`，门会从 0° 直接跳到 90°，看起来像"瞬间移动"，没有任何动画感。`lerp` 的价值就在于让中间过程平滑可见。
:::

## 五、stage-08 的渲染循环骨架

把上面所有概念串起来，stage-08 的 `animate` 函数就长这样：

```js
import * as THREE from "three";

let clock = null;
let animationId = null;

const initScene = () => {
  // ...场景/相机/渲染器初始化
  clock = new THREE.Clock(); // 创建时钟
};

const animate = () => {
  animationId = requestAnimationFrame(animate); // 1. 请求下一帧
  const dt = clock.getDelta(); // 2. 取帧间隔（每帧只调一次）

  controls.update(); // 3. 控制器阻尼更新
  updateDoor(dt); // 4. 门动画（用 dt）
  updateLamp(dt); // 5. 灯动画（用 dt）
  updateDayNight(dt); // 6. 昼夜循环（用 dt）

  renderer.render(scene, camera); // 7. 渲染本帧
};

onMounted(() => {
  initScene();
  // ...添加场景内容
  animate(); // 启动渲染循环
});

onUnmounted(() => {
  if (animationId) cancelAnimationFrame(animationId); // 关键：停止循环
  // ...其他 dispose
});
```

这就是 stage-08 全部动画的"骨架"——后面两节的开关门和昼夜循环都只是填充 `updateDoor` / `updateLamp` / `updateDayNight` 这三个函数而已。

## 六、本节总结

- **渲染循环**：3D 动画的核心是"每帧重绘"，用 `requestAnimationFrame(animate)` 形成无限循环，每秒约 60 次
- **rAF 优于 setInterval**：与显示器同步、后台自动暂停、不丢帧、省电
- **Clock.getDelta()**：返回距上一帧的真实时间间隔 `dt`，是"帧率无关动画"的关键——所有"速度"都要写成 `speed * dt` 而不是固定步进
- **lerp 平滑过渡**：`current += (target - current) * factor` 让数值平滑接近目标，配合 `dt` 可做帧率无关的 lerp：`factor = Math.min(1, speed * dt)`
- **资源释放**：组件卸载时一定要 `cancelAnimationFrame(animationId)`，否则循环不会停

这三件套——`requestAnimationFrame` + `Clock.getDelta()` + `lerp`——是 Three.js 动画系统的"基础设施"。理解了它们，下一节的开关门动画就只是一道"几何变换 + 旋转插值"的应用题。
