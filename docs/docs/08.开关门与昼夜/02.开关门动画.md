# 开关门动画：门轴 pivot 与键盘交互

理解了渲染循环和 lerp 之后，我们来做 stage-08 的第一个实战动画：**按 O 键，木门绕门轴平滑打开 90°；再按一下，又平滑关闭**。

听起来简单，但实际写起来会卡在一个经典几何难题上：**怎么让门绕"门轴"旋转，而不是绕"自身中心"自旋？** 这个问题不解决，门会原地打转而不是打开。本节围绕这个核心问题展开，介绍 Three.js 动画里超高频的"`Group` 当 pivot（轴心）"技巧。

## 一、问题：直接旋转门板会发生什么

stage-03 我们做的木门是一个 `BoxGeometry(1.0, 2.0, 0.05)`，几何中心在 `(0, 1.3, 3.125)`（门洞中心位置）。如果直接给门板设置 `rotation.y`：

```js
// ❌ 反面教材：直接旋转门板
const door = new THREE.Mesh(
  new THREE.BoxGeometry(1.0, 2.0, 0.05),
  doorMat
);
door.position.set(0, 1.3, 3.125); // 门板中心在门洞中央
scene.add(door);

// 试图开门
door.rotation.y = Math.PI / 2; // 绕 Y 轴转 90°
```

结果会是：**门绕自己的几何中心（即门板正中央）旋转 90°**，门板的一半会嵌进门洞左边的墙里，另一半凸出到门洞右边——根本不是开门效果，而是"门板原地横过来了"。

正确效果应该是：门板绕**门洞左边缘**（即门轴）旋转，门板的右侧远端划出一道圆弧，整个门板转 90° 后与墙面垂直。

## 二、解法：用 Group 当门轴 pivot

### 1. pivot 的核心思想

Three.js 里所有 `Object3D`（包括 Mesh 和 Group）的 `rotation` 都是绕**自身原点（局部坐标 (0,0,0)）**旋转。所以要让门绕门轴旋转，需要让门轴位置成为"旋转中心"——做法是：

1. 创建一个 `Group`，把它的 `position` 设到门轴位置
2. 把门板作为 `Group` 的子级，但门板几何中心在 Group 局部坐标里**偏移**到门轴右侧（偏移量 = 门宽的一半）
3. 旋转 `Group.rotation.y`——这时门板就会绕 Group 原点（也就是门轴）转

### 2. 坐标推导

按 HOUSE_SPEC，门洞中心 `(0, 1.3, 3)`，门宽 1.0m，所以门洞左边缘 `x = -0.5`。这就是门轴位置：

```
俯视图（从 +Y 向下看，z 轴向上）：

   墙面（z=3.1，向 +Z 凸出）
   ─────────────────────────
   |   门洞左边缘    门洞右边缘
   |       ┃           ┃
   |      -0.5         +0.5
   |       ┃           ┃
   |       ▼           ▼
   |      门轴       门板右侧
   |     (pivot)    （会划弧）
   |       ┏━━━━━━━━━━┓
   |       ┃   门板    ┃
   |       ┗━━━━━━━━━━┛
   |       └ 门板中心 x=0
   ─────────────────────────
```

- **门轴 Group 世界坐标**：`(-0.5, 1.3, 3.125)`（z 略凸出墙面 0.025）
- **门板在 Group 局部坐标**：`(0.5, 0, 0)`（向右偏移半门宽）
- **旋转**：`doorGroup.rotation.y` 从 0 → π/2（90°），门板会绕 x=-0.5 这条竖线转动

::: tip 关键直觉
Group 的局部原点 = 旋转中心。把子物体偏移到一边，子物体就会绕 Group 原点画弧——这就是 pivot 的全部秘密。
:::

### 3. 代码实现

```js
import * as THREE from "three";

// 门轴 Group：position 在门洞左边缘
const doorGroup = new THREE.Group();
doorGroup.position.set(-0.5, 1.3, 3.125); // 关键 1：Group 原点 = 门轴
doorGroup.rotation.y = 0; // 初始关闭（门板与墙面平行）

// 门板：几何中心在 Group 局部坐标偏移到右侧
const doorPanel = new THREE.Mesh(
  new THREE.BoxGeometry(1.0, 2.0, 0.05), // 宽 1.0，高 2.0，厚 0.05
  doorMat
);
doorPanel.position.set(0.5, 0, 0); // 关键 2：门板偏移半门宽到右侧
doorPanel.castShadow = true;
doorPanel.receiveShadow = true;
doorGroup.add(doorPanel);

houseGroup.add(doorGroup);
```

## 三、动画状态机：目标值 + 当前值 + lerp

### 1. 双状态变量模式

开关门动画的核心是一个**状态机**——按 O 键切换"目标状态"，每帧把"当前角度"lerp 向"目标角度"。这是 Three.js 里写交互式动画的标准模式：

```js
// 状态变量
let doorGroup = null;       // 门轴 Group
let doorState = 0;          // 目标状态：0=关，1=开
let doorAngle = 0;          // 当前角度（弧度），每帧 lerp 向目标
```

为什么需要两个变量（`doorState` 和 `doorAngle`）？

- `doorState` 是"目标"，按 O 键时立刻翻转（0↔1），代表"用户想干嘛"
- `doorAngle` 是"当前实际值"，每帧平滑追赶目标，代表"门现在转到哪了"

这种"目标 + 当前"分离的模式让交互非常自然——用户连续按 O 也能立刻响应（目标翻转），但视觉上门会平滑追赶，不会瞬间跳变。

### 2. 渲染循环里更新门角度

```js
import * as THREE from "three";

const updateDoor = (dt) => {
  if (!doorGroup) return;
  // 目标角度：doorState=0 → 0 弧度（关），doorState=1 → π/2 弧度（90° 开）
  const targetAngle = doorState * (Math.PI / 2);

  // 帧率无关 lerp（来自上一节的公式）
  const speed = 8; // 速度因子，越大越快，8 表示约 0.125 秒到位
  doorAngle += (targetAngle - doorAngle) * Math.min(1, speed * dt);

  // 应用到 Group 旋转
  doorGroup.rotation.y = doorAngle;
};
```

::: tip 为什么 speed=8 大约是 0.125 秒到位
`factor = speed * dt`，60fps 下 dt≈0.0167，所以 factor≈0.133，即每帧追赶剩余距离的 13.3%。指数衰减下大约 `log(0.05)/log(0.867) ≈ 21 帧` 降到 5% 以下，21 帧 / 60fps ≈ 0.35 秒。实际感觉是"约 0.1~0.3 秒到位"，速度自然。如果想更快，调大 `speed`。
:::

## 四、键盘交互：监听 keydown

### 1. 基本写法

按 O 键切换门状态——就是 `window.addEventListener('keydown', ...)`：

```js
const onKeyDown = (e) => {
  const key = e.key.toLowerCase(); // 统一转小写，兼容大小写锁定
  if (key === "o") {
    // 切换门目标状态：0 → 1，1 → 0
    doorState = doorState === 0 ? 1 : 0;
    ui.doorState = doorState === 1 ? "开启" : "关闭"; // 更新 UI 文案
  } else if (key === "l") {
    // 切换室内灯目标状态
    lampOn = !lampOn;
    ui.lampState = lampOn ? "开启" : "关闭";
  }
};

onMounted(() => {
  // ...
  window.addEventListener("keydown", onKeyDown);
});

onUnmounted(() => {
  // 关键：组件卸载时移除监听
  window.removeEventListener("keydown", onKeyDown);
  // ...
});
```

### 2. 为什么用 e.key 而不是 e.keyCode

`e.key` 返回字符串（如 `"o"`、`"O"`、`"Enter"`、`" "`），可读性好且兼容大小写（用 `toLowerCase()` 统一）。`e.keyCode` 已废弃，不同浏览器还有差异。

### 3. 注意点：canvas 焦点问题

`window` 级监听不依赖焦点，鼠标点不点画布都能响应。如果改成 `canvas.addEventListener('keydown', ...)`，需要 canvas 有 `tabindex` 才能获得焦点——stage-08 用 `window` 监听更省心。

## 五、Vue 响应式 UI 同步

stage-08 在画面上叠加了状态卡片，显示"门：开启/关闭"。这需要把 Three.js 的状态同步到 Vue 的响应式数据：

```js
import { reactive } from "vue";

// 响应式 UI 状态
const ui = reactive({
  doorState: "关闭",
  lampState: "关闭",
  phase: "白天",
});

// 在 onKeyDown 中更新
const onKeyDown = (e) => {
  const key = e.key.toLowerCase();
  if (key === "o") {
    doorState = doorState === 0 ? 1 : 0;
    ui.doorState = doorState === 1 ? "开启" : "关闭"; // 触发 Vue 重渲染
  }
  // ...
};
```

template 里直接绑定：

```html
<div>
  门：<span :style="{ color: ui.doorState === '开启' ? '#67c23a' : '#909399' }">
    {{ ui.doorState }}
  </span>
</div>
```

::: tip 三层关注点分离
stage-08 的 HouseScene.vue 维护三层状态：
1. **Three.js 状态**（`doorState`、`doorAngle`）—— 驱动 3D 渲染
2. **Vue 响应式状态**（`ui.doorState`）—— 驱动 HTML 文案
3. **DOM 事件**（`keydown`）—— 触发状态切换

三者各司其职：用户按键 → 改 Three.js 目标值 + 同步 Vue 状态 → 渲染循环每帧 lerp 实际值 + 重绘 3D + Vue 自动重渲染 HTML。
:::

## 六、完整开关门代码（来自 HouseScene.vue）

把上面所有片段串起来，stage-08 的开关门完整代码：

```js
import * as THREE from "three";

// 状态变量
let doorGroup = null;
let doorState = 0;          // 目标：0 关 / 1 开
let doorAngle = 0;          // 当前角度（弧度）

// 创建门 + 门轴 pivot
const addWallsAndDoor = (houseGroup) => {
  // ... 墙体代码省略（详见 stage-03）

  // 木门材质
  const doorMat = new THREE.MeshStandardMaterial({
    color: 0x8b5a2b,
    map: makeWoodTexture(),
    roughness: 0.6,
  });

  // 门轴 Group：原点 = 门洞左边缘
  doorGroup = new THREE.Group();
  doorGroup.position.set(-0.5, 1.3, 3.125); // 门轴位置
  doorGroup.rotation.y = 0;                  // 初始关闭

  // 门板：偏移到门轴右侧
  const doorPanel = new THREE.Mesh(
    new THREE.BoxGeometry(1.0, 2.0, 0.05),
    doorMat
  );
  doorPanel.position.set(0.5, 0, 0); // 关键偏移
  doorPanel.castShadow = true;
  doorPanel.receiveShadow = true;
  doorGroup.add(doorPanel);

  houseGroup.add(doorGroup);
};

// 键盘交互
const onKeyDown = (e) => {
  const key = e.key.toLowerCase();
  if (key === "o") {
    doorState = doorState === 0 ? 1 : 0;
    ui.doorState = doorState === 1 ? "开启" : "关闭";
  }
  // ... L 键代码见下一节
};

// 每帧更新门角度
const updateDoor = (dt) => {
  if (!doorGroup) return;
  const targetAngle = doorState * (Math.PI / 2);
  const speed = 8;
  doorAngle += (targetAngle - doorAngle) * Math.min(1, speed * dt);
  doorGroup.rotation.y = doorAngle;
};

// 渲染循环
const animate = () => {
  animationId = requestAnimationFrame(animate);
  const dt = clock.getDelta();
  controls.update();
  updateDoor(dt); // 门动画
  // ...
  renderer.render(scene, camera);
};
```

## 七、扩展：从门轴到机械臂、角色骨骼

"用 Group 当 pivot" 这个技巧远不止用在门上——它是 Three.js 里所有"绕非中心点旋转"问题的通用解法：

| 场景 | pivot 怎么设 |
|------|--------------|
| 门绕门轴 | pivot 在门洞边缘 |
| 时钟分针绕表盘中心 | pivot 在表盘中心，针偏移到外圈 |
| 机械臂关节 | 每节臂的 pivot 在上一个关节处，层层嵌套 |
| 太阳系（行星绕太阳） | pivot 在太阳中心，行星偏移到轨道半径 |
| 角色胳膊绕肩膀 | pivot 在肩膀，胳膊偏移到下方 |

::: tip 进阶预告
stage-09 我们会加载 glTF 家具模型，stage-12 烟囱粒子也会用到类似的"局部坐标偏移"思路。把"Group 当 pivot"练成肌肉记忆，后面所有"绕某个点旋转"的需求都不再是问题。
:::

## 八、本节总结

- **核心问题**：直接旋转门板会绕自身中心自旋，必须用 Group 充当门轴 pivot
- **坐标推导**：Group 原点放在门洞左边缘 `(-0.5, 1.3, 3.125)`，门板在 Group 局部坐标偏移 `(0.5, 0, 0)`
- **状态机**：`doorState`（目标 0/1）+ `doorAngle`（当前弧度），每帧用帧率无关 lerp 让 `doorAngle` 平滑追赶 `doorState * π/2`
- **键盘交互**：`window.addEventListener('keydown', ...)`，按 O 键翻转 `doorState`，同步 Vue 响应式数据更新 UI
- **通用价值**：Group 当 pivot 是机械臂、太阳系、角色关节等所有"绕非中心点旋转"问题的标准解法

::: warning 别忘了 dispose doorGroup
`doorGroup` 内的 `doorPanel` 没挂到 `disposables` 数组，必须在 `disposeScene` 中单独 traverse 释放。stage-08 的代码里这么写：

```js
if (doorGroup) {
  doorGroup.traverse((obj) => {
    if (obj.geometry) obj.geometry.dispose();
    if (obj.material) {
      if (Array.isArray(obj.material)) obj.material.forEach((m) => m.dispose());
      else obj.material.dispose();
    }
  });
  if (doorGroup.parent) doorGroup.parent.remove(doorGroup);
  doorGroup = null;
}
```
:::
