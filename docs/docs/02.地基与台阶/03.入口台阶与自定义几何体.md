# 入口台阶与自定义几何体

地基铺好后，门口还差两级台阶——否则地基顶面 y = 0.3 比草地高出 0.3m，进屋得「跳」上去。本节我们用两块 `BoxGeometry` 拼出 2 级台阶，让访客可以拾级而上；然后再用 `BufferGeometry` 手动定义顶点，构建一个**自定义三角面斜坡**作为对比演示，理解 Three.js 几何体的最底层结构。

## 1. 台阶设计回顾

按 HOUSE_SPEC 规范，入口台阶是 2 级：

| 属性 | 第一级（低、远） | 第二级（高、近） |
|------|------------------|------------------|
| 几何体 | `BoxGeometry(1.5, 0.15, 0.4)` | `BoxGeometry(1.5, 0.15, 0.4)` |
| 中心坐标 | `(0, 0.075, 3.2)` | `(0, 0.225, 3.0)` |
| 顶面 y | 0.15 | 0.30（与地基顶面齐平） |
| 颜色 | `#909399` 信息灰 | `#909399` 信息灰 |

台阶整体宽 1.5m（X 方向，刚好对应 stage-03 的门洞宽 1.0m 加两边留 0.25m），每级高 0.15m，深 0.4m。两级加起来高 0.3m，正好把人从草地 y = 0 接到地基顶面 y = 0.3。

::: tip 为什么是 2 级而不是 1 级
0.3m 的高度如果做成 1 级，单级踏步高 0.3m，相当于一个膝盖那么高，爬起来非常吃力。拆成 2 级后每级 0.15m，是真实建筑里踏步的常见高度（一般 0.15~0.18m）。本教程虽然是虚拟场景，但遵循真实建筑尺度能让小屋更有「人味儿」，不至于像玩具。
:::

## 2. 两级台阶的尺寸与位置推算

### 2.1 共享同一份 geometry

两级台阶的尺寸完全相同：`BoxGeometry(1.5, 0.15, 0.4)`。所以本阶段**两块台阶共用同一份 geometry 与 material**——这是 Three.js 的常见优化：相同形状的物体只创建一次几何体数据，多个 Mesh 引用它即可，节省显存。

```js
import * as THREE from "three";

// 两级台阶共用一份 geometry + material
const stepGeo = new THREE.BoxGeometry(1.5, 0.15, 0.4);
const stepMat = new THREE.MeshStandardMaterial({
  color: 0x909399, // 与地基同灰
  roughness: 0.8,
  metalness: 0.0,
});

// 第一级（低、远）
const step1 = new THREE.Mesh(stepGeo, stepMat);
step1.position.set(0, 0.075, 3.2);
scene.add(step1);

// 第二级（高、近）
const step2 = new THREE.Mesh(stepGeo, stepMat);
step2.position.set(0, 0.225, 3.0);
scene.add(step2);
```

::: warning 共享资源的 dispose 陷阱
两块台阶共享同一份 `stepGeo` 与 `stepMat`，dispose 时**只能调用一次**。如果对每个 Mesh 都调用 `mesh.geometry.dispose()`，会导致同一份 geometry 被 dispose 两次。本教程的 `HouseScene.vue` 用一个 `disposableGeometries` 数组**登记时只 push 一次**，清理时遍历释放，确保安全：

```js
// 只 push 一次（创建 geometry 之后）
disposableGeometries.push(stepGeo);
disposableMaterials.push(stepMat);

// 创建两个 Mesh 引用同一份资源
const step1 = new THREE.Mesh(stepGeo, stepMat);
const step2 = new THREE.Mesh(stepGeo, stepMat);

// dispose 时遍历数组，每份资源只释放一次
disposableGeometries.forEach((g) => g.dispose());
disposableMaterials.forEach((m) => m.dispose());
```
:::

### 2.2 第一级 position 推算

第一级（低、远）位于 `(0, 0.075, 3.2)`：

- **Y = 0.075**：高度 0.15m，底面贴地 → `position.y = 0.15 / 2 = 0.075`，顶面在 `y = 0.15`
- **Z = 3.2**：地基前缘在 `z = 3`，第一级探出 0.2m → `z = 3 + 0.2 = 3.2`
- **X = 0**：居中，与地基中心对齐

第一级的顶面 y = 0.15 是「中间过渡面」，访客踩着它再上到第二级。

### 2.3 第二级 position 推算

第二级（高、近）位于 `(0, 0.225, 3.0)`：

- **Y = 0.225**：高度 0.15m，底面在第一级顶面 y = 0.15 → `position.y = 0.15 + 0.15 / 2 = 0.225`，顶面在 `y = 0.30`
- **Z = 3.0**：紧贴地基前缘 `z = 3`（地基前缘正好是 `0 + depth / 2 = 3`）
- **X = 0**：居中

第二级顶面 y = 0.30 **与地基顶面齐平**——这是台阶设计的关键，访客踩上第二级就能直接走到地基顶面上，无缝衔接。

::: tip 台阶与地基的「无缝对齐」
注意第二级 Z = 3.0 正好等于地基前缘 Z = 3.0。两者在 Z 方向紧贴，没有缝隙也没有重叠。第二级顶面 y = 0.3 等于地基顶面 y = 0.3，两者在 Y 方向也无缝衔接。这种「边界对齐」是 3D 建模的基本功，避免出现穿模或缝隙。

如果你看到的台阶与地基之间有缝隙，多半是浮点精度问题——可以将台阶 Z 改成 `3.001` 让它略微嵌入地基，肉眼就看不到缝了。
:::

## 3. 完整代码：铺设两级台阶

下面是 `HouseScene.vue` 里铺设台阶的核心片段。注意 `stepGeo` 与 `stepMat` 只创建一份，然后两个 Mesh 共享：

```js
import * as THREE from "three";

// === 入口台阶（2 级，共享 geometry 与 material）===
// 每级 BoxGeometry(1.5, 0.15, 0.4)：1.5m 宽 × 0.15m 高 × 0.4m 深
const stepGeo = new THREE.BoxGeometry(1.5, 0.15, 0.4);
const stepMat = new THREE.MeshStandardMaterial({
  color: 0x909399, // 与地基同灰
  roughness: 0.8,
  metalness: 0.0,
});

// 重要：共享资源只登记一次，避免重复 dispose
disposableGeometries.push(stepGeo);
disposableMaterials.push(stepMat);

// 第一级（低、远）：顶面 y=0.15，探出地基前缘 0.2m
const step1 = new THREE.Mesh(stepGeo, stepMat);
step1.position.set(0, 0.075, 3.2);
scene.add(step1);

// 第二级（高、近）：顶面 y=0.30，紧贴地基前缘
const step2 = new THREE.Mesh(stepGeo, stepMat);
step2.position.set(0, 0.225, 3.0);
scene.add(step2);
```

运行后你应该看到地基前缘探出两级灰色台阶，从下往上看：草地 → 第一级（顶面 y=0.15）→ 第二级（顶面 y=0.30）→ 地基顶面。每一级高度都是 0.15m，拾级而上的体验自然。

## 4. 自定义几何体：BufferGeometry 入门

如果台阶的形状不是规则长方体——比如想做一条**斜坡**让小车推上去，或者做一个**三角面装饰**——`BoxGeometry` 就不够用了。这时需要用 `BufferGeometry` 手动定义顶点。本节我们用 `BufferGeometry` 构建一个简单的**三角面斜坡**作为对比演示，理解 Three.js 几何体的最底层结构。

### 4.1 BufferGeometry 四要素

`BufferGeometry` 是所有内置几何体的基类。它不存储「这是一个台阶」这样的语义信息，而是直接持有最底层的**顶点缓冲区数据**：

| 属性 | 含义 | 每顶点数据数 | 是否必需 |
|------|------|-------------|---------|
| `position` | 顶点位置 (x, y, z) | 3 | 必需 |
| `normal` | 法线向量，决定光照朝向 | 3 | 受光照时必需 |
| `uv` | 纹理坐标 | 2 | 使用贴图时必需 |
| `color` | 顶点颜色 | 3 | 顶点着色时使用 |
| `index` | 顶点索引（不属于 attribute，独立存储） | 1 | 可选，用于复用顶点 |

::: tip 三角形是基本单元
WebGL 中所有面都由**三角形**组成，3 个顶点构成一个三角形。一个矩形 = 2 个三角形，一个立方体 = 12 个三角形。`BufferGeometry` 让我们直接控制这些顶点和三角形索引，所以可以构建任意形状。
:::

### 4.2 构建一个三角面斜坡

我们要构建的斜坡形状如下（侧视图）：

```
高度 0.3 ──────╮
              │ ╲
              │   ╲  斜面（访客走上去）
              │     ╲
高度 0   ─────┴──────╯
        -0.75  0    0.75   (X 方向，宽 1.5m)
```

这是一个直角三角形挤出的「斜坡」：底面在 y = 0，顶面在 y = 0.3，斜面从右下连到左上。我们用 6 个顶点（前后两面各 3 个）+ 8 个三角形索引构建它。

```js
import * as THREE from "three";

const rampGeo = new THREE.BufferGeometry();

// 6 个顶点（前后面各 3 个）
// 前面（Z = +0.2）：左下、右下、左上
// 后面（Z = -0.2）：左下、右下、左上
const vertices = new Float32Array([
  // 前面
  -0.75, 0.0,  0.2,  // 0：左下前
   0.75, 0.0,  0.2,  // 1：右下前
  -0.75, 0.3,  0.2,  // 2：左上前
  // 后面
  -0.75, 0.0, -0.2,  // 3：左下后
   0.75, 0.0, -0.2,  // 4：右下后
  -0.75, 0.3, -0.2,  // 5：左上后
]);

// 索引：定义顶点如何组成三角形
// 注意：顶点顺序按逆时针（从面外看）才是正面
const indices = new Uint16Array([
  // 前面三角形（0, 1, 2）
  0, 1, 2,
  // 后面三角形（3, 5, 4，注意顺序与前面镜像）
  3, 5, 4,
  // 底面（0, 4, 1 + 0, 3, 4）
  0, 4, 1,
  0, 3, 4,
  // 左竖直面（0, 2, 3 + 2, 5, 3）
  0, 2, 3,
  2, 5, 3,
  // 斜面（1, 4, 2 + 2, 4, 5）—— 访客走上去的面
  1, 4, 2,
  2, 4, 5,
]);

rampGeo.setAttribute("position", new THREE.BufferAttribute(vertices, 3));
rampGeo.setIndex(new THREE.BufferAttribute(indices, 1));

// 自动计算法线（根据顶点位置和索引）
rampGeo.computeVertexNormals();

const rampMat = new THREE.MeshStandardMaterial({
  color: 0xe6a23c, // Element Plus 警告色（黄色斜坡，便于区分台阶）
  roughness: 0.6,
  metalness: 0.0,
  side: THREE.DoubleSide, // 双面渲染，避免背面看不见
});
const ramp = new THREE.Mesh(rampGeo, rampMat);
ramp.position.set(2.5, 0, 3.2); // 放在台阶右侧作为对比
scene.add(ramp);
```

::: warning 顶点顺序与正面方向
WebGL 默认采用**逆时针（CCW）**顶点顺序作为正面（FrontSide）。如果顶点按顺时针排列，该面会被视为背面，默认渲染时不可见。这就是有时模型"透明"或"看不到"的常见原因——可通过 `side: THREE.DoubleSide` 临时排查。

上面斜坡代码里，「前面」三角形是 `0, 1, 2`（从 +Z 方向看逆时针），「后面」三角形是 `3, 5, 4`（从 -Z 方向看逆时针，即从 +Z 看 clockwise，所以顺序与前面镜像）。如果你看到的斜坡某面透明，把那个面的三角形顶点顺序反转即可。
:::

### 4.3 computeVertexNormals 自动算法线

受光照的 `MeshStandardMaterial` 需要 `normal` 属性才能正确计算明暗。手动为每个顶点定义法线很繁琐，Three.js 提供 `computeVertexNormals()`，根据顶点位置和索引自动计算每个顶点的法线（取共享该顶点的所有三角形面法线的平均）：

```js
// 必须在 setAttribute("position") 和 setIndex 之后调用
rampGeo.computeVertexNormals();
```

::: warning computeVertexNormals 的局限
`computeVertexNormals()` 计算的是**共享顶点的面法线平均值**，会让相邻面之间的过渡变平滑。这对球体是想要的，但对立方体却是灾难——棱角会变圆滑。上面的斜坡用 6 个独立顶点（每面顶点不共享），所以 `computeVertexNormals()` 算出的法线互不影响，棱角保持锐利。这与 `BoxGeometry` 内部用 24 个独立顶点（每面 4 个）的做法一致。
:::

## 5. 内置 vs 自定义：何时用哪个

| 维度 | 内置几何体 | 自定义 BufferGeometry |
|------|-----------|---------------------|
| 适用场景 | 规则形状（立方体、球、圆柱、圆环等） | 不规则形状、有机形状、从外部加载的模型数据 |
| 开发效率 | 一行代码搞定 | 需要手动定义每个顶点 |
| 性能 | 内部优化过，索引合理 | 取决于你的实现，可能不如内置 |
| 灵活性 | 受参数限制 | 完全自由，可逐顶点控制 |
| 法线 | 自动生成 | 需 `computeVertexNormals()` 或手动 |
| UV | 自动生成 | 需手动定义（如需贴图） |

欧式小屋项目里 95% 的构件用内置几何体就够了：地基、台阶、墙体、门板都是 `BoxGeometry`；屋顶用 `ConeGeometry` 或两块倾斜 `BoxGeometry`；烟囱用 `BoxGeometry` + `CylinderGeometry`。只有 stage-04 的山墙三角形、stage-10 的草地着色器才会用到自定义 `BufferGeometry`。

::: tip 优先用内置几何体
初学者常见的误区是「什么都自己写 BufferGeometry」。实际上 Three.js 内置的 13 种几何体已经覆盖了绝大多数场景，且经过优化。**只有当内置几何体无法满足需求时**，才考虑自定义 `BufferGeometry`。本节用自定义斜坡只是为了教学底层结构，实际项目里这种斜坡可以用 `BoxGeometry` + 旋转或 `ExtrudeGeometry` 实现。
:::

## 7. 完整 dispose 流程

本阶段 `HouseScene.vue` 的 `disposeScene()` 函数清理所有资源，顺序如下：

```js
const disposeScene = () => {
  // 1. 停止渲染循环
  if (animationId) {
    cancelAnimationFrame(animationId);
    animationId = null;
  }

  // 2. 移除事件监听
  window.removeEventListener("resize", handleResize);

  // 3. 释放轨道控制器
  if (controls) {
    controls.dispose();
    controls = null;
  }

  // 4. 释放辅助工具
  if (axesHelper) axesHelper.dispose();
  if (gridHelper) {
    gridHelper.geometry.dispose();
    gridHelper.material.dispose();
  }

  // 5. 释放所有几何体与材质（含共享的 stepGeo / stepMat，只释放一次）
  disposableGeometries.forEach((g) => g.dispose());
  disposableMaterials.forEach((m) => m.dispose());

  // 6. 释放渲染器
  if (renderer) renderer.dispose();

  // 7. 清空引用
  scene = null;
  camera = null;
  renderer = null;
};
```

::: tip Vue 3 + Three.js 的资源管理惯例
在 Vue 3 单文件组件里管理 Three.js 资源，推荐用「**集中登记 + 统一释放**」模式：
1. 顶部维护 `disposableGeometries` / `disposableMaterials` 数组
2. 用 `createMesh` 工具函数包装 `new THREE.Mesh`，自动登记 geometry 与 material
3. 共享资源（如两块台阶的 stepGeo）**只 push 一次**
4. `onUnmounted` 调用 `disposeScene()` 遍历数组释放

这套模式后续所有 stage 都会沿用，到 stage-13 性能优化阶段还会扩展出 `InstancedMesh` / `LOD` 的资源管理。
:::

## 8. 验证：台阶应该长什么样

运行 `npm run dev`，浏览器打开 `http://localhost:5173`，你应该看到：

- 地基前缘（z = 3 附近）探出 **两级灰色台阶**
- 第一级（远、低）：顶面 y = 0.15，探出地基 0.2m
- 第二级（近、高）：顶面 y = 0.30，**与地基顶面齐平**
- 两级台阶宽度都是 1.5m，居中在 X = 0
- 阳光从右上方照下来，台阶**右前侧亮、左后侧暗**
- 旋转视角到正面（+Z 方向看过去），能看到完整的「拾级而上」效果

如果台阶**埋在草地里**：检查 `position.y` 是不是 0（应该分别是 0.075 和 0.225）。
如果台阶**悬空**：检查 `BoxGeometry` 第二个参数（高度）是不是 0.15。
如果第二级顶面**与地基不齐平**：检查 `position.y` 是不是 0.225（应为 `0.15 + 0.15 / 2`）。
如果两块台阶**重叠在一起**：检查 `position.z` 是否分别是 3.2 和 3.0。

## 9. 与 HOUSE_SPEC 的对齐核对

| HOUSE_SPEC 字段 | 本节实现 | 是否一致 |
|----------------|---------|---------|
| 构件：入口台阶 | `BoxGeometry(1.5, 0.15, 0.4)` × 2 | 是 |
| 尺寸：1.5(X) × 0.4(Z) × 0.15(Y) × 2 级 | `(1.5, 0.15, 0.4)` 对应 X/Y/Z | 是 |
| 位置：(0, 0.075/0.225, 3.2) | `step1 (0, 0.075, 3.2)` + `step2 (0, 0.225, 3.0)` | 是（注：HOUSE_SPEC 表里 3.2 是第一级，3.0 是第二级紧贴地基） |
| 颜色：#909399 | `0x909399` | 是 |

::: warning 台阶朝向不可改
台阶必须朝 +Z 方向（门朝向）探出，因为 stage-03 的门洞就开在前墙中央 (0, 1.3, 3)。如果你不小心把台阶朝 -Z 探出（`z = -3.2`），后续阶段就会出现「台阶在屋后、门在屋前」的尴尬场景。
:::

## 本节总结

本节用两块 `BoxGeometry` 拼出 2 级台阶，并用 `BufferGeometry` 构建自定义斜坡作为对比演示，重点掌握：

1. **共享 geometry / material**：相同形状的多个 Mesh 共用一份资源，节省显存；dispose 时只释放一次
2. **底面贴地公式**：`position.y = height / 2`；叠加放置时 `position.y = baseY + height / 2`
3. **边界对齐**：第二级 Z = 3.0 紧贴地基前缘，顶面 y = 0.30 与地基顶面齐平
4. **BufferGeometry 四要素**：`position` / `normal` / `uv` / `index`，三角形是基本图元，逆时针为正面
5. **computeVertexNormals**：自动算法线，独立顶点保留硬棱角
6. **dispose 惯例**：集中登记 + 统一释放，共享资源只登记一次

至此 stage-02 完成：草地 + 地基 + 台阶 + 几何体预览，房子已经有了「地基」和「入户台阶」。下一阶段 stage-03 将在地基顶面砌四面墙（含门洞、窗洞）并装上木门，房子开始有了「墙」和「门」的雏形。
