# 草地波动着色器：高细分网格 + 顶点正弦波动

stage-01 的草地是一块 `PlaneGeometry(40, 40)`（默认 1×1 细分，4 个顶点）+ 一张程序化草地贴图。它"看起来"是草地，但永远静止——既不会随风起伏，也不会被踩出脚印。本节我们把它升级为"会呼吸的草地"：把平面细分成 100×100 段（共 10201 个顶点），在顶点着色器里用多频正弦函数让每个顶点的 y 随 uTime 起伏，模拟风吹草动。这是一个"顶点着色器主导"的案例——核心计算全在顶点着色器，片段着色器只做配色和简单光照。

## 一、为什么需要高细分网格

顶点着色器只能移动**已有的顶点**。1×1 细分的平面只有 4 个顶点（4 个角），无论怎么位移，中间都是一块绷紧的布——没有"波"可言。要看到波动，必须有足够的顶点密度。

`PlaneGeometry(40, 40, 100, 100)` 把 40×40 米的平面切成 100×100 段，共 101×101 = 10201 个顶点，每两个顶点间距 0.4 米。这样密度的网格，正弦波才能平滑显现。

```js
// 低细分（stage-01 用）：4 个顶点，无法波动
const geo1 = new THREE.PlaneGeometry(40, 40);

// 高细分（stage-10 用）：10201 个顶点，可平滑波动
const geo2 = new THREE.PlaneGeometry(40, 40, 100, 100);
```

::: tip 细分不是越高越好
细分越高，顶点着色器运行次数越多（每顶点一次）。10201 个顶点对现代 GPU 是小菜一碟，但 1000×1000 = 100 万顶点就开始有压力。本阶段 100×100 是质量与性能的平衡点。
:::

## 二、把平面"烤"成水平方向

`PlaneGeometry` 默认在 XY 平面（法线朝 +Z）。stage-01 我们用 `mesh.rotation.x = -Math.PI / 2` 让它水平铺开。但这样在顶点着色器里，`position.y` 是原始的"上下"方向（垂直于平面），不是世界的"上下"——直接位移 `position.y` 会让草地在平面内"前后"移动，不是"上下起伏"。

最干净的方案：用 `geo.rotateX(-Math.PI / 2)` 把旋转**烘焙到几何体顶点数据**里，mesh 就不需要再旋转了。烘焙后：
- 顶点坐标：`(x, 0, -y_original)`，即所有顶点 y=0，水平铺在 XZ 平面
- 法线：`(0, 1, 0)`，朝上

这样在顶点着色器里，`position.x` 和 `position.z` 是水平坐标，`position.y` 就是世界竖直方向，直接位移 `position.y` 就是"上下起伏"。

```js
const groundGeo = new THREE.PlaneGeometry(40, 40, 100, 100);
groundGeo.rotateX(-Math.PI / 2); // 烘焙旋转：从此 mesh 不需要 rotation
```

::: warning rotateX 是几何体方法不是 mesh 方法
`geo.rotateX()` 修改的是几何体顶点数据（永久烘焙），`mesh.rotation.x` 是渲染时的变换矩阵（不修改顶点数据）。两者都行，但着色器里要的是"已变换后的局部坐标"——烘焙后 `position` 直接就是水平坐标，着色器逻辑最简单。
:::

## 三、顶点着色器：多频正弦波动

风吹草动的真实感来自"多频率叠加"——单一正弦波太规律，像水波不像草地。我们用三个不同频率、不同幅度、不同相位的正弦/余弦波叠加：

```glsl
uniform float uTime;

varying vec2 vUv;
varying float vWave;     // 当前顶点的波动高度（传给片段着色器配色）
varying vec3 vNormalW;   // 世界空间法线（传给片段着色器光照）

void main() {
  vec3 pos = position;

  // 三个频率叠加：长波 + 中波 + 短波
  float wave1 = sin(pos.x * 0.4 + uTime * 1.5) * 0.15;  // 沿 X 长波
  float wave2 = cos(pos.z * 0.5 + uTime * 1.2) * 0.12;  // 沿 Z 中波
  float wave3 = sin((pos.x + pos.z) * 0.3 + uTime * 2.0) * 0.08; // 对角短波
  float wave = wave1 + wave2 + wave3;

  // 位移顶点 y（geo 已 rotateX，y 就是世界竖直方向）
  pos.y += wave;

  // 用波动对法线做轻微扰动，让光照跟随起伏变化
  // 计算波动在 x/z 方向的数值梯度，反推近似法线
  float eps = 0.5;
  float wx = sin((pos.x + eps) * 0.4 + uTime * 1.5) * 0.15
           + cos(pos.z * 0.5 + uTime * 1.2) * 0.12
           + sin((pos.x + eps + pos.z) * 0.3 + uTime * 2.0) * 0.08;
  float wz = sin(pos.x * 0.4 + uTime * 1.5) * 0.15
           + cos((pos.z + eps) * 0.5 + uTime * 1.2) * 0.12
           + sin((pos.x + pos.z + eps) * 0.3 + uTime * 2.0) * 0.08;
  // 法线 = (-dy/dx, 1, -dy/dz) 归一化
  vec3 nrm = normalize(vec3(-(wx - wave) / eps, 1.0, -(wz - wave) / eps));
  vNormalW = nrm;

  vUv = uv;
  vWave = wave;

  // 标准变换：局部 → 视图 → 裁剪空间
  gl_Position = projectionMatrix * modelViewMatrix * vec4(pos, 1.0);
}
```

逐项解释：

1. **三个波动叠加**：
   - `wave1`：沿 X 方向、频率 0.4、时间速度 1.5、幅度 0.15（长波，主导起伏）
   - `wave2`：沿 Z 方向、频率 0.5、时间速度 1.2、幅度 0.12（中波，让起伏不单一方向）
   - `wave3`：沿对角线、频率 0.3、时间速度 2.0、幅度 0.08（短波，加细节）
   - 总幅度 ≈ 0.35 米，足够看见但不夸张

2. **法线数值梯度**：要让光照跟随波动变化，需要"扰动后的法线"。直接用 `(0,1,0)` 会显得平。这里用数值差分计算法线：
   - `wx` 是 x 方向偏移 eps 后的波动值
   - `wz` 是 z 方向偏移 eps 后的波动值
   - 法线 = `(-dy/dx, 1, -dy/dz)`，即 `(-(wx-wave)/eps, 1, -(wz-wave)/eps)`，归一化

3. **varying 输出**：`vWave` 给片段着色器按高度配色，`vNormalW` 给片段着色器做 Lambert 光照

::: tip 数值梯度法线的原理
曲面 y = f(x, z) 的法线公式是 `(-df/dx, 1, -df/dz)` 归一化。我们不知道 f 的解析导数，但可以用数值差分近似：`df/dx ≈ (f(x+eps) - f(x)) / eps`。eps 取 0.5（米），比顶点间距 0.4 略大，梯度更平滑。
:::

::: warning 数值梯度会增加计算量
每个顶点要算 3 次完整波动（wave + wx + wz），相当于 3 倍 sin/cos 计算。10201 个顶点 × 9 次 sin/cos = 9 万次/帧，对现代 GPU 仍是小数目。如果性能吃紧，可以简化为"用原始 (0,1,0) 法线 + 波动高度直接调亮度"的近似方案。
:::

## 四、片段着色器：配色 + Lambert + 昼夜亮度

```glsl
uniform vec3 uColorA;       // 深草绿（低洼处）
uniform vec3 uColorB;       // 浅草绿（隆起处）
uniform float uBrightness;  // 昼夜亮度（白天 1.0 / 夜晚 0.25）

varying vec2 vUv;
varying float vWave;
varying vec3 vNormalW;

void main() {
  // 1) 按波动高度在两种绿色间平滑过渡：高处更亮、低处更暗
  float mixFactor = smoothstep(-0.2, 0.3, vWave);
  vec3 baseColor = mix(uColorA, uColorB, mixFactor);

  // 2) 简单 Lambert 明暗：法线 · 光源方向
  vec3 lightDir = normalize(vec3(0.4, 1.0, 0.3));
  float diff = max(dot(normalize(vNormalW), lightDir), 0.0);
  float ambient = 0.45;
  float lighting = ambient + diff * 0.55;

  // 3) 乘上昼夜亮度（白天 1.0 / 夜晚 0.25）
  vec3 finalColor = baseColor * lighting * uBrightness;

  gl_FragColor = vec4(finalColor, 1.0);
}
```

逐项解释：

1. **smoothstep 配色**：`smoothstep(-0.2, 0.3, vWave)` 把波动高度 [-0.2, 0.3] 映射到 [0, 1]，低洼处返回 0（深绿 uColorA），隆起处返回 1（浅绿 uColorB）。比 `mix` 的线性过渡更柔和

2. **Lambert 光照**：`max(dot(normal, lightDir), 0.0)` 计算法线与光源方向的点积，正比于光照强度。光源方向 `(0.4, 1.0, 0.3)` 模拟阳光从右前上方斜照

3. **昼夜亮度**：`uBrightness` 由 stage-08 的昼夜循环驱动，白天 1.0、夜晚 0.25。这样草地会跟着天空一起变暗

::: warning ShaderMaterial 不自动接收灯光
`lightDir` 是我们**硬编码**的方向，不是场景里 `sunLight` 的真实方向。要让草地跟随阳光位置变化，需要把 `sunLight.position` 作为 uniform 传入。本阶段为教学聚焦，固定光源方向即可。
:::

## 五、JS 端组装

```js
import * as THREE from "three";

const groundGeo = new THREE.PlaneGeometry(40, 40, 100, 100);
groundGeo.rotateX(-Math.PI / 2); // 烘焙旋转

const grassMaterial = new THREE.ShaderMaterial({
  uniforms: {
    uTime: { value: 0 },
    uColorA: { value: new THREE.Color(0x4a7c2a) }, // 深草绿
    uColorB: { value: new THREE.Color(0x8bc34a) }, // 浅草绿
    uBrightness: { value: 1.0 },
  },
  vertexShader: /* glsl */ `
    uniform float uTime;
    varying vec2 vUv;
    varying float vWave;
    varying vec3 vNormalW;
    void main() {
      vec3 pos = position;
      float wave1 = sin(pos.x * 0.4 + uTime * 1.5) * 0.15;
      float wave2 = cos(pos.z * 0.5 + uTime * 1.2) * 0.12;
      float wave3 = sin((pos.x + pos.z) * 0.3 + uTime * 2.0) * 0.08;
      float wave = wave1 + wave2 + wave3;
      pos.y += wave;

      float eps = 0.5;
      float wx = sin((pos.x + eps) * 0.4 + uTime * 1.5) * 0.15
               + cos(pos.z * 0.5 + uTime * 1.2) * 0.12
               + sin((pos.x + eps + pos.z) * 0.3 + uTime * 2.0) * 0.08;
      float wz = sin(pos.x * 0.4 + uTime * 1.5) * 0.15
               + cos((pos.z + eps) * 0.5 + uTime * 1.2) * 0.12
               + sin((pos.x + pos.z + eps) * 0.3 + uTime * 2.0) * 0.08;
      vec3 nrm = normalize(vec3(-(wx - wave) / eps, 1.0, -(wz - wave) / eps));
      vNormalW = nrm;
      vUv = uv;
      vWave = wave;
      gl_Position = projectionMatrix * modelViewMatrix * vec4(pos, 1.0);
    }
  `,
  fragmentShader: /* glsl */ `
    uniform vec3 uColorA;
    uniform vec3 uColorB;
    uniform float uBrightness;
    varying vec2 vUv;
    varying float vWave;
    varying vec3 vNormalW;
    void main() {
      float mixFactor = smoothstep(-0.2, 0.3, vWave);
      vec3 baseColor = mix(uColorA, uColorB, mixFactor);
      vec3 lightDir = normalize(vec3(0.4, 1.0, 0.3));
      float diff = max(dot(normalize(vNormalW), lightDir), 0.0);
      float lighting = 0.45 + diff * 0.55;
      vec3 finalColor = baseColor * lighting * uBrightness;
      gl_FragColor = vec4(finalColor, 1.0);
    }
  `,
});

const ground = new THREE.Mesh(groundGeo, grassMaterial);
ground.position.y = 0;
scene.add(ground);
```

## 六、与昼夜循环联动 uBrightness

stage-08 的 `updateDayNight` 函数里已经计算了 `dayFactor`（白天 1、夜晚 0）。我们把它同步写入草地的 `uBrightness`：

```js
const updateDayNight = (dt) => {
  cycleTime = (cycleTime + dt) % DAY_PERIOD;
  const t = cycleTime / DAY_PERIOD;
  const dayFactor = (Math.cos(t * Math.PI * 2) + 1) / 2; // 0~1

  // ... 原有 sunLight / ambientLight / sky 逻辑 ...

  // [stage-10] 同步驱动草地着色器的 uBrightness
  if (grassMaterial) {
    grassMaterial.uniforms.uBrightness.value = 0.25 + 0.75 * dayFactor;
  }

  return dayFactor;
};
```

夜晚 `dayFactor=0` → `uBrightness=0.25`（草地变暗）；白天 `dayFactor=1` → `uBrightness=1.0`（草地正常亮度）。这样草地的明暗与天空、阳光完全同步。

## 七、渲染循环更新 uTime

```js
const animate = () => {
  requestAnimationFrame(animate);
  const dt = clock.getDelta();
  const elapsed = clock.getElapsedTime();

  controls.update();
  updateDoor(dt);
  updateLamp(dt);
  updateDayNight(dt); // 内部会同步 grassMaterial.uniforms.uBrightness

  // 更新草地着色器的 uTime
  if (grassMaterial) {
    grassMaterial.uniforms.uTime.value = elapsed;
  }

  renderer.render(scene, camera);
};
```

::: tip uTime 用 elapsed 而不是 dt
`uTime` 是"绝对时间"，要让 `sin(uTime)` 持续推进，必须用累计秒数 `getElapsedTime()`。如果用 `getDelta()`（每帧约 0.016），sin 值会在 0 附近来回跳，看不到波动。
:::

## 八、dispose 完整释放

草地 mesh 走标准的 disposables 路径，ShaderMaterial 会被自动 dispose：

```js
disposables.forEach((obj) => {
  if (obj.geometry) obj.geometry.dispose();
  if (obj.material) {
    if (obj.material.map) obj.material.map.dispose();
    obj.material.dispose(); // ShaderMaterial 走相同路径
  }
});
grassMaterial = null; // 显式断引用
```

::: warning ShaderMaterial 没有 map
普通材质可能有 `map`（贴图），需要单独 dispose。ShaderMaterial 通常没有 map（除非你显式传 sampler2D uniform）。这里 `if (obj.material.map)` 对 ShaderMaterial 会返回 undefined，跳过，安全。
:::

## 九、性能与教学权衡

本阶段草地着色器有几个"可优化但故意没优化"的点，列出便于读者思考：

| 设计 | 当前做法 | 更优做法 | 为何这样选 |
|------|---------|---------|-----------|
| 法线计算 | 每顶点 3 次完整波动 | 解析导数（手算 d/dx sin(...)） | 数值梯度更易理解，教学优先 |
| 光源方向 | 硬编码 `(0.4, 1.0, 0.3)` | uniform 传 sunLight.position | 固定方向便于观察波动效果 |
| 顶点密度 | 100×100 = 10201 顶点 | 视距 LOD 动态调整 | stage-13 会专门讲 LOD/InstancedMesh |
| 波动幅度 | 全场统一 0.35 米 | 边缘衰减（边界不动） | 统一幅度让波动更明显，教学优先 |

::: tip 边缘衰减的技巧
如果要让草地边缘"不动"（避免与地基交界处穿模），可以用 `smoothstep` 给波动幅度做径向衰减：`float falloff = 1.0 - smoothstep(15.0, 20.0, length(pos.xz));` 然后 `pos.y += wave * falloff;`。这样 15 米内全幅波动，15~20 米平滑衰减到 0，边缘不动。
:::

## 本节总结

| 知识点 | 关键 API / 语法 | 说明 |
|--------|----------------|------|
| 高细分网格 | `PlaneGeometry(40, 40, 100, 100)` | 10201 顶点，波动才平滑 |
| 烘焙旋转 | `geo.rotateX(-Math.PI / 2)` | 把平面变成水平，着色器坐标最简 |
| 多频正弦 | `sin + cos + sin` 三波叠加 | 风吹草动的不规则感 |
| 顶点位移 | `pos.y += wave` | 顶点着色器核心 |
| 数值梯度法线 | `(-dy/dx, 1, -dy/dz) normalize` | 让光照跟随波动 |
| smoothstep 配色 | `mix(uColorA, uColorB, smoothstep(...))` | 高处亮、低处暗 |
| Lambert 光照 | `max(dot(normal, lightDir), 0)` | 简单漫反射 |
| uBrightness 联动 | `updateDayNight` 中同步写入 | 白天 1.0 / 夜晚 0.25 |
| uTime 更新 | `getElapsedTime()` | 累计秒数，绝对时间 |
| dispose | `material.dispose()` | 走与普通材质相同路径 |
