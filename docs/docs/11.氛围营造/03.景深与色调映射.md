# 景深与色调映射

Bloom 解决了"亮的地方发光"的问题，但我们的画面还有两个"工程感"的痕迹：第一，**所有距离的物体都一样清晰**——从脚下的草地到远处的天空盒，全部锐利，这不符合真实相机的物理特性；第二，**颜色看起来太"直"**——该亮的高光不够柔和，该暗的阴影不够深邃，缺少电影那种"压得住"的色调。

这一节我们用两个 Pass 解决这两个问题：`BokehPass` 做景深虚化，让焦点对准小屋、远处柔和虚化；`OutputPass` 配合 `ACESFilmicToneMapping` 做色调映射，把 HDR 线性数据染上电影质感。完成后，整条后期管线就齐活了。

## 一、景深（Depth of Field）

### 真实相机的景深

真实相机镜头无法让所有距离的物体同时清晰——只有"焦点"附近的一个距离范围是清晰的，更近或更远的物体会逐渐模糊。这个清晰范围叫**景深（DoF, Depth of Field）**。手机照片里前景背景都清晰，是因为手机光圈小、景深大；单反拍人像时背景虚化成光斑，是因为光圈大、景深浅。

3D 渲染默认没有景深——所有像素都同样清晰，这是它"看起来假"的重要原因之一。加上景深后，画面立刻有了"主次"：焦点处的主体清晰，背景虚化，视觉焦点被引导到主体上。

### BokehPass

Three.js 的 `BokehPass` 实现了基于深度图的景深。它的工作原理：

```
1. 用相机重新渲染一次场景，但只取深度缓冲（拿到每个像素的距离）
2. 根据每个像素的深度与"焦点距离"的差，决定模糊强度
3. 对像素做模糊（差越大越模糊），叠加到画面
```

构造函数：

```js
new BokehPass(scene, camera, { focus, aperture, maxblur })
```

| 参数 | 含义 | stage-11 取值 |
|------|------|---------------|
| `focus` | 焦点距离（世界单位，米） | `12.0`（约等于相机到小屋的距离） |
| `aperture` | 光圈大小，越大景深越浅（背景越虚） | `0.0025` |
| `maxblur` | 最大模糊量，限制最远处的模糊程度 | `0.008` |

### 加入流水线

```js
// Pass 3：BokehPass —— 景深
bokehPass = new BokehPass(scene, camera, {
  focus: 12.0,       // 焦点对准小屋（相机距小屋约 12 米）
  aperture: 0.0025,  // 光圈，适中
  maxblur: 0.008,    // 最大模糊量，保持较低避免画面糊成一团
});
composer.addPass(bokehPass);
```

加在 `UnrealBloomPass` 之后、`OutputPass` 之前。这样景深作用于"已经加了辉光"的画面，最后由 OutputPass 统一做色调映射输出。

::: warning BokehPass 会重新渲染场景
`BokehPass` 内部为了拿到深度缓冲，会用相机把场景**重新渲染一次**到自己的深度纹理。也就是说引入 BokehPass 后，场景每帧渲染两次（RenderPass 一次 + BokehPass 取深度一次）。这是已知开销，移动端或低性能设备上可以考虑关闭景深（用 `bokehPass.enabled = false`）。
:::

### 三个参数的调参

- **focus**：测一下相机到主体的距离。stage-11 相机在 `(12, 8, 12)`，距原点约 17 米，距小屋正面约 14 米，取 12 让小屋正面到屋顶都在焦点附近。设错的话主体会变模糊。
- **aperture**：`0.001` 几乎全清晰，`0.005` 明显虚化，`0.01+` 极浅景深。stage-11 用 `0.0025` 保持克制，只让远处轻微虚化。
- **maxblur**：限制最远处的最大模糊量，避免远处糊成色块。`0.005~0.01` 是舒适范围。

::: tip maxblur 为什么这么小
`maxblur` 是 0~1 的归一化值，0.008 听起来很小，但在全屏模糊里已经能产生明显的虚化感。设到 0.05 以上画面会糊得无法辨认，慎用。
:::

## 二、色调映射（Tone Mapping）

### 为什么需要色调映射

Bloom 让我们的画面里出现了 HDR 像素（亮度 > 1.0，比如灯泡的线性 1.6）。但屏幕是显示不了 > 1.0 的亮度的——屏幕最亮就是白（1.0, 1.0, 1.0）。如果不做处理，HDR 像素会被直接截断（clamp 到 1.0），高光区域变成死白一片，丢失所有细节。

**色调映射**就是解决"如何把 HDR 亮度优雅地压回 0~1 显示范围"的算法。好的色调映射会：
- 把 > 1 的亮度柔和地压回 1，保留高光层次（而不是截断成死白）
- 提升暗部细节
- 给画面染上特定的"风格"（电影感、写实感、卡通感）

### ACESFilmic 色调映射

Three.js 内置多种色调映射算法，最常用的几种：

| 算法 | 风格 | 适用场景 |
|------|------|---------|
| `NoToneMapping` | 不做任何处理 | 调试 |
| `LinearToneMapping` | 线性压缩 | 简单 |
| `ReinhardToneMapping` | 经典柔和 | 通用 |
| `ACESFilmicToneMapping` | **电影级**，高光柔和、对比适中 | **电影/游戏主流** |

stage-11 选用 `ACESFilmicToneMapping`——这是当前电影和 3A 游戏的事实标准，由美国电影摄影师学会（ASC）提出。它的特点是：高光柔和过渡（不会死白）、暗部对比适当提升、整体染上一层"电影青橙调"。

### 设置色调映射

色调映射通过 `renderer.toneMapping` 设置：

```js
// [stage-11] 色调映射：ACES Filmic（电影级）
// 注意：必须在创建 OutputPass 之前设置，因为 OutputPass 在构造时
// 读取 renderer.toneMapping 来决定其片元着色器中的色调映射算法
renderer.toneMapping = THREE.ACESFilmicToneMapping;
renderer.toneMappingExposure = 1.0; // 整体曝光，>1 提亮，<1 压暗
```

::: warning 必须在 OutputPass 之前设置
`OutputPass` 在构造时会读取 `renderer.toneMapping` 的值，并据此编译自己的片元着色器。如果你先创建 OutputPass 再改 `renderer.toneMapping`，OutputPass 不会自动更新着色器，色调映射不生效。**顺序：先设 toneMapping，再 new OutputPass()**。
:::

## 三、OutputPass：流水线最后一站

`OutputPass` 是后期管线的"收尾工位"，做两件事：

1. **色调映射**：根据 `renderer.toneMapping` 把线性 HDR 数据压回 0~1
2. **颜色空间转换**：把线性数据转成 sRGB（屏幕能显示的色彩空间）

```js
// Pass 4：OutputPass —— 色调映射 + sRGB 输出（必须最后）
outputPass = new OutputPass();
composer.addPass(outputPass);
```

`OutputPass` 必须是流水线的最后一个 Pass。它会把结果直接写到屏幕（内部 `renderToScreen = true`）。

### 为什么需要 OutputPass

在 EffectComposer 流水线里，所有中间 Pass（RenderPass / UnrealBloomPass / BokehPass）都在**线性空间**操作，数据保存在浮点纹理里（亮度可以 > 1）。如果直接把这个线性数据写到屏幕，画面会又暗又偏色——因为屏幕需要 sRGB 编码。

早期 Three.js 需要手动加一个 `ShaderPass(GammaCorrectionShader)` 做 sRGB 转换，再单独处理色调映射。现代 Three.js 推荐直接用 `OutputPass`，它把这两步合一，并且会读取 renderer 的 toneMapping 设置，避免重复代码。

::: tip 没有 OutputPass 会怎样
如果管线末尾不放 OutputPass，最后一个 Pass（BokehPass）的结果会被直接当作线性数据写到屏幕。画面会变得偏暗、颜色发灰（因为 sRGB 显示器期待的是经过 gamma 编码的数据）。HDR 高光也会被硬截断成死白。
:::

## 四、颜色空间的协同

理解整条管线的颜色空间流转，是掌握后期处理的关键：

```
RenderPass         → 线性 HDR 纹理（亮度可 > 1，未做色调映射）
   ↓
UnrealBloomPass    → 仍线性 HDR（bloom 在线性空间计算，threshold=0.85 是线性值）
   ↓
BokehPass          → 仍线性 HDR（景深模糊不改变颜色空间）
   ↓
OutputPass         → 色调映射（HDR→LDR） + sRGB 编码 → 屏幕
```

::: warning 为什么材质在 RenderPass 时不做色调映射
Three.js 的材质着色器里有"是否做色调映射"的开关。当渲染目标**不是屏幕**（而是 EffectComposer 的离屏纹理）时，WebGLRenderer 会自动关闭材质的色调映射，输出纯线性数据。这样 Bloom 的 threshold 才是在真正的线性亮度上比较。只有最终的 OutputPass 才做色调映射，避免"双重色调映射"。
:::

这就是为什么我们能把灯泡颜色写到线性 1.6——它在线性空间被 Bloom 正确捕捉，最后由 OutputPass 的 ACES 算法柔和地压回显示范围，既"亮得发光"又"不死白"。

## 五、完整后期管线

把三道工序组合起来，stage-11 的完整后期管线如下：

```js
const initPostProcessing = () => {
  // 色调映射：必须在创建 OutputPass 之前设置
  renderer.toneMapping = THREE.ACESFilmicToneMapping;
  renderer.toneMappingExposure = 1.0;

  composer = new EffectComposer(renderer);

  // Pass 1：RenderPass —— 把场景渲染到离屏纹理（线性空间）
  const renderPass = new RenderPass(scene, camera);
  composer.addPass(renderPass);

  // Pass 2：UnrealBloomPass —— 辉光（强度 0.6 / 半径 0.4 / 阈值 0.85）
  bloomPass = new UnrealBloomPass(
    new THREE.Vector2(window.innerWidth, window.innerHeight),
    0.6,
    0.4,
    0.85
  );
  composer.addPass(bloomPass);

  // Pass 3：BokehPass —— 景深（焦点 12m / 光圈 0.0025 / 最大模糊 0.008）
  bokehPass = new BokehPass(scene, camera, {
    focus: 12.0,
    aperture: 0.0025,
    maxblur: 0.008,
  });
  composer.addPass(bokehPass);

  // Pass 4：OutputPass —— ACESFilmic 色调映射 + sRGB 输出（必须最后）
  outputPass = new OutputPass();
  composer.addPass(outputPass);
};
```

## 六、运行时切换与对比

stage-11 提供 **D 键** 切换景深，方便对比：

```js
if (key === "d") {
  // [stage-11] 切换景深
  dofEnabled = !dofEnabled;
  if (bokehPass) bokehPass.enabled = dofEnabled;
  ui.dofState = dofEnabled ? "开启" : "关闭";
}
```

按下 D 关闭景深后，远处草地和天空盒变得锐利清晰——画面"平"了。再按 D 开启，远处柔和虚化，小屋作为主体被视觉聚焦。配合 B 键切换 Bloom，你可以四象限对比四种组合（仅 Bloom、仅景深、全开、全关），直观感受后期处理的氛围价值。

::: tip 体验顺序建议
1. 默认状态（Bloom + 景深全开）观察整体氛围
2. 按 L 开灯，看灯泡和玻璃边缘的辉光
3. 按 B 关闭 Bloom，看灯泡失去光晕后的"平"
4. 按 D 关闭景深，看远处变得锐利后的"乱"
5. 全部重新开启，对比体会"氛围"的差距
:::

## 七、性能与取舍

后期处理是有性能代价的。stage-11 的管线每帧需要：

| Pass | 主要开销 |
|------|---------|
| RenderPass | 一次完整场景渲染 |
| UnrealBloomPass | 多次降采样 + 高斯模糊（5~7 次全屏 pass） |
| BokehPass | 一次场景重渲染（取深度）+ 全屏模糊 |
| OutputPass | 一次全屏色调映射 |

总体上，引入后期处理后 GPU 开销大约增加 50%~150%（取决于显卡和分辨率）。在性能受限场景下，可以做的优化：

- 关闭景深（`bokehPass.enabled = false`），省下一次场景渲染
- 降低 bloom 分辨率（`new UnrealBloomPass(new Vector2(w/2, h/2), …)`）
- 降低 `renderer.setPixelRatio(1)`，减少处理像素数
- 移动端只保留 OutputPass，放弃 Bloom 和景深

::: warning stage-13 会专门讲性能优化
后期处理是性能优化的重点对象。本书 [13. 流畅运行](../13.流畅运行/) 会专门讲 Stats 监控、LOD、InstancedMesh、按需降低 pixelRatio 等技巧，其中就包括后期管线的裁剪策略。
:::

## 本节总结

- **景深（BokehPass）**：基于深度图让焦点外像素模糊，引导视觉焦点。`focus` 设到主体距离，`aperture` 控制虚化强度，`maxblur` 限制最大模糊
- **色调映射（ACESFilmicToneMapping）**：把 HDR 亮度（>1.0）柔和压回 0~1，避免高光死白，染上电影色调
- **OutputPass**：流水线最后一站，做色调映射 + sRGB 编码，必须最后加入；构造前要先设 `renderer.toneMapping`
- **颜色空间协同**：RenderPass/Bloom/Bokeh 都在线性 HDR 空间操作，只有 OutputPass 做色调映射与编码，避免双重处理
- **性能取舍**：后期处理增加 50%~150% GPU 开销，可按需关闭景深或降低 bloom 分辨率

至此，stage-11 的后期管线全部就位：辉光让灯光发光，景深让画面有主次，色调映射让色彩有电影感。小屋从"3D 模型"彻底升级为"夜景大片"。
