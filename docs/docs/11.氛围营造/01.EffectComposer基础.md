# EffectComposer 后期合成器

从 stage-01 到 stage-10，我们渲染场景用的都是同一行代码：`renderer.render(scene, camera)`。这条命令把场景直接画到屏幕上——一锤定音，没有任何回旋余地。想给画面加辉光？想虚化背景？想调色？都来不及了，像素已经"显影"到屏幕上。

**后期处理（Post-Processing）**的核心思路是：先把场景画到一张**离屏纹理（Render Target）**上，而不是直接画到屏幕；然后对这张纹理施加各种特效，一道一道工序走完，最后才输出到屏幕。管理这条"先渲染再加工"流水线的总指挥，就是 `EffectComposer`。

## 一、为什么需要后期处理

### 传统渲染流程

```
场景数据 ──→ renderer.render(scene, camera) ──→ 屏幕
```

这是一条"单程票"：场景 → 屏幕，中间无法插入任何画面处理。所有视觉效果（光照、阴影、雾）都必须在"场景渲染"这一步内完成。

### 后期处理流程

```
场景数据 ──→ [RenderPass]      ──→ 离屏纹理 A
                                   │
                                   ▼
                             [UnrealBloomPass] ──→ 离屏纹理 B
                                   │
                                   ▼
                             [BokehPass]       ──→ 离屏纹理 C
                                   │
                                   ▼
                             [OutputPass]      ──→ 屏幕
```

每个 **Pass（通道）**接收上一站的纹理，处理后再传给下一站。`EffectComposer` 负责串联所有 Pass，并管理这些中间纹理的分配与回收。

::: tip 为什么不能在 renderer.render 里直接做这些效果
辉光、景深这类效果需要访问"整张画面"——比如辉光要知道"周围像素有多亮"才能晕开，景深要知道"每个像素的深度"才能决定模糊程度。而 `renderer.render` 是逐物体绘制，画完一个物体就忘了它的像素，无法做"全画面"分析。后期处理把整张画面当作一张纹理来处理，才有了全局操作的自由度。
:::

## 二、EffectComposer 后期合成器

### 引入路径

后期处理模块位于 `three/examples/jsm/postprocessing/` 下，需要按需引入：

```js
import * as THREE from "three";
import { EffectComposer } from "three/examples/jsm/postprocessing/EffectComposer.js";
import { RenderPass } from "three/examples/jsm/postprocessing/RenderPass.js";
import { UnrealBloomPass } from "three/examples/jsm/postprocessing/UnrealBloomPass.js";
import { BokehPass } from "three/examples/jsm/postprocessing/BokehPass.js";
import { OutputPass } from "three/examples/jsm/postprocessing/OutputPass.js";
```

### 创建 EffectComposer

`EffectComposer` 接收一个 `renderer` 作为参数，内部会自动创建一组离屏渲染目标（`WebGLRenderTarget`）作为 Pass 之间的中转纹理：

```js
// renderer 已经在 initScene 里创建好
composer = new EffectComposer(renderer);
```

::: warning 性能与内存
`EffectComposer` 默认使用 `HalfFloatType` 浮点纹理来保存中间结果——这是为了支持 HDR（亮度 > 1.0）数据，让辉光、色调映射能正确工作。浮点纹理比普通 8 位纹理占更多显存，移动端要谨慎。
:::

## 三、RenderPass：流水线第一站

`RenderPass` 的职责就是把场景"拍成照片"。它接收 `scene` 和 `camera`，调用 `renderer.render` 把场景渲染到 composer 的离屏纹理上，而不是屏幕上：

```js
// Pass 1：RenderPass —— 把场景渲染到离屏纹理
const renderPass = new RenderPass(scene, camera);
composer.addPass(renderPass);
```

`composer.addPass(pass)` 把一个 Pass 追加到流水线末尾。Pass 的执行顺序就是 `addPass` 的顺序，所以 **RenderPass 必须第一个加入**。

### Pass 的核心属性：enabled

每个 Pass 都有 `enabled` 布尔属性。设为 `false` 时，composer 会跳过这个 Pass（把输入直接传给下一站）。这是运行时切换特效的常用手段：

```js
// 按 B 键切换 Bloom
if (key === "b") {
  bloomEnabled = !bloomEnabled;
  if (bloomPass) bloomPass.enabled = bloomEnabled;
}
```

## 四、串联 Pass 与渲染循环改写

### 完整的初始化

下面是 stage-11 中 `initPostProcessing` 的核心结构（暂用占位 Pass，下一节会换成真实的 Bloom/Bokeh/Output）：

```js
const initPostProcessing = () => {
  // 色调映射：必须在创建 OutputPass 之前设置
  // 因为 OutputPass 在构造时会读取 renderer.toneMapping 来决定片元着色器
  renderer.toneMapping = THREE.ACESFilmicToneMapping;
  renderer.toneMappingExposure = 1.0;

  composer = new EffectComposer(renderer);

  // Pass 1：RenderPass
  const renderPass = new RenderPass(scene, camera);
  composer.addPass(renderPass);

  // Pass 2：UnrealBloomPass（下一节详解）
  bloomPass = new UnrealBloomPass(
    new THREE.Vector2(window.innerWidth, window.innerHeight),
    0.6,   // strength
    0.4,   // radius
    0.85   // threshold
  );
  composer.addPass(bloomPass);

  // Pass 3：BokehPass（第 03 节详解）
  bokehPass = new BokehPass(scene, camera, {
    focus: 12.0,
    aperture: 0.0025,
    maxblur: 0.008,
  });
  composer.addPass(bokehPass);

  // Pass 4：OutputPass（第 03 节详解，必须最后）
  outputPass = new OutputPass();
  composer.addPass(outputPass);
};
```

### 渲染循环：composer.render 替代 renderer.render

这是后期处理最关键的"一行改动"。原来的渲染循环用 `renderer.render`，现在改成 `composer.render`：

```js
const animate = () => {
  animationId = requestAnimationFrame(animate);
  const dt = clock.getDelta();

  shaderUniforms.uTime.value += dt; // 更新着色器时间
  controls.update();
  updateDoor(dt);
  updateLamp(dt);
  updateDayNight(dt);

  // 关键改动：用 EffectComposer 渲染，串联所有 Pass
  if (composer) {
    composer.render();
  } else {
    renderer.render(scene, camera); // 容错回退
  }
};
```

`composer.render()` 内部会依次调用每个 Pass 的 `render` 方法，把数据从第一个 Pass 一路传到最后一个，最后由 `OutputPass` 输出到屏幕。

::: tip composer.render 内部做了什么
1. 调用第一个 Pass（RenderPass），把场景渲染到内部 `readBuffer` 纹理
2. 依次调用后续 Pass，每个 Pass 读取 `readBuffer`，处理后写入 `writeBuffer`，然后交换两者（ping-pong）
3. 最后一个 `renderToScreen = true` 的 Pass 把结果写到屏幕（OutputPass 默认就是这一站）
:::

## 五、resize 与 dispose 的同步

引入 composer 后，resize 和资源释放都要同步处理它，否则窗口缩放后画面会错位，或组件卸载后显存泄漏。

### resize 同步

```js
const handleResize = () => {
  if (!camera || !renderer) return;
  const w = window.innerWidth;
  const h = window.innerHeight;
  camera.aspect = w / h;
  camera.updateProjectionMatrix();
  renderer.setSize(w, h);
  renderer.setPixelRatio(Math.min(window.devicePixelRatio, 2));

  // [stage-11] 同步 composer 与 bloom 分辨率
  if (composer) {
    composer.setSize(w, h);
    if (bloomPass) bloomPass.setSize(w, h); // bloom 内部有独立纹理
  }
};
```

::: warning 不调用 composer.setSize 会怎样
窗口变大时，composer 的内部纹理仍是旧尺寸，画面会被拉伸模糊；窗口变小时则出现黑边。`UnrealBloomPass` 内部还维护了多张降采样纹理，必须单独调用它的 `setSize` 才会同步。
:::

### dispose 同步

每个 Pass 都可能持有纹理、着色器、深度缓冲等 GPU 资源，必须逐个释放：

```js
const disposeScene = () => {
  // ... 释放 geometry / material ...

  // [stage-11] 释放后期 Pass
  if (bloomPass) { bloomPass.dispose?.(); bloomPass = null; }
  if (bokehPass) { bokehPass.dispose?.(); bokehPass = null; }
  if (outputPass) { outputPass.dispose?.(); outputPass = null; }
  if (composer)   { composer.dispose?.();   composer = null; }

  if (controls) controls.dispose();
  if (renderer) { renderer.dispose(); renderer.forceContextLoss?.(); }
};
```

::: tip 为什么用 dispose?.()
不同 Three.js 版本里，部分 Pass 的 `dispose` 方法签名不同或缺失。用可选链 `dispose?.()` 既安全又简洁——有就调用，没有就跳过，不会因版本差异报错。
:::

## 六、最小可运行示例

把上面的零件组装起来，就是一个最小的后期处理管线（只有 RenderPass + OutputPass，暂不加特效，先验证管线本身能跑通）：

```js
import * as THREE from "three";
import { EffectComposer } from "three/examples/jsm/postprocessing/EffectComposer.js";
import { RenderPass } from "three/examples/jsm/postprocessing/RenderPass.js";
import { OutputPass } from "three/examples/jsm/postprocessing/OutputPass.js";

const scene = new THREE.Scene();
const camera = new THREE.PerspectiveCamera(50, innerWidth / innerHeight, 0.1, 200);
camera.position.set(12, 8, 12);

const renderer = new THREE.WebGLRenderer({ antialias: true });
renderer.setSize(innerWidth, innerHeight);
renderer.toneMapping = THREE.ACESFilmicToneMapping; // 输出前做色调映射
document.body.appendChild(renderer.domElement);

scene.add(new THREE.Mesh(
  new THREE.BoxGeometry(2, 2, 2),
  new THREE.MeshStandardMaterial({ color: 0x409eff })
));
scene.add(new THREE.AmbientLight(0xffffff, 0.6));

// 后期管线：RenderPass → OutputPass
const composer = new EffectComposer(renderer);
composer.addPass(new RenderPass(scene, camera));
composer.addPass(new OutputPass());

function animate() {
  requestAnimationFrame(animate);
  composer.render(); // 注意：是 composer.render，不是 renderer.render
}
animate();
```

运行后你会发现画面和直接用 `renderer.render` 看起来几乎一样——因为还没加特效。但这条管线已经就位，下一节我们往中间塞一个 `UnrealBloomPass`，画面立刻就会"亮"起来。

::: warning 为什么看起来"几乎"一样而不是完全一样
因为 `OutputPass` 应用了 ACESFilmic 色调映射。如果你的场景里有亮度 > 1 的像素（HDR），色调映射会把它们柔和地压回显示范围，整体观感会比直接渲染更"电影"、高光更柔和。这正是我们想要的效果。
:::

## 本节总结

- **后期处理** = 先把场景渲染到离屏纹理，再用多个 Pass 流水线加工，最后输出到屏幕
- **EffectComposer** 是流水线总指挥，`addPass` 顺序就是执行顺序
- **RenderPass** 是流水线第一站，把场景渲染到离屏纹理；必须第一个加入
- **Pass.enabled** 可以运行时切换某个特效，无需重建管线
- 渲染循环从 `renderer.render()` 改为 `composer.render()`，并在 resize / dispose 中同步处理 composer
