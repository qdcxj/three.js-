# Bloom 辉光

上一节我们搭起了 `EffectComposer` 流水线，但只放了 `RenderPass` 和 `OutputPass`，画面看起来和普通渲染几乎一样。这一节我们往中间塞入第一个真正的特效——**Bloom（辉光）**，让小屋里点亮的灯泡真正"发光"。

Bloom 是电影和游戏里最常见的后期效果之一。它的视觉特征是：**画面中明亮的部分会向四周晕开柔和的光晕**——夜晚的街灯、车灯、霓虹灯，游戏里的魔法特效、能量武器，几乎都靠 Bloom 营造"亮得发光"的感觉。在我们的欧式小屋里，Bloom 会让室内点亮的暖灯向四周晕开温暖的光晕，玻璃边缘的 Fresnel 高光也会"溢出"成柔和的光圈。

## 一、Bloom 的视觉原理

Bloom 的核心思路可以拆成三步：

```
1. 提取亮部：从画面中挑出亮度超过阈值的像素，得到一张"亮部蒙版"
2. 高斯模糊：对亮部蒙版做多次模糊，得到柔和的光晕层
3. 叠加回原图：把光晕层叠加到原始画面上，亮的地方就"晕开"了
```

用伪代码表示：

```
brightPixels = threshold(image, 0.85)   // 只保留亮度 > 0.85 的像素
bloomLayer   = gaussianBlur(brightPixels, radius)  // 多次模糊
finalImage   = image + bloomLayer * strength       // 叠加
```

::: tip 为什么 Bloom 能让人"觉得亮"
人眼对亮度的感知不是线性的——一个发光物体之所以"看起来发光"，不是因为它的像素值更高（屏幕最亮就是 1.0），而是因为它的光**向周围扩散了**，形成一片柔和的明亮区域。Bloom 就是模拟这种"光溢出"的视觉心理，让屏幕上无法真正超过 1.0 的像素，通过"晕开"骗过眼睛，显得"亮得发白"。
:::

## 二、UnrealBloomPass

Three.js 提供的 `UnrealBloomPass` 是一个性能与效果都不错的 Bloom 实现（名字来源于 Epic Games 的 Unreal Engine，算法借鉴了 UE 的 Bloom）。它的构造函数接收四个参数：

```js
new UnrealBloomPass(resolution, strength, radius, threshold)
```

| 参数 | 类型 | 含义 | stage-11 取值 |
|------|------|------|---------------|
| `resolution` | `THREE.Vector2` | 内部模糊纹理分辨率，一般等于窗口尺寸 | `(window.innerWidth, window.innerHeight)` |
| `strength` | `number` | 辉光强度，越大越亮 | `0.6` |
| `radius` | `number` | 辉光半径，控制光晕扩散范围 | `0.4` |
| `threshold` | `number` | 亮度阈值，超过才发光（0~1） | `0.85` |

### 加入流水线

```js
// Pass 2：UnrealBloomPass —— 辉光
bloomPass = new UnrealBloomPass(
  new THREE.Vector2(window.innerWidth, window.innerHeight),
  0.6,   // strength  辉光强度
  0.4,   // radius    辉光半径
  0.85   // threshold 亮度阈值（线性空间）
);
composer.addPass(bloomPass);
```

加在 `RenderPass` 之后、`OutputPass` 之前。这样 Bloom 拿到的是 RenderPass 输出的线性 HDR 数据，处理完再交给 OutputPass 做色调映射与输出。

## 三、三个参数的调参指南

### strength：辉光强度

控制光晕的明亮程度。`0` = 无辉光，`1` = 强烈辉光，`2+` = 梦幻/过曝风格。

- `0.3~0.6`：自然电影感（stage-11 用 0.6）
- `0.8~1.5`：游戏特效感
- `>2`：梦幻/梦境风格

### radius：辉光半径

控制光晕扩散的范围。`0` = 几乎不扩散（只亮不晕），`1` = 大范围柔和扩散。

- `0.2~0.4`：紧凑光晕（stage-11 用 0.4）
- `0.6~1.0`：柔和弥漫
- 太大会让整个画面"糊"掉

### threshold：亮度阈值

**最重要的参数**。只有亮度超过这个阈值的像素才会发光。取值 0~1，但注意它是在**线性空间**比较的。

- `0.0`：所有像素都发光（画面整体发白，慎用）
- `0.6~0.85`：只有明亮的高光发光（stage-11 用 0.85）
- `0.95+`：只有极亮的 HDR 像素发光

::: warning threshold 是线性空间的
`UnrealBloomPass` 的 threshold 是在**线性空间**比较的，不是 sRGB。这意味着如果你想让某个物体发光，它在 RenderPass 输出的线性亮度必须超过 0.85。普通被灯光照亮的材质（漫反射）线性亮度通常在 0.1~0.5 之间，**不会触发 Bloom**。要让物体真正发光，需要用：
- **MeshBasicMaterial**（不受光照影响，颜色直接输出）
- 或者材质的 **emissive** 自发光属性
- 并把颜色值设到 > 0.85（HDR）
:::

## 四、让灯光发光：HDR 灯泡

这是 stage-11 最关键的技巧。普通的 `PointLight` / `SpotLight` 只是**光源**，本身不可见——它们照亮别的物体，但你看不到"灯泡"。要让 Bloom 捕捉到灯光，我们给每个灯加一个**可见的灯泡网格**，用 `MeshBasicMaterial`（纯自发光，不受光照影响），并在开灯时把它的线性颜色提到 1.0 以上。

### 创建灯泡

```js
// [stage-11] 室内灯泡：MeshBasicMaterial 不受光照影响（纯自发光）
const bulbMat = new THREE.MeshBasicMaterial({
  color: 0x000000,
  transparent: true,
  opacity: 0.9,
});
// 用 setRGB + LinearSRGBColorSpace 直接写入线性值，便于 HDR 控制
bulbMat.color.setRGB(0, 0, 0, THREE.LinearSRGBColorSpace);
lampBulb = new THREE.Mesh(new THREE.SphereGeometry(0.12, 16, 16), bulbMat);
lampBulb.position.set(0, 2.8, 0); // 与室内点光源同位置
scene.add(lampBulb);
```

::: tip 为什么用 setRGB + LinearSRGBColorSpace
Three.js 的 `Color` 默认按 sRGB 解释颜色值（例如 `setHex(0xffffff)` 会被转成线性 1.0）。但我们要的是 HDR 值 > 1.0 来触发 Bloom，sRGB 空间不支持 > 1。所以用 `setRGB(r, g, b, THREE.LinearSRGBColorSpace)` 直接写入线性值，绕过 sRGB 转换，可以自由设置 1.6、2.0 这样的超亮值。
:::

### 随灯强度更新颜色

每帧在 `updateLamp` 里，根据 `lampIntensity`（0~1 的过渡值）动态更新灯泡颜色：

```js
const updateLamp = (dt) => {
  // ... lampIntensity lerp 到目标值 ...

  // [stage-11] 更新灯泡 HDR 颜色：开灯时线性值 > 0.85 触发 Bloom
  // 暖黄色 (1.6, 1.25, 0.55) 线性 → bloom 捕捉
  if (lampBulb) {
    const k = lampIntensity;
    lampBulb.material.color.setRGB(
      1.6 * k,   // R：线性 1.6（开灯满值）
      1.25 * k,  // G：线性 1.25
      0.55 * k,  // B：线性 0.55（暖色偏黄）
      THREE.LinearSRGBColorSpace
    );
    lampBulb.material.opacity = 0.4 + 0.6 * k;
  }

  // 壁灯灯泡同理
  wallLampBulbs.forEach((b) => {
    const k = lampIntensity;
    b.material.color.setRGB(1.5 * k, 1.2 * k, 0.5 * k, THREE.LinearSRGBColorSpace);
  });
};
```

开灯时 `k` 趋近 1，灯泡线性颜色达到 `(1.6, 1.25, 0.55)`，亮度远超阈值 0.85，Bloom 把它晕开成温暖的黄色光晕——这就是"灯真正亮了"的视觉秘密。

## 五、让玻璃边缘发光

stage-10 的玻璃着色器（Fresnel 边缘高光）在这里也要"配合"一下 Bloom。我们让玻璃的 Fresnel 强度随室内灯强度变化：白天边缘只有淡淡反光（线性 ~0.45，不触发 Bloom），夜晚开灯后边缘亮度突破 0.85，被 Bloom 捕捉成辉光。

```glsl
// 玻璃片元着色器（节选）
uniform float uLampIntensity;
uniform vec3 uBaseColor;
uniform vec3 uRimColor;
varying vec3 vNormal;
varying vec3 vViewDir;

void main() {
  float fresnel = pow(1.0 - max(dot(vNormal, vViewDir), 0.0), 2.5);
  vec3 color = uBaseColor;
  // 边缘辉光：白天淡，夜晚开灯强（HDR > 0.85 触发 Bloom）
  float glow = fresnel * (0.45 + uLampIntensity * 1.6);
  color += uRimColor * glow;
  float alpha = 0.35 + fresnel * 0.45;
  gl_FragColor = vec4(color, alpha);
}
```

`uLampIntensity` 由 JS 每帧同步：

```js
// 在 updateLamp 末尾
shaderUniforms.uLampIntensity.value = lampIntensity;
```

开灯时 `glow = fresnel * (0.45 + 1.6) ≈ fresnel * 2.05`，玻璃边缘（fresnel 接近 1）的线性亮度可达 2.0，远超 Bloom 阈值，形成漂亮的边缘辉光。

## 六、Bloom 与透明物体的配合

stage-11 的玻璃是半透明 ShaderMaterial，它和 Bloom 有一个易踩的坑：如果玻璃写了深度缓冲（`depthWrite: true`），它会"挡住"后面灯泡的深度，导致灯泡在 Bloom 的亮度提取阶段被错误地剔除，光晕变小甚至消失。解决方法是给玻璃材质关掉深度写入：

```js
const glassMat = new THREE.ShaderMaterial({
  // ... uniforms / vertexShader / fragmentShader ...
  transparent: true,
  depthWrite: false, // 玻璃不写深度，避免遮挡内部灯光导致 bloom 失效
  side: THREE.DoubleSide,
});
```

::: tip 透明物体的通用原则
所有 `transparent: true` 的材质都建议把 `depthWrite` 设为 `false`。否则半透明物体之间会出现"谁先渲染谁挡住后面"的排序问题，画面会闪动或穿模。Bloom 只是放大了这个问题——让透明物体背后的 HDR 高光被错误剔除。
:::

另一个细节是渲染顺序：Three.js 默认会把透明物体排在透明队列里按距离排序后再渲染。这意味着玻璃会在所有不透明物体（包括灯泡）之后渲染，保证透明混合正确。我们无需手动干预。

## 七、运行时切换 Bloom

stage-11 加了一个 **B 键** 切换 Bloom，方便对比效果：

```js
const onKeyDown = (e) => {
  const key = e.key.toLowerCase();
  // ...
  if (key === "b") {
    // [stage-11] 切换 Bloom
    bloomEnabled = !bloomEnabled;
    if (bloomPass) bloomPass.enabled = bloomEnabled;
    ui.bloomState = bloomEnabled ? "开启" : "关闭";
  }
};
```

按下 B 关闭 Bloom 后，灯泡虽然还是亮的（颜色没变），但失去了光晕——画面立刻"平"了下来。再按 B 开启，光晕重新出现，氛围感拉满。这是理解 Bloom 价值最直观的方式。

## 八、参数对比实验

鼓励你动手改这三个参数，观察变化：

| 改动 | 预期效果 |
|------|---------|
| `strength: 0.6 → 1.5` | 灯泡光晕明显变亮、变刺眼 |
| `radius: 0.4 → 0.9` | 光晕扩散范围变大，更"弥漫" |
| `threshold: 0.85 → 0.3` | 大量被照亮的墙面也开始发光，画面过曝发白 |
| `threshold: 0.85 → 0.98` | 只有灯泡最中心发光，光晕变得很小很硬 |

::: warning 不要把 threshold 设太低
`threshold` 设到 0.3 以下时，几乎所有被照亮的物体都会触发 Bloom，整张画面像蒙了一层雾，失去层次感。Bloom 的精髓是"少而精"——只有真正应该发光的高光才发光。
:::

## 本节总结

- **Bloom** 的原理：提取亮部 → 高斯模糊 → 叠加回原图，模拟"光溢出"的视觉心理
- **UnrealBloomPass** 四个参数：`resolution` / `strength` / `radius` / `threshold`
- **threshold 是线性空间**：要让物体发光，它的线性亮度必须超过阈值
- **让灯光发光**：用 `MeshBasicMaterial` 灯泡 + `setRGB(…, LinearSRGBColorSpace)` 写入 HDR 值（>1.0）
- **让玻璃发光**：玻璃着色器的 Fresnel 强度随灯强度变化，开灯时边缘突破阈值
- **B 键切换**：`bloomPass.enabled` 运行时开关，对比效果
