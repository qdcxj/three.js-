# LOD 与合并几何体

上一节我们装好了 Stats 面板，能看见 FPS、MS、DrawCall、三角形数了。现在的问题变成了："三角形数太多怎么办？DrawCall 太多怎么办？"——这两类问题的答案分别是 **LOD（多精度模型）** 和 **mergeGeometries（合并几何体）**。本节我们用 LOD 让远处家具自动退化为简单盒子，用 mergeGeometries 把 30 块碎石合并成 1 个几何体，最后讲清楚 Three.js 默认开启的 **frustum culling（视锥剔除）** 是怎么帮我们免费省下大量 DrawCall 的。

## 一、两类"减负"问题的区别

先建立全局认知。Three.js 场景里"渲染太慢"通常分两种：

| 问题 | 症状 | 优化手段 | 适用场景 |
|------|------|----------|----------|
| **单个物体太复杂** | 三角形数多 | LOD 多精度切换 | 树木、家具、角色等可"远看"的物体 |
| **物体数量太多** | DrawCall 数多 | mergeGeometries 合并 / InstancedMesh | 碎石、瓦片、落叶等大量重复静态物体 |

::: tip 不要混淆
LOD 解决的是"一个物体太复杂"——它把同一个物体的多套精度摆好，按距离切换。mergeGeometries 解决的是"很多个物体"——它把多个几何体合并成一个 BufferGeometry。两者方向不同，常配合使用：先合并静态物体降 DrawCall，再对剩下的复杂物体加 LOD 降三角形。
:::

## 二、LOD 多精度模型

### 2.1 LOD 是什么

LOD（Level of Detail，细节层次）的核心思想很简单：**远处的物体看不清，没必要用那么多三角形**。比如一张桌子，近处你能看清桌腿的纹理、桌布的褶皱，需要 50 个三角形；但拉到 20 米外，桌子就一个小方块，5 个三角形足矣。

Three.js 的 `THREE.LOD` 帮你管理这件事：你给它多套精度的网格，每套关联一个"距离阈值"，相机距离一变，它自动切换可见的那一级。

### 2.2 LOD 的 API

```js
const lod = new THREE.LOD();

// addLevel(object, distance)：在 distance 距离处显示 object
// 距离是从相机到 LOD 原点的世界距离
lod.addLevel(highDetailMesh, 0);   // 0~5 米：用高精度
lod.addLevel(lowDetailMesh, 5);    // 5~15 米：用低精度
lod.addLevel(new THREE.Object3D(), 15); // >15 米：用空对象（=不渲染）

scene.add(lod);
```

::: warning 距离阈值的含义
`addLevel(obj, d)` 表示"相机距离 ≥ d 时，切换到这一级"。Three.js 内部会按 distance 从小到大排序，找到第一个 `distance ≥ 当前相机距离` 的层级来显示。所以阈值要**递增**，且最后一级通常放一个 `Object3D`（空对象）实现"远到看不见就完全不渲染"。
:::

### 2.3 在 HouseScene.vue 中给家具加 LOD

stage-13 的家具原本是用 Box 拼出来的"高精度版"：桌子有桌面 + 4 腿 + 桌布共 6 块，椅子有座 + 靠背 + 4 腿共 6 块。我们给每件家具再做一个"低精度版"——一个整体盒子：

```js
import * as THREE from "three";

// 高精度桌子：桌面 + 4 腿 + 桌布（共 6 块）
const makeTableHigh = (matSet) => {
  const g = new THREE.Group();
  const top = new THREE.Mesh(
    new THREE.BoxGeometry(1.4, 0.08, 0.8),
    matSet.wood
  );
  top.position.y = 0.78;
  top.castShadow = true;
  g.add(top);

  const legGeo = new THREE.BoxGeometry(0.08, 0.78, 0.08);
  [[-0.6, -0.32], [0.6, -0.32], [-0.6, 0.32], [0.6, 0.32]].forEach(
    ([x, z]) => {
      const leg = new THREE.Mesh(legGeo, matSet.wood);
      leg.position.set(x, 0.39, z);
      leg.castShadow = true;
      g.add(leg);
    }
  );
  // ... 桌布略
  return g;
};

// 低精度桌子：一个整体盒子（1 块）
const makeTableLow = (matSet) => {
  const m = new THREE.Mesh(
    new THREE.BoxGeometry(1.4, 0.86, 0.8),
    matSet.wood
  );
  m.position.y = 0.43;
  m.castShadow = true;
  return m;
};
```

然后用 LOD 包装两者，加进房子组：

```js
const addLOD = (high, low, x, z, rotateY = 0) => {
  const lod = new THREE.LOD();
  lod.addLevel(high, 0);                    // 距离 <8 米：高精度
  lod.addLevel(low, 8);                      // 距离 8~18 米：低精度
  lod.addLevel(new THREE.Object3D(), 18);     // 距离 >18 米：空对象=不渲染
  lod.position.set(x, 0.35, z);
  lod.rotation.y = rotateY;
  houseGroup.add(lod);
};

// 餐桌 + 2 椅子 + 床 + 柜子，每件都用 LOD
addLOD(makeTableHigh(matSet), makeTableLow(matSet), 0, 1.0);
addLOD(makeChairHigh(matSet), makeChairLow(matSet), -0.9, 1.0);
addLOD(makeChairHigh(matSet), makeChairLow(matSet), 0.9, 1.0, Math.PI);
addLOD(makeBedHigh(matSet), makeBedLow(matSet), 2.5, -1.5, -Math.PI / 2);
addLOD(makeCabinetHigh(matSet), makeCabinetLow(matSet), -3.0, -2.0);
```

::: tip LOD 不需要 update
`THREE.LOD` 内部会在每帧渲染时自动检查相机距离并切换层级——你**不需要**在 animate 里手动调 `lod.update(camera)`。但前提是 LOD 已经被加进场景图，且相机位置是当前的。如果相机突然瞬移（如切换视角），第一帧可能短暂显示错误层级，下一帧就修正了。
:::

### 2.4 验证 LOD 生效

运行 stage-13 后，把相机拉远到 20 米外，再回来看 Stats 面板：

| 相机距离 | 显示的层级 | 三角形数 |
|----------|-----------|----------|
| <8 米 | 高精度（桌腿/桌布等） | 较多 |
| 8~18 米 | 低精度（整体盒子） | 较少 |
| >18 米 | 空对象（不渲染） | 0 |

把相机拉到 20 米外，能看到 Stats 的三角形数明显下降——这就是 LOD 在工作。

::: warning LOD 的"切换跳变"
LOD 切换是离散的——相机走到 8 米那一瞬间，桌子会从"高精度版"突然变成"低精度版"，肉眼能看到一次"跳变"。工业级方案是用 **几何形变（geomorphing）** 在两级之间做顶点插值过渡，但 Three.js 内置 LOD 不支持。教学场景下离散切换足够，工程化项目可考虑 `@dpmjs/three-mesh-bvh` 等扩展库。
:::

## 三、合并几何体 mergeGeometries

### 3.1 为什么需要合并

来看一个反面教材：草地上铺 30 块碎石，传统写法是循环创建 30 个 Mesh：

```js
// ❌ 烂写法：30 个 Mesh = 30 个 DrawCall
const stoneMat = new THREE.MeshStandardMaterial({ color: 0xa8a8a8 });
for (let i = 0; i < 30; i++) {
  const g = new THREE.BoxGeometry(0.3, 0.05, 0.3);
  const m = new THREE.Mesh(g, stoneMat);
  m.position.set(x, 0.025, z);
  scene.add(m); // 每加一个就多一个 DrawCall
}
```

打开 Stats 看 `renderer.info.render.calls`，会发现碎石占了 30 个 DrawCall。CPU 给 GPU 发 30 次绘制指令的开销，远大于实际画 30 个小盒子的 GPU 计算量——这就是 **CPU 瓶颈**的典型来源。

### 3.2 mergeGeometries 的用法

`mergeGeometries` 来自 `BufferGeometryUtils`，它接收一个 `BufferGeometry` 数组，返回一个合并后的新 `BufferGeometry`：

```js
import { mergeGeometries } from "three/examples/jsm/utils/BufferGeometryUtils.js";

// 准备一组小几何体（位置已 bake 进顶点）
const geos = [];
for (let i = 0; i < 30; i++) {
  const g = new THREE.BoxGeometry(0.3, 0.05, 0.3);
  // ★ 关键：把世界位置 bake 进顶点
  g.applyMatrix4(new THREE.Matrix4().makeTranslation(x, y, z));
  geos.push(g);
}

// 合并为一个 BufferGeometry
const merged = mergeGeometries(geos, false);

// 释放原始小几何体（已被合并进 merged，留着浪费内存）
geos.forEach((g) => g.dispose());

// 只用一个 Mesh 渲染——DrawCall 从 30 降为 1
const stones = new THREE.Mesh(merged, stoneMat);
scene.add(stones);
```

::: warning 必须先 bake 世界变换
`mergeGeometries` 只合并**顶点数据**，不合并 Mesh 的 `position`/`rotation`/`scale`。如果你不调 `applyMatrix4` 把变换烘焙进顶点，所有几何体合并后会**重叠在原点 (0,0,0)**。这是新手最常踩的坑——记得合并前先 bake。
:::

### 3.3 mergeGeometries 的前提条件

不是所有几何体都能随便合并，有几个硬性前提：

| 前提 | 不满足的后果 |
|------|-------------|
| **共用同一份材质** | 材质不同无法合并；要么先分组按材质合并，要么放弃合并 |
| **顶点属性一致**（都有 position / normal / uv） | 属性不一致合并会报错或丢失数据 |
| **布尔第二参数 `useGroups`** | 设为 `true` 时合并后保留材质分组（多材质场景），默认 `false` 单材质 |

::: tip 为什么必须共用材质
一个 Mesh 只能有一个材质（或一个材质数组）。合并几何体后只剩一个 Mesh，所以原几何体们必须共用同一份材质。如果你的碎石有"灰色石头 + 棕色泥土"两种材质，要么分两次合并（一次石头一次泥土），要么用 `useGroups=true` 让合并后的 geometry 带材质分组索引。
:::

### 3.4 在 HouseScene.vue 中合并碎石小径

stage-13 的 `addMergedStonePath()` 完整实现：

```js
import { mergeGeometries } from "three/examples/jsm/utils/BufferGeometryUtils.js";

const addMergedStonePath = () => {
  const stoneMat = new THREE.MeshStandardMaterial({
    color: 0xa8a8a8,
    roughness: 0.95,
    metalness: 0.0,
  });

  const geos = [];
  const STONE_COUNT = 30;
  for (let i = 0; i < STONE_COUNT; i++) {
    const size = 0.3 + Math.random() * 0.2;
    const g = new THREE.BoxGeometry(size, 0.05, size);
    // 沿 +Z 方向从台阶向远处铺开
    const x = (Math.random() - 0.5) * 1.5;
    const z = 3.5 + i * 0.25;
    const y = 0.025;
    // ★ 把平移烘焙进顶点
    g.applyMatrix4(new THREE.Matrix4().makeTranslation(x, y, z));
    geos.push(g);
  }
  // 合并所有小盒子为一个 BufferGeometry
  const merged = mergeGeometries(geos, false);
  // 释放原始小几何体
  geos.forEach((g) => g.dispose());

  const stones = new THREE.Mesh(merged, stoneMat);
  stones.castShadow = true;
  stones.receiveShadow = true;
  scene.add(track(stones));
};
```

合并后看 Stats：DrawCall 减少 29 次，三角形数不变（合并只降 DrawCall，不降三角形）。

### 3.5 何时该合并、何时不该

合并不是银弹，它有代价：

| 场景 | 该不该合并 |
|------|-----------|
| 大量静态且不重复的物体（碎石、瓦片、墙块） | ✅ 合并 |
| 大量重复的相同物体（落叶、雨滴） | ❌ 用 InstancedMesh（下节讲） |
| 需要单独移动/动画的物体（门、车） | ❌ 不能合并（合并后无法单独操作） |
| 材质不同的物体 | ⚠️ 需要先按材质分组，每组分别合并 |

::: tip 合并 vs InstancedMesh 的选择
**合并（mergeGeometries）** 适合"每个都不同"的静态物体（碎石大小不一）；**InstancedMesh** 适合"每个都一样"的重复物体（落叶全同形状）。两者都把 DrawCall 降到 1，但 InstancedMesh 还能在 GPU 端单独移动每个实例（CPU 设矩阵），合并则把所有变换固化进顶点、无法再单独动。下节会详细讲 InstancedMesh。
:::

## 四、frustum culling 视锥剔除

讲完 LOD 和合并，最后一个性能"免费午餐"是 **frustum culling（视锥剔除）**——它是 Three.js 默认开启的，你什么都不用做就能享受。

### 4.1 什么是视锥剔除

相机的视锥（frustum）是一个被 6 个平面切出的"截头金字塔"，只有视锥内的物体才会出现在画面上。Three.js 在每帧渲染前，会遍历场景图，对每个 Mesh 检查它的**包围球**是否与视锥相交：

- 相交 → 渲染
- 不相交 → 跳过（不发起 DrawCall）

这意味着即使场景里有 10000 个物体，相机只能看到 50 个时，DrawCall 也只有 50。

### 4.2 默认开启，无需配置

```js
const mesh = new THREE.Mesh(geo, mat);
console.log(mesh.frustumCulled); // true，默认就是开的
```

`frustumCulled = true` 是默认值，绝大多数情况下你不需要改它。

### 4.3 何时该关掉 frustumCulled

只有少数情况要手动设 `false`：

| 情况 | 原因 |
|------|------|
| **粒子系统**（`THREE.Points`） | 粒子运动范围大、几何体只是一个点，包围球不准，可能误判剔除导致粒子突然消失 |
| **自定义着色器渲染的"无限延伸"物体**（如天空盒） | 包围球可能不在视锥内但实际画面上还有像素 |
| **动画快速移动的物体** | 包围球没及时更新，一帧"消失"下一帧又出现 |

stage-13 里烟囱粒子就关掉了：

```js
const smokePoints = new THREE.Points(geo, mat);
smokePoints.frustumCulled = false; // 粒子运动范围小，关掉避免闪烁
scene.add(smokePoints);
```

::: warning 关掉 frustumCulled 的代价
关掉后该物体**每帧都会被渲染**，无论是否在视锥内。所以只对"必须始终渲染"的少数物体关闭，不要全局关。否则视锥剔除的免费优化就白白浪费了。
:::

### 4.4 包围球是怎么算的

每个 Mesh 有一个 `boundingSphere`（包围球），它在 `geometry.computeBoundingSphere()` 时根据所有顶点位置算出。如果你在运行时**修改了顶点位置**（如粒子动画），需要重新调 `computeBoundingSphere()` 让 culling 判断准确——否则可能出现"粒子明明在视锥里却被剔除"的 bug。

```js
// 修改顶点后重新计算包围球
geo.attributes.position.needsUpdate = true;
geo.computeBoundingSphere(); // ★ 必须，否则 frustumCulled 会误判
```

stage-13 的烟囱粒子动画里我们直接 `frustumCulled = false`，避开了这个问题；如果粒子运动范围大，正确的做法是每帧 `computeBoundingSphere()`。

## 五、三种优化对比

本节涉及的三种"减负"手段放在一起对比：

| 手段 | 解决的问题 | DrawCall | 三角形数 | 是否需要每帧 update |
|------|-----------|----------|----------|---------------------|
| **LOD** | 单个物体太复杂 | 不变 | 下降 | 否（自动切换） |
| **mergeGeometries** | 静态物体太多 | 下降 | 不变 | 否 |
| **frustum culling** | 视锥外物体不该渲染 | 下降 | 下降 | 否（默认开启） |

::: tip 三者不冲突
LOD、合并、frustum culling 可以同时用：合并后的 Mesh 仍然受 frustum culling 约束（视锥外整组跳过），LOD 物体内部每一级也各自受 culling 约束。所以工业级场景通常三层都开：先合并静态物体降 DrawCall，再给剩下的复杂物体加 LOD 降三角形，最后靠 frustum culling 把视锥外的全跳过。
:::

## 六、整合到 HouseScene.vue 的验证

把 LOD + 合并 + Stats 都装好后，跑 stage-13 做个对照实验：

| 操作 | Stats 显示 |
|------|-----------|
| 相机距房子 5 米 | 三角形数较多（家具用高精度版） |
| 相机距房子 12 米 | 三角形数明显下降（家具切换到低精度） |
| 相机距房子 25 米 | 三角形数更少（家具完全不渲染） |

## 本节总结

| 知识点 | 关键 API | 说明 |
|--------|---------|------|
| LOD 导入 | `import { THREE } from "three"`（内置） | `THREE.LOD` 是 three 主包自带的 |
| LOD 添加层级 | `lod.addLevel(mesh, distance)` | distance 是相机到 LOD 原点的世界距离 |
| LOD 自动切换 | 无需 update | Three.js 渲染时自动检查距离并切换 |
| 远端隐藏 | `lod.addLevel(new THREE.Object3D(), d)` | 空对象=不渲染 |
| 合并导入 | `mergeGeometries from "BufferGeometryUtils"` | 来自 three/examples/jsm/utils |
| 合并前提 | 共用材质 + 属性一致 + bake 变换 | 缺一不可，否则合并失败 |
| bake 变换 | `g.applyMatrix4(new THREE.Matrix4().makeTranslation(...))` | 把世界位置烘焙进顶点 |
| 释放原几何体 | `geos.forEach(g => g.dispose())` | 合并后原始几何体已无用 |
| frustum culling | `mesh.frustumCulled = true`（默认） | 视锥外自动跳过 |
| 关闭 culling | `mesh.frustumCulled = false` | 仅用于粒子等特殊场景 |
| 重建包围球 | `geo.computeBoundingSphere()` | 修改顶点后必须，否则 culling 误判 |

LOD 和合并把"静态物体"的优化讲完了。下一节 [InstancedMesh 与按需渲染](./03.InstancedMesh与按需渲染) 我们处理"大量重复物体"——200 片落叶用 InstancedMesh 一次 DrawCall 搞定，再加一个"按需渲染"模式让静态场景几乎零耗电。
:::
