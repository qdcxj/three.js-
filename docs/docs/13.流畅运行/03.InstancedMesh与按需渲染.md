# InstancedMesh 与按需渲染

上一节我们用 LOD 给家具减负、用 mergeGeometries 合并了碎石小径。但还有一类问题没解决——"大量重复的物体"，比如 200 片落叶、1000 朵花、5000 棵树。合并几何体当然也能处理，但合并后所有变换都被固化进顶点，**无法再单独移动每一片叶子**。这一节我们请出 Three.js 的"实例化网格" `InstancedMesh`：用一份 geometry + 一份 material + N 个实例矩阵，渲染 N 个相同物体，DrawCall 始终为 1，且每个实例都能单独摆位/旋转/缩放。最后我们加一个**按需渲染**模式：场景静止时不再每帧空转，仅在用户拖拽相机或按键时才重绘一帧——让你的笔记本风扇都安静下来。

## 一、为什么需要 InstancedMesh

先看反面教材。在草地上撒 200 片落叶，传统写法是循环创建 200 个 Mesh：

```js
// ❌ 烂写法：200 个 Mesh = 200 个 DrawCall
const leafGeo = new THREE.PlaneGeometry(0.15, 0.15);
const leafMat = new THREE.MeshStandardMaterial({ color: 0xd97706 });
for (let i = 0; i < 200; i++) {
  const leaf = new THREE.Mesh(leafGeo, leafMat);
  leaf.position.set(x, y, z);
  scene.add(leaf); // 每加一片就多一个 DrawCall
}
```

打开 Stats 看 `renderer.info.render.calls`：200 片叶子占了 200 个 DrawCall。CPU 给 GPU 发 200 次绘制指令的开销巨大——而每片叶子只有 2 个三角形，GPU 实际计算量微乎其微。**瓶颈完全在 CPU 端**。

`InstancedMesh` 就是为这种场景而生：用 1 个 DrawCall 渲染 N 个相同物体，且每个实例的位置/旋转/缩放可独立设置。

## 二、InstancedMesh 的 API

```js
const instancedMesh = new THREE.InstancedMesh(geometry, material, count);
// count 是实例数量，创建后不可改
```

三个参数：

| 参数 | 类型 | 说明 |
|------|------|------|
| `geometry` | `BufferGeometry` | 一份几何体，所有实例共用 |
| `material` | `Material` | 一份材质，所有实例共用 |
| `count` | `number` | 实例数量，创建时确定 |

::: warning count 创建后不可改
`InstancedMesh` 的实例数量在构造时就定死了。如果你需要动态增减，只能"创建一个大的 + 用矩阵缩放为 0 隐藏多余的"——把不想渲染的实例矩阵设为全 0 矩阵即可。
:::

### 2.1 设置实例矩阵

每个实例的位置/旋转/缩放由一个 4×4 矩阵描述，用 `setMatrixAt(i, matrix4)` 设置：

```js
import * as THREE from "three";

const dummy = new THREE.Object3D(); // 复用临时对象，避免每帧 new
for (let i = 0; i < count; i++) {
  // 用 dummy 设置位置/旋转/缩放
  dummy.position.set(x, y, z);
  dummy.rotation.set(rx, ry, rz);
  dummy.scale.set(sx, sy, sz);
  dummy.updateMatrix(); // 把变换更新到 dummy.matrix

  instancedMesh.setMatrixAt(i, dummy.matrix);
}
// ★ 必须设 needsUpdate 让 GPU 重新上传矩阵数据
instancedMesh.instanceMatrix.needsUpdate = true;
```

::: tip 复用临时对象
循环里**不要 `new THREE.Object3D()` 或 `new THREE.Matrix4()`**——每次 new 都触发 GC，200 片叶子循环就 new 200 次，性能反而比 200 个 Mesh 还差。正确做法是在循环外创建一个 `dummy` 对象，循环内反复更新它的属性。stage-13 里我们用 `_leafMatrix` / `_leafPos` / `_leafQuat` / `_leafScale` 等模块级临时变量复用。
:::

### 2.2 矩阵的内部结构

`Matrix4` 是一个 16 元素的数组（4×4），描述了"平移 + 旋转 + 缩放"的组合变换：

```js
// 等价于：
const m = new THREE.Matrix4();
m.compose(position, quaternion, scale);
// position: Vector3
// quaternion: Quaternion（避免欧拉角万向锁）
// scale: Vector3
```

stage-13 里我们直接用 `Matrix4.compose()` 而不是 `Object3D`，更轻量：

```js
const _leafMatrix = new THREE.Matrix4();
const _leafPos = new THREE.Vector3();
const _leafQuat = new THREE.Quaternion();
const _leafScale = new THREE.Vector3();
const _leafEuler = new THREE.Euler();

for (let i = 0; i < LEAVES_COUNT; i++) {
  _leafPos.set(x, y, z);
  _leafEuler.set(rx, ry, rz);
  _leafQuat.setFromEuler(_leafEuler);
  _leafScale.set(sx, sy, sz);
  _leafMatrix.compose(_leafPos, _leafQuat, _leafScale);
  leavesMesh.setMatrixAt(i, _leafMatrix);
}
leavesMesh.instanceMatrix.needsUpdate = true;
```

## 三、在 HouseScene.vue 中创建 200 片落叶

stage-13 的 `addInstancedLeaves()` 完整实现：

```js
const LEAVES_COUNT = 200;
let leavesMesh = null;

// 模块级临时变量，循环复用避免 GC
const _leafMatrix = new THREE.Matrix4();
const _leafPos = new THREE.Vector3();
const _leafQuat = new THREE.Quaternion();
const _leafScale = new THREE.Vector3();
const _leafEuler = new THREE.Euler();

const addInstancedLeaves = () => {
  // 单片叶子的几何：0.15×0.15 的平面（双面）
  const leafGeo = new THREE.PlaneGeometry(0.15, 0.15);
  // 叶子材质：暖橙色（秋天落叶）
  const leafMat = new THREE.MeshStandardMaterial({
    color: 0xd97706,
    roughness: 0.8,
    metalness: 0.0,
    side: THREE.DoubleSide,
  });

  leavesMesh = new THREE.InstancedMesh(leafGeo, leafMat, LEAVES_COUNT);
  leavesMesh.castShadow = true;
  leavesMesh.receiveShadow = true;

  // 给每个实例设置初始矩阵
  leavesMesh.userData.basePositions = []; // 存基准位置，方便 animate 摆动
  for (let i = 0; i < LEAVES_COUNT; i++) {
    // 随机散布在 40x40 草地上，避开房子地基范围
    let x, z;
    do {
      x = (Math.random() - 0.5) * 38;
      z = (Math.random() - 0.5) * 38;
    } while (Math.abs(x) < 5 && Math.abs(z) < 3.5);
    const y = 0.05 + Math.random() * 0.05;

    _leafPos.set(x, y, z);
    _leafEuler.set(
      Math.random() * Math.PI,
      Math.random() * Math.PI,
      Math.random() * Math.PI
    );
    _leafQuat.setFromEuler(_leafEuler);
    const s = 0.7 + Math.random() * 0.6;
    _leafScale.set(s, s, s);
    _leafMatrix.compose(_leafPos, _leafQuat, _leafScale);
    leavesMesh.setMatrixAt(i, _leafMatrix);
    leavesMesh.userData.basePositions.push({ x, y, z, phase: Math.random() * Math.PI * 2 });
  }
  leavesMesh.instanceMatrix.needsUpdate = true;
  leavesMesh.frustumCulled = true; // 默认就是 true，显式说明
  scene.add(track(leavesMesh));
};
```

::: warning 避开地基范围
`do...while` 循环排除了 `|x|<5 && |z|<3.5` 的区域——这是房子地基范围，叶子掉在屋顶或地板上会很奇怪。这是个小细节，但能让落叶分布看起来更自然。
:::

## 四、动态更新实例矩阵（风吹落叶）

InstancedMesh 真正的强大在于**可以每帧更新实例矩阵**，实现"风吹落叶"这类动画：

```js
const updateLeaves = (time) => {
  if (!leavesMesh) return;
  const bases = leavesMesh.userData.basePositions;
  if (!bases) return;

  for (let i = 0; i < LEAVES_COUNT; i++) {
    const b = bases[i];
    // 用 sin 让叶子在原地小幅起伏 + 旋转
    const wobble = Math.sin(time * 1.5 + b.phase) * 0.05;
    _leafPos.set(b.x, b.y + wobble, b.z);
    _leafEuler.set(
      Math.PI / 2 + Math.sin(time + b.phase) * 0.2,
      time * 0.3 + b.phase,
      0
    );
    _leafQuat.setFromEuler(_leafEuler);
    _leafScale.set(1, 1, 1);
    _leafMatrix.compose(_leafPos, _leafQuat, _leafScale);
    leavesMesh.setMatrixAt(i, _leafMatrix);
  }
  // ★ 必须！否则 GPU 不知道矩阵变了
  leavesMesh.instanceMatrix.needsUpdate = true;
};
```

::: tip needsUpdate 是关键
所有 InstancedMesh 的动态更新都必须在循环结束后调 `instanceMatrix.needsUpdate = true`。忘了调的话 GPU 永远用旧矩阵，叶子一动不动。这是新手最容易忘的一行——务必养成"setMatrixAt 后必设 needsUpdate"的肌肉记忆。
:::

## 五、InstancedMesh vs mergeGeometries vs Mesh

把这三种方案放在一起对比，帮你建立选择直觉：

| 方案 | DrawCall | 单独移动 | 内存占用 | 适用场景 |
|------|----------|----------|----------|----------|
| **N 个独立 Mesh** | N | ✅ 可单独动 | 高（每个 Mesh 一份对象） | 物体数量少（<100） |
| **mergeGeometries** | 1 | ❌ 变换固化进顶点 | 低 | 静态、形状各异的物体 |
| **InstancedMesh** | 1 | ✅ 可单独动矩阵 | 中 | 大量重复形状的物体 |

::: tip 选择的判断流程
先问："**物体形状都一样吗？**" 不一样→合并或独立 Mesh；一样→再问："**需要每帧单独动吗？**" 不需要→合并；需要→InstancedMesh。stage-13 的落叶（同形状 + 需要摆动）正是 InstancedMesh 的典型场景。
:::

## 六、按需渲染

讲完 InstancedMesh，本节第二个重点是**按需渲染**。前面所有阶段的渲染循环都是这样的：

```js
// 一直每帧渲染（无论场景动不动）
const animate = () => {
  animationId = requestAnimationFrame(animate);
  // ... 更新动画
  renderer.render(scene, camera); // 每帧都画
};
```

问题：即使场景完全静止（用户没拖相机、没按键），`requestAnimationFrame` 仍每秒触发 60 次，`render()` 仍每帧画一遍——**GPU 在空转，白白耗电发热**。

### 6.1 脏标记模式

按需渲染的思路：用一个 `needsRender` 布尔变量做"脏标记"。只有标记为 `true` 时才真正调 `render()`，渲染完立刻设回 `false`。

```js
let needsRender = true; // 初始为 true，保证第一帧画出来

const animate = () => {
  animationId = requestAnimationFrame(animate);
  if (stats) stats.begin();

  controls.update(); // 阻尼仍需每帧 update

  if (needsRender) {
    renderer.render(scene, camera); // ★ 只在脏时才画
    needsRender = false;             // 画完置回干净
  }

  if (stats) stats.end();
};
```

### 6.2 谁来"弄脏"场景

`needsRender = true` 必须在以下时机触发：

| 时机 | 怎么触发 |
|------|----------|
| 用户拖拽相机 | 监听 `controls.addEventListener("change", ...)` |
| 用户按键 | `onKeyDown` 里设 `needsRender = true` |
| resize | `handleResize` 里设 `needsRender = true` |
| 主动调用动画 | 如开门动画启动时设 `needsRender = true` |

stage-13 里我们监听 OrbitControls 的 `change` 事件：

```js
const onControlsChange = () => {
  needsRender = true;
};

// 在 onMounted 里
controls.addEventListener("change", onControlsChange);

// 在 onKeyDown 里
const onKeyDown = (e) => {
  // ...
  if (key === "o") {
    doorState = doorState === 0 ? 1 : 0;
    needsRender = true; // ★ 状态变化，标记需要重绘
  }
  // ...
};
```

::: warning 阻尼模式下的特殊情况
OrbitControls 启用 `enableDamping` 时，用户松开鼠标后阻尼还会持续一小段时间——这段时间 `change` 事件会持续触发，`needsRender` 持续为 `true`，画面会一直渲染到阻尼停止。所以 `controls.update()` 必须**每帧都调**，不能只在 `needsRender` 时调，否则阻尼不会平滑停止。
:::

### 6.3 与动画的冲突

按需渲染的"死敌"是**持续动画**——昼夜循环、烟雾上升、落叶摆动这些都是每帧都要更新的，如果只在 `needsRender` 时才渲染，动画就停了。

stage-13 的解决方案是**双模式**：

- **动画全开模式**（默认）：每帧都更新所有动画 + 渲染
- **静态按需模式**（按 P 切换）：停掉所有动画，仅在 `needsRender` 时渲染

```js
const animate = () => {
  animationId = requestAnimationFrame(animate);
  if (stats) stats.begin();

  const dt = clock.getDelta();
  const time = clock.elapsedTime;

  if (perfMode) {
    // 静态按需渲染：所有动画暂停，仅在 needsRender=true 时渲染
    controls.update();
    if (needsRender) {
      renderer.render(scene, camera);
      updateRenderInfo();
      needsRender = false;
    }
  } else {
    // 动画全开：每帧更新 + 渲染
    controls.update();
    updateDoor(dt);
    updateLamp(dt);
    updateDayNight(dt);
    updateSmoke(dt);
    updateLeaves(time);
    renderer.render(scene, camera);
    updateRenderInfo();
  }

  if (stats) stats.end();
};
```

按 P 切到静态模式后，相机不动时 Stats 的 MS 数值会瞬间降到接近 0——这就是按需渲染的威力。

::: tip 静态模式不是"暂停"
按 P 切到静态模式不是"暂停动画"，而是"停掉所有动画 + 改用按需渲染"。两者有微妙区别：暂停动画可以单独立项（如按空格暂停所有动画但渲染方式不变），按需渲染是渲染层面的优化。stage-13 把两者绑在一起，是因为按需渲染的前提就是"场景静止"。
:::

### 6.4 何时该用按需渲染

| 场景 | 该不该用按需渲染 |
|------|------------------|
| 纯展示型 3D 模型查看器（无动画） | ✅ 强烈推荐，省电巨大 |
| 产品配置器（用户偶尔操作） | ✅ 推荐 |
| 游戏场景（一直有动画） | ❌ 没意义，每帧都得画 |
| 有"持续动画 + 偶尔静止"的场景 | ⚠️ 用 stage-13 这种双模式切换 |

::: tip 实战经验
很多企业级 3D 配置器（如汽车选配、家具摆放）默认就用按需渲染——用户调整时画面跟手，松手后立刻进入"零耗电"状态。这能让笔记本电池续航从 1 小时延长到 4 小时，体验提升巨大。
:::

## 七、本阶段性能优化全景

stage-13 装齐了所有优化后，对比 stage-12 看效果：

| 优化项 | 优化前 | 优化后 | 看哪个指标 |
|--------|--------|--------|-----------|
| 落叶 200 片 | 200 DrawCall | 1 DrawCall | `renderer.info.render.calls` |
| 碎石 30 块 | 30 DrawCall | 1 DrawCall | `renderer.info.render.calls` |
| 远处家具 4 件 | 高精度 ~50 三角形/件 | 低精度 12 三角形/件或不渲染 | `renderer.info.render.triangles` |
| 视锥外物体 | 也会被渲染 | 自动跳过 | `renderer.info.render.calls` |
| 静态场景 | 每帧都渲染 | 仅交互时渲染 | Stats MS 模式 |

按 P 切到静态模式，相机不动时 Stats MS 几乎为 0；动相机时 MS 才短暂上升——这就是"按需渲染"的终极目标。

## 八、性能优化的心法

最后总结一下本章节贯穿始终的几条心法：

1. **先测量，再优化**：Stats 面板 + `renderer.info` 是你的眼睛，没有它们就是瞎猜
2. **先找瓶颈，再选手段**：CPU 瓶颈（DrawCall 多）用合并/InstancedMesh；GPU 瓶颈（三角形多）用 LOD；内存瓶颈（泄漏）用 dispose
3. **不要过度优化**：60FPS 已经流畅，再降 DrawCall 也不会让用户体验更好——优化的边际收益递减，工程时间宝贵
4. **dispose 是底线**：再快也挡不住内存泄漏，stage-13 的 `disposeScene` 完整释放了 Stats DOM、几何体、材质、纹理、控制器、渲染器
5. **可观测优先**：Stats 挂上去后，所有后续优化都"看得见"——这就是为什么本章节从性能监测开始

::: warning 一个反例
有人为了"极致优化"把所有物体的 `castShadow` 都关了，结果画面丑得没法看——这是典型的"为了性能牺牲体验"。性能优化的目标是"在不损失可见体验的前提下让运行更流畅"，不是"为数字好看而牺牲画面"。记住：用户看的是画面，不是 FPS 数字。
:::

## 本节总结

| 知识点 | 关键 API | 说明 |
|--------|---------|------|
| InstancedMesh 创建 | `new THREE.InstancedMesh(geo, mat, count)` | count 创建后不可改 |
| 设置实例矩阵 | `instancedMesh.setMatrixAt(i, matrix4)` | 用 Matrix4.compose 生成矩阵 |
| 标记更新 | `instancedMesh.instanceMatrix.needsUpdate = true` | 改完必须设，否则 GPU 用旧矩阵 |
| 复用临时对象 | 模块级 `_leafMatrix` / `_leafPos` 等 | 避免循环内 new 导致 GC |
| 脏标记渲染 | `let needsRender = true` + `if (needsRender) render()` | 静止时不渲染 |
| 触发重绘 | `controls.addEventListener("change", ...)` | 用户交互时设 `needsRender = true` |
| 双模式切换 | `if (perfMode) { 按需 } else { 动画全开 }` | 兼顾动画与省电 |
| 阻尼仍需每帧 update | `controls.update()` 在 if 之外 | 否则阻尼不会平滑停止 |
| 三方案对比 | Mesh / mergeGeometries / InstancedMesh | 看物体是否同形状 + 是否需单独动 |
