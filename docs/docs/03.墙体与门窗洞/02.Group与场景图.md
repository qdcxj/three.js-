# Group 与场景图

上一节我们学了怎么把单个 `Object3D` 摆到合适的位置。但一栋房子有十多块墙板、一扇门、将来还有屋顶、烟囱、家具……如果全都直接 `scene.add()`，那场景里就是一团「扁平散沙」——你想整体移动房子怎么办？想整体旋转怎么办？想隐藏所有墙怎么办？

`Group` 就是来解这个问题的。它本身也是 `Object3D`，但多了「容器」的能力：可以把多个子对象挂到它下面，形成一个**有层级的场景图**。本节我们学习 Group 的基本用法，以及和它紧密相关的几个 API：`add` / `remove` / `traverse` / `getObjectByName`，还有局部坐标 vs 世界坐标的区分。

## 一、Group 是什么

`Group` 是 `Object3D` 的子类，它本身**不渲染任何几何体**，只是一个「容器」：

```js
import * as THREE from "three";

const group = new THREE.Group();
group.name = "house";

const mesh1 = new THREE.Mesh(geo1, mat1);
const mesh2 = new THREE.Mesh(geo2, mat2);

group.add(mesh1);
group.add(mesh2);

scene.add(group);
```

这一刻，`mesh1` 和 `mesh2` 成了 `group` 的子节点，`group` 又是 `scene` 的子节点。结构如下：

```
scene
└── group (name: house)
    ├── mesh1
    └── mesh2
```

::: tip Group 的本质
`Group` 自己也是一个 `Object3D`，所以它有 `position` / `rotation` / `scale`。给 `group` 设置变换，会**自动作用到所有子节点**——这就是「整体移动」的实现方式。
:::

## 二、add / remove：组装与拆解

`add` 把一个或多个 `Object3D` 挂到当前对象下：

```js
// 一次 add 多个
group.add(mesh1, mesh2, mesh3);

// 也可以从别的父节点「搬过来」
const oldParent = mesh.parent;
oldParent.remove(mesh);
group.add(mesh);
```

`remove` 则相反：

```js
group.remove(mesh1); // 把 mesh1 从 group 里拆下来
```

被 `remove` 的对象**不会自动释放显存**——它只是从场景图里脱离。如果想彻底删除一个 Mesh，记得手动 `geometry.dispose()` 和 `material.dispose()`。

::: warning remove ≠ dispose
`remove` 只是从场景图里拿走，**资源仍在显存里**。要彻底释放必须显式 `dispose`。这是 Three.js 内存泄漏最常见的来源——后续我们会在 dispose 章节详讲。
:::

## 三、父子层级：变换会「传递」

这是 Group 最强大的特性：父节点的 `position` / `rotation` / `scale` 会**累积作用到子节点的世界坐标**。

```js
import * as THREE from "three";

const house = new THREE.Group();
house.position.set(5, 0, 0); // 整栋房子向右移 5 米
scene.add(house);

const wall = new THREE.Mesh(geo, mat);
wall.position.set(0, 1.8, -3); // 局部坐标：墙相对 house 偏移
house.add(wall);

// wall 的「世界坐标」= house 的变换 + wall 的局部变换
// 即 (5, 0, 0) + (0, 1.8, -3) = (5, 1.8, -3)
console.log(wall.position);          // (0, 1.8, -3) —— 局部坐标不变
console.log(wall.getWorldPosition(new THREE.Vector3())); // (5, 1.8, -3) —— 世界坐标
```

这就是为什么我们项目里把整栋房子放进 `house` Group——只要给 `house` 设置 `position`，所有墙、门都会跟着移动；旋转、缩放同理。

## 四、局部坐标 vs 世界坐标

这是 Group 学习里最容易混淆的概念。同一个对象有**两套坐标**：

- **局部坐标**：`mesh.position`，相对于**父节点**的位置
- **世界坐标**：`mesh.matrixWorld` 派生，相对于**场景根**的位置

```js
// 局部坐标（直接读）
mesh.position; // Vector3

// 世界坐标（要通过方法获取，且要先更新矩阵）
scene.updateMatrixWorld(true); // 强制刷新世界矩阵
const worldPos = new THREE.Vector3();
mesh.getWorldPosition(worldPos);
console.log(worldPos);
```

在动画循环里，`renderer.render(scene, camera)` 会自动调用 `updateMatrixWorld`，所以渲染时世界矩阵总是最新的。但如果你在渲染之外（比如 onClick 里）想读世界坐标，最好手动 `updateMatrixWorld(true)` 一次。

::: tip 何时关心世界坐标
- 跟随相机：相机需要看向「世界坐标」的目标
- 碰撞检测：两个 Mesh 是否相交看的是世界坐标
- 鼠标拾取：射线检测的是世界坐标
- 大多数「摆放」场景：用局部坐标即可，因为父节点没变换
:::

## 五、traverse：递归遍历整棵子树

`traverse` 是一个递归遍历方法，会**深度优先**地访问当前对象和它所有子孙节点：

```js
house.traverse((obj) => {
  console.log(obj.name, obj.type);
  // house Group
  // walls Group
  // back-wall Mesh
  // left-wall Group
  // left-wall-front Mesh
  // ...
});
```

我们项目里用 `traverse` 来**统一释放资源**：

```js
function dispose(obj) {
  obj.traverse((child) => {
    if (child.isMesh) {
      child.geometry?.dispose();
      if (Array.isArray(child.material)) {
        child.material.forEach((m) => m.dispose());
      } else {
        child.material?.dispose();
      }
    }
  });
}
```

只要对 `house` 调一次 `dispose(house)`，它下面所有 Mesh 的 geometry / material 都会被释放。

::: warning traverse 的性能
`traverse` 会访问整棵子树，节点越多越慢。在每帧调用 `traverse` 是性能杀手。需要每帧遍历的场景请用 `getObjectsByProperty` 或者自己维护一个扁平数组。
:::

## 六、getObjectByName：按名字查找节点

`Object3D` 给每个对象都提供了一个 `name` 属性（字符串）。配合 `getObjectByName` 可以**深度查找**子树里第一个匹配名字的对象：

```js
const house = new THREE.Group();
house.name = "house";

const door = new THREE.Mesh(geo, mat);
door.name = "door";
house.add(door);

// 在 house 子树里找名为 "door" 的对象
const found = house.getObjectByName("door");
console.log(found === door); // true
```

`getObjectByName` 默认递归查找。如果只想找直接子节点，传第二个参数 `false`：

```js
// 只在直接子节点里找
const direct = house.getObjectByName("door", false);
```

我们项目里给门命名为 `door`，正是为了 stage-08 的开关门动画能通过 `house.getObjectByName("door")` 拿到它：

```js
// stage-08 开门动画伪代码
const door = house.getObjectByName("door");
door.rotation.y = Math.PI / 2; // 假装门绕 Y 轴打开
```

::: tip 命名的工程价值
给关键节点起名是 3D 项目工程化的标志之一。相比「记住对象引用」，命名查找更解耦——你可以在代码任何地方通过名字拿到节点，而不需要层层传引用。但代价是字符串容易拼错，且无类型提示，所以**仅给关键节点命名**（门、窗、相机等），不要给每块墙都起名。
:::

## 七、实战：把墙体组织成层级

把前面学的串起来。我们项目的墙体层级是这样组织的：

```
scene
└── house (Group)
    ├── walls (Group)        # 墙体归到一起，方便整体隐藏/批量操作
    │   ├── back-wall (Mesh)
    │   ├── left-wall (Group)
    │   │   ├── left-wall-front (Mesh)
    │   │   ├── left-wall-back (Mesh)
    │   │   ├── left-wall-sill (Mesh)
    │   │   └── left-wall-header (Mesh)
    │   ├── right-wall (Group)
    │   │   └── ... (4 块)
    │   └── front-wall (Group)
    │       └── ... (9 块)
    └── door (Mesh)          # 门是「活动构件」，直接挂到 house 下
```

代码实现：

```js
import * as THREE from "three";

// 整栋房子
const house = new THREE.Group();
house.name = "house";

// 墙体子分组
const wallsGroup = new THREE.Group();
wallsGroup.name = "walls";
wallsGroup.add(createBackWall());
wallsGroup.add(createLeftWall());
wallsGroup.add(createRightWall());
wallsGroup.add(createFrontWall());
house.add(wallsGroup);

// 门板（不进 wallsGroup，因为它是活动构件）
const door = createDoor();
house.add(door);

scene.add(house);
```

为什么门不放进 `wallsGroup`？因为「墙」是**静态结构**，而「门」是**活动构件**。把它们分开，将来如果需要对墙整体着色、整体隐藏，只操作 `wallsGroup` 就行；对门做动画时也不会影响墙。这就是**按职责分组**的工程思维。

::: tip 为什么前墙、左墙、右墙都各自是 Group
因为它们都由「多块 Box 拼接」而成（详见下一节）。把一面墙的多块 Box 放到一个子 Group 里，调试时一眼就能看出「这 9 块属于前墙」——比让 9 个 Mesh 平铺在 wallsGroup 里清晰得多。
:::

## 本节总结

| 知识点 | 要点 |
|--------|------|
| `Group` | 容器型 `Object3D`，本身不渲染，但能挂载子节点 |
| `add` / `remove` | 把子节点加入 / 移出当前对象 |
| 变换传递 | 父节点的 `position`/`rotation`/`scale` 会累积作用到子节点的世界坐标 |
| 局部坐标 vs 世界坐标 | `position` 是局部；`getWorldPosition` 是世界 |
| `traverse` | 深度优先遍历整棵子树；释放资源时常用 |
| `getObjectByName` | 按 `name` 深度查找节点；用于解耦访问关键节点 |
| 按职责分组 | 把静态结构与活动构件分开，便于后续单独操作 |
