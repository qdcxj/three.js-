# 安装门板

四面墙已经砌好，门洞也按 `1.0 × 2.0` 的尺寸留出来了。本节我们做一件简单但关键的事：把一扇木门嵌进门洞里，并给它起名 `door`。

为什么说「关键」？因为这扇门不是一个静态的墙板——它是**活动构件**，stage-08 会让它绕铰链旋转开关。今天我们虽然只是把它「摆」在门洞里，但已经为后续动画埋下了两个伏笔：

1. **节点命名**：`door.name = "door"`，让后续代码可以通过 `getObjectByName("door")` 拿到引用
2. **挂载位置**：门直接挂到 `house` 下而不是 `wallsGroup`，因为墙是静态结构、门是活动构件，按职责分组

## 一、门的尺寸与位置

按 `HOUSE_SPEC.md`：

- 门板尺寸：`1.0(X) × 2.0(Y) × 0.05(Z)`
- 门板中心：`(0, 1.3, 3.05)`
- 材质：`#8b5a2b` 木色
- 命名：`door`

门洞范围（前墙留洞）：`x ∈ [-0.5, 0.5]`、`y ∈ [0.3, 2.3]`、`z = 3`。门板尺寸 `1.0 × 2.0` 正好嵌入门洞，所以中心 `y = 0.3 + 1.0 = 1.3`，`x = 0`。

::: tip 为什么 z = 3.05？
前墙中心在 `z = 3`，墙厚 0.2，所以墙体范围 `z ∈ [2.9, 3.1]`。门板放在 `z = 3.05`，是墙体的**前侧**（朝外那一侧）。这样门板「贴在墙的前面」，更接近真实门的外观。stage-08 做开关门动画时，门会绕一侧的铰链旋转，这个 z 偏移也给动画留了余地。
:::

## 二、创建门板

```js
import * as THREE from "three";

function createDoor() {
  // 1.0(X) × 2.0(Y) × 0.05(Z)
  const geometry = new THREE.BoxGeometry(1.0, 2.0, 0.05);
  const material = new THREE.MeshStandardMaterial({
    color: 0x8b5a2b, // 木色
    roughness: 0.7,
    metalness: 0.0,
  });

  const door = new THREE.Mesh(geometry, material);
  door.position.set(0, 1.3, 3.05);

  // 关键：给门命名，后续 stage-08 动画会通过 getObjectByName 拿到它
  door.name = "door";

  return door;
}
```

注意门板的材质**没有**和墙体共享——因为门是木色，墙是暖米色，颜色不同。而且门将来会单独贴木纹贴图（stage-05），所以门的材质必须是独立实例。

## 三、把门挂到 house 下

回顾上一节：墙体都挂在 `wallsGroup` 子分组里。门板不一样——它**不挂到 `wallsGroup`**，而是直接挂到 `house`：

```js
function createHouse() {
  const house = new THREE.Group();
  house.name = "house";

  // 1. 墙体（静态结构）
  const wallMaterial = createWallMaterial();
  const wallsGroup = new THREE.Group();
  wallsGroup.name = "walls";
  wallsGroup.add(createBackWall(wallMaterial));
  wallsGroup.add(createLeftWall(wallMaterial));
  wallsGroup.add(createRightWall(wallMaterial));
  wallsGroup.add(createFrontWall(wallMaterial));
  house.add(wallsGroup);

  // 2. 门板（活动构件，直接挂到 house，不进 wallsGroup）
  const door = createDoor();
  house.add(door);

  return house;
}

scene.add(createHouse());
```

### 为什么门不进 wallsGroup？

这是**按职责分组**的工程思维：

- `wallsGroup` 是「静态结构」：四面墙不会动，将来一起换贴图、一起隐藏都很方便
- `door` 是「活动构件」：stage-08 会单独旋转它做开关门动画

如果把门也放进 `wallsGroup`，将来想隐藏所有墙时会把门一起隐藏——但你可能希望「墙隐藏、门留下」做特写镜头。把门单独挂出来，将来想操作墙时只动 `wallsGroup`，想操作门时只动 `door`，互不干扰。

::: tip 工程思维
3D 项目里**职责分离**比「省几个 Group」更重要。多一层 Group 的代价几乎可以忽略（一次矩阵乘法），但带来的解耦收益是巨大的。
:::

## 四、通过名字找到门

我们已经给门命名为 `door`。现在可以演示一下 `getObjectByName` 的查找能力：

```js
const house = createHouse();
scene.add(house);

// 在 house 子树里查找名为 "door" 的对象
const door = house.getObjectByName("door");
console.log("找到了：", door.name, door.position);
// 输出：找到了：door (0, 1.3, 3.05)
```

`getObjectByName` 会**深度优先**地查找子树，所以无论 door 挂在 house 下哪一层，都能被找到。这意味着即使将来你给 wallsGroup 再加一层「门框」子分组，门查找代码也不用改。

::: warning 名字要唯一
`getObjectByName` 返回**第一个**匹配的对象。如果你给多个对象起同名，只能找到第一个。所以关键节点的名字要确保唯一性——比如不要给前后两扇门都叫 `door`，应该叫 `front-door` 和 `back-door`。
:::

## 五、为 stage-08 开关门动画预留接口

stage-08 会实现开门 / 关门动画。虽然现在门是「贴」在门洞里，但动画的雏形已经能演示——把门绕 Y 轴旋转一下，门就会「打开」：

```js
// stage-08 开门动画的伪代码
const door = house.getObjectByName("door");

// 让门绕「左侧铰链」打开 90°
// 注意：直接 rotation.y 会让门绕自己中心转，需要先把门的「几何中心」平移到左侧
// stage-08 会用 Group 包装门来实现「绕铰链」效果
door.rotation.y = -Math.PI / 2;
```

::: tip 真实的门铰链
真实门的铰链在门的一侧（左或右），门绕铰链旋转。但 Three.js 里默认 `rotation.y` 是绕**对象自身中心**旋转。要模拟铰链，需要把门放进一个 Group，让 Group 的中心对齐铰链位置——这个细节我们留到 stage-08 详讲。本阶段只要把门摆好、命名好就够了。
:::

## 六、运行效果

完成本节后，你的场景应该包含：

- 一片绿色草地（40×40）
- 一块灰色地基（8×0.3×6）
- 两级灰色台阶
- 四面暖米色墙体（含门洞、两个前窗洞、两个侧窗洞）
- 一扇嵌在门洞里的木色门板

打开浏览器，用鼠标拖拽可以环绕观察这栋小屋。从正面看，你能看到门板和两个窗洞；从侧面看，能看到侧墙的窗洞；从背面看，是一整块完整的墙。

::: tip 调试技巧
你可以打开浏览器控制台，输入：
```js
// 找到 house
const house = scene.children.find(c => c.name === "house");

// 把整栋房子向右移 2 米
house.position.x = 2;

// 隐藏所有墙，只看门
house.getObjectByName("walls").visible = false;
```
这些操作都是「即时生效」的——下一帧渲染就会反映出来。这是命名 + Group 带来的调试便利。
:::

## 本节总结

| 知识点 | 要点 |
|--------|------|
| 门板尺寸 | `1.0 × 2.0 × 0.05`，中心 `(0, 1.3, 3.05)` |
| 门板材质 | 独立 `MeshStandardMaterial({ color: 0x8b5a2b })`，不与墙共享 |
| 节点命名 | `door.name = "door"`，方便后续 `getObjectByName` 查找 |
| 挂载位置 | 直接挂 `house`，不进 `wallsGroup`，按职责分离 |
| 接口预留 | 给 stage-08 开关门动画留好命名引用，旋转接口 `rotation.y` 可用 |
| 调试便利 | 命名 + Group 让运行时操作变得直观（移动整栋房子、隐藏墙体） |

## 阶段总结

恭喜！stage-03 完成了。你的 3D 场景已经从「光秃秃的地基」变成了「有围墙、有门窗洞、有门板」的毛坯房。

回顾本章节，你学到了：

1. **Object3D 基类**：所有 3D 对象的共性——位置、旋转、缩放、命名

3. **多 Box 拼接**：用工程思维实现墙体留洞，无需 CSG
