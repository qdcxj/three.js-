# 坐标系与辅助工具

上一节我们搭好了三件套，浏览器显示一片浅蓝灰色——背景有了，但场景空空如也，根本看不出自己在 3D 世界的什么位置。本节我们要解决这个「迷失感」：先彻底搞懂 Three.js 的右手坐标系，然后用 `AxesHelper` 和 `GridHelper` 把坐标轴和网格画出来，让你清楚地看到「哪里是地面、哪里是上方、哪里是房子的前方」。

## 1. Three.js 的右手坐标系

Three.js 默认使用**右手坐标系**，三个坐标轴的方向遵循「右手定则」。判断方法是：伸出右手，让拇指、食指、中指两两垂直，则：

- **拇指**指向 `+X`（右）
- **食指**指向 `+Y`（上）
- **中指**指向 `+Z`（前，朝向观察者）

### 1.1 本项目的坐标约定

按照 `HOUSE_SPEC.md` 的规定，本项目所有构件都遵循以下坐标约定：

| 坐标轴 | 方向 | 含义 |
|--------|------|------|
| `+X` | 向右 | 房子的右侧（东侧） |
| `+Y` | 向上 | 天空方向 |
| `+Z` | 向前（朝向观察者） | 房子的大门朝向（南侧） |
| `-Z` | 向后 | 房子的后墙方向（北侧） |

**原点 `(0, 0, 0)` = 房子中心地面点**，所有构件的位置都相对原点计算。1 个单位 = 1 米（m），地面 `y = 0`。

```
              +Y (上)
              │
              │
       ╱──────┼──────╲  +Z (前，大门方向)
      ╱       │       ╲
     ╱        │        ╲
   +X ────────┼────────╲
   (右)       │
             地面 y=0
```

::: tip 为什么大门朝 +Z
这是项目约定的：相机默认放在 `(12, 8, 12)`，也就是右前上方，正好能看到大门。把大门朝 +Z 方向，相机第一眼就能看到正立面，符合「盖房子先看门脸」的直觉。
:::

### 1.2 右手坐标系 vs 左手坐标系

不同 3D 引擎使用的坐标系不同，初学时容易混淆：

| 引擎 | 坐标系 | +Z 方向 |
|------|--------|---------|
| Three.js / OpenGL | 右手系 | 朝向观察者（出屏幕） |
| Unity | 左手系 | 远离观察者（进屏幕） |
| DirectX | 左手系 | 远离观察者（进屏幕） |
| Blender | 右手系 | 朝向观察者（出屏幕），但 +Y 向上、+Z 向后 |

记住 Three.js 是**右手系、+Y 向上、+Z 出屏幕**就行。如果你之前用 Unity，要特别注意 Z 轴方向是相反的。

## 2. 世界坐标 vs 局部坐标

Three.js 中每个 3D 对象都有两套坐标系：

### 2.1 局部坐标（Local Space）

每个 `Object3D`（Mesh、Group、Light 等都继承自它）都有自己的**局部坐标系**，原点是对象自身的 `position`，朝向由自身的 `rotation` / `quaternion` 决定。

给一个 Mesh 设置 `mesh.position.set(2, 0, 3)`，是把它的**局部原点**放到父对象的 `(2, 0, 3)` 位置。如果父对象又发生了移动或旋转，子对象会跟着动。

### 2.2 世界坐标（World Space）

世界坐标是相对于 **Scene 根节点**的绝对位置。一个对象最终渲染时的位置，是它所有祖先的变换累加结果。

举个例子：

```js
const group = new THREE.Group();
group.position.set(10, 0, 0); // 父组放在 (10, 0, 0)

const mesh = new THREE.Mesh(geometry, material);
mesh.position.set(2, 0, 3); // 子 Mesh 在父组的 (2, 0, 3)
group.add(mesh);
scene.add(group);

// 此时 mesh 的：
//   局部坐标 position = (2, 0, 3)
//   世界坐标       = (12, 0, 3)  ← 父组位置 + 子位置
```

### 2.3 什么时候用哪套

| 场景 | 用哪套 |
|------|--------|
| 给单个 Mesh 设位置 | 局部坐标（`mesh.position.set`） |
| 检测两个物体是否碰撞 | 世界坐标（`getWorldPosition`） |
| 让物体绕自身轴旋转 | 局部（`mesh.rotation.x = ...`） |
| 让物体绕世界轴旋转 | 用 Group 包一层，旋转 Group |
| 射线拾取 / 鼠标点选 | 世界坐标 |

::: tip 本阶段的简化
stage-01 只有一块草地和一个空场景，所有物体直接 `add` 到 Scene 上，**局部坐标 = 世界坐标**。从 stage-03 开始我们会用 `Group` 把墙体、屋顶等构件分组管理，那时就会体会到两套坐标的差异。
:::

## 3. AxesHelper：三色坐标轴

光说不练假把式，我们把坐标轴直接画出来。Three.js 提供了 `AxesHelper`，它会在原点画三条彩色线段：

- **红色** = +X 轴
- **绿色** = +Y 轴
- **蓝色** = +Z 轴

```js
import * as THREE from "three";

// AxesHelper(size)：size 是每条轴的长度（单位 m）
// 传入 5 表示每条轴长 5m，足够看清
const axesHelper = new THREE.AxesHelper(5);
scene.add(axesHelper);
```

加入 `AxesHelper` 后，原点处会出现三条 5m 长的彩色线段，分别指向 +X、+Y、+Z 方向。这个工具在开发阶段极其有用——任何时候你不确定「这个位置到底在哪儿」，加一个 `AxesHelper` 就能立刻看清。

::: warning AxesHelper 的颜色含义
记住口诀 **「红 X、绿 Y、蓝 Z」**。注意绿色代表 Y 轴（向上），不要和「绿色草地」的颜色混淆。Three.js 内置的 AxesHelper 用的是 RGB ↔ XYZ 的对应关系，非常好记。
:::

## 4. GridHelper：地面网格

`GridHelper` 会在 `y = 0` 平面画一个方格网，每个格子是固定大小的正方形。它有两个核心作用：

1. **目测尺寸**：每格 1m，肉眼就能数出物体有多大多远
2. **确认地面**：网格所在的平面就是 `y = 0`，所有「贴地」的物体都应该在这个平面附近

```js
// GridHelper(size, divisions)
//   size:       网格总尺寸（这里是 40m × 40m，和草地一致）
//   divisions:  分格数（40 格，每格 1m）
const gridHelper = new THREE.GridHelper(40, 40);
scene.add(gridHelper);
```

加入 `GridHelper` 后，地面会出现一片灰色方格网，中心十字颜色稍深（标示 X/Z 轴位置）。配合 `AxesHelper` 一起看，你能立刻判断出：

- 原点在哪里（坐标轴交点）
- 哪边是 +X 哪边是 -X（红色轴方向）
- 哪边是 +Z 哪边是 -Z（蓝色轴方向）
- 任意位置距离原点多少米（数格子）

## 5. 把辅助工具加进 HouseScene.vue

在上一节的 `HouseScene.vue` 基础上，我们加入 `AxesHelper` 和 `GridHelper`。下面是 `initScene` 函数中新增的部分：

```js
function initScene() {
  // ... 之前的 Scene / Camera / Renderer 代码 ...

  // ─── 辅助工具 ─────────────────────────────────────────
  // AxesHelper(5)：三色坐标轴，红=X 绿=Y 蓝=Z，长度 5m
  const axesHelper = new THREE.AxesHelper(5);
  scene.add(axesHelper);

  // GridHelper(40, 40)：40m × 40m 网格，每 1m 一格，便于目测尺寸
  const gridHelper = new THREE.GridHelper(40, 40);
  scene.add(gridHelper);

  // ... 之后的渲染循环代码 ...
}
```

现在运行 `pnpm dev`，你会看到地面上铺满了灰色方格，原点处矗立着三色坐标轴——画面终于不再是空白了。可以试着在脑中标记几个位置：

- `(0, 0, 0)`：原点，未来房子中心地面点
- `(0, 5, 0)`：5m 高空，未来屋顶最高点
- `(4, 0, 3)`：右前角，未来前墙右端
- `(-4, 0, -3)`：左后角，未来后墙左端

## 6. 临时光照（让画面亮起来）

如果你照着做到这一步，可能会发现画面有点暗——虽然辅助工具能看见，但颜色不够鲜亮。这是因为 `MeshStandardMaterial`（PBR 材质）需要光照才能正确显示，而当前场景还没有任何光源。

本阶段我们加两个**临时灯光**，仅用于照亮辅助工具和后续的草地。正式的灯光方案（阳光 + 环境光 + 室内灯 + 壁灯）要等到 stage-06 才会接入：

```js
import * as THREE from "three";

// ─── 临时光照（正式灯光在 stage-06）─────────────────────
// 环境光：整体均匀照亮，避免阴影区域全黑
// AmbientLight(color, intensity)
const ambientLight = new THREE.AmbientLight(0xffffff, 0.6);
scene.add(ambientLight);

// 平行光：模拟太阳光，带方向性，让物体有明暗变化
// DirectionalLight(color, intensity)
const directionalLight = new THREE.DirectionalLight(0xffffff, 0.8);
// 平行光位置 (10, 15, 8)，照射方向默认指向原点
directionalLight.position.set(10, 15, 8);
scene.add(directionalLight);
```

- **环境光 `AmbientLight`**：所有方向均匀照亮，没有方向性，**不会产生阴影**。强度 0.6 保证背光面也能看见
- **平行光 `DirectionalLight`**：模拟无限远的光源（如太阳），所有光线平行，能产生阴影（stage-06 才开启 shadowMap）。位置 `(10, 15, 8)` 决定了光的方向——从右前上方照向原点

::: warning 本阶段不开启阴影
虽然 `DirectionalLight` 支持阴影，但开启阴影需要：renderer 启用 `shadowMap`、灯光启用 `castShadow`、物体启用 `castShadow/receiveShadow`、配置 `shadow.camera` 视锥……这一整套属于 stage-06 的内容。本阶段保持简单，只要画面够亮就行。
:::

## 7. 完整的辅助工具 + 灯光代码

把辅助工具和临时光照整合进 `HouseScene.vue`，关键部分如下（完整的 `initScene` 函数节选）：

```js
function initScene() {
  const container = containerRef.value;
  const width = container.clientWidth;
  const height = container.clientHeight;

  // 1. 场景
  scene = new THREE.Scene();
  scene.background = new THREE.Color(0xcfd8e3);

  // 2. 相机
  camera = new THREE.PerspectiveCamera(50, width / height, 0.1, 200);
  camera.position.set(12, 8, 12);
  camera.lookAt(0, 1, 0);

  // 3. 渲染器
  renderer = new THREE.WebGLRenderer({ antialias: true });
  renderer.setSize(width, height);
  renderer.setPixelRatio(Math.min(window.devicePixelRatio, 2));
  container.appendChild(renderer.domElement);

  // 4. 临时光照
  ambientLight = new THREE.AmbientLight(0xffffff, 0.6);
  scene.add(ambientLight);
  directionalLight = new THREE.DirectionalLight(0xffffff, 0.8);
  directionalLight.position.set(10, 15, 8);
  scene.add(directionalLight);

  // 5. 辅助工具
  axesHelper = new THREE.AxesHelper(5);
  scene.add(axesHelper);
  gridHelper = new THREE.GridHelper(40, 40);
  scene.add(gridHelper);

  // 6. 渲染循环
  const animate = () => {
    animationId = requestAnimationFrame(animate);
    renderer.render(scene, camera);
  };
  animate();

  // 7. resize 监听
  resizeHandler = () => {
    const w = container.clientWidth;
    const h = container.clientHeight;
    camera.aspect = w / h;
    camera.updateProjectionMatrix();
    renderer.setSize(w, h);
  };
  window.addEventListener("resize", resizeHandler);
}
```

运行后你会看到：浅蓝灰背景 + 灰色方格网 + 三色坐标轴——一个清晰的「施工场地坐标系」已经搭建好，下一步就可以铺草地了。

## 8. 关于 Helper 是否需要 dispose

`AxesHelper` 和 `GridHelper` 内部也用了 `BufferGeometry` 和 `LineBasicMaterial`，严格来说也应该 dispose。但 Helper 的几何数据量极小（就几条线段），即使不显式 dispose 也不会有明显内存泄漏。

本教程为了简洁，在 `disposeScene` 中只对 `Mesh` 的 geometry/material 显式 dispose，Helper 仅 `scene.remove()` 移除即可。如果你追求完美，可以这样 dispose：

```js
if (axesHelper) {
  scene.remove(axesHelper);
  axesHelper.geometry.dispose();
  axesHelper.material.dispose();
  axesHelper = null;
}
```

## 9. 用辅助工具目测位置

辅助工具不仅是「好看」，更是**调试的利器**。从下一节开始，我们要往场景里加草地、加地基、加墙体，每个构件放下去之前都应该先想清楚：

- 它的中心在 `(x, y, z)` 什么位置？
- 这个位置对应网格上的哪一格？
- 离原点多远？离地面多高？

养成「加物体先看坐标轴」的习惯，能帮你避免 90% 的「物体不知道放哪去了」的问题。这也是 `HOUSE_SPEC.md` 里把每个构件的坐标都写得清清楚楚的原因——**先有图纸，再盖房子**。
