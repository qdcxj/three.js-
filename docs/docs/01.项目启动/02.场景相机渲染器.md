# 场景、相机、渲染器

上一节我们搭好了 Vite 工程骨架，但浏览器还是一片漆黑——因为还没有写任何 Three.js 代码。本节我们就把 Three.js 的「三件套」搬进 `HouseScene.vue`：**Scene（场景）**、**Camera（相机）**、**Renderer（渲染器）**。这三件套是所有 Three.js 应用的核心骨架，理解了它们，你就理解了 3D 渲染的本质。

## 1. 三件套的分工

在写代码之前，先用一个生活类比理解三件套的关系：

- **Scene（场景）**：一个**虚拟的 3D 世界容器**。你往里面放房子、草地、灯光、相机——所有东西都挂在 Scene 上。可以把它想象成一块空地，等待你盖房子。
- **Camera（相机）**：**观察这个 3D 世界的眼睛**。它决定了「从哪个角度、用多大视野、看哪些范围」渲染场景。相机本身**不会出现在画面里**，它只是观察工具。
- **Renderer（渲染器）**：**把场景和相机合成成 2D 画面**的「画家」。它每帧都会把相机看到的 3D 场景，按照 WebGL 的方式投影到 `<canvas>` 上，形成你最终看到的 2D 图像。

三者协作的流程是：

```
Scene（场景，里面装满物体）
        │
        ↓
Camera（相机，决定观察角度）
        │
        ↓
Renderer（渲染器，把 3D 投影成 2D 画面）
        │
        ↓
   <canvas>（浏览器显示的画面）
```

::: tip 一个最常见的误解
很多人以为「相机是眼睛，所以相机会被渲染出来」。**不会**。相机只是观察工具，永远不会出现在画面里——就像你用手机拍照，手机本身不会出现在照片里一样。
:::

## 2. 在 Vue 组件里组织 Three.js 代码

Three.js 是命令式的（创建对象、调用方法），Vue 是声明式的（响应式数据驱动模板）。两者结合的关键是：**用 Vue 的生命周期来管理 Three.js 资源的创建和销毁**。

我们的 `HouseScene.vue` 采用如下结构：

```vue
<script setup>
import { onMounted, onUnmounted, ref } from "vue";
import * as THREE from "three";

// 用普通变量持有 Three.js 资源（不用 ref，避免响应式开销）
let scene = null;
let camera = null;
let renderer = null;
let animationId = null;

const containerRef = ref(null); // DOM 容器引用

function initScene() {
  // 在这里创建 Scene / Camera / Renderer
}

function disposeScene() {
  // 在这里销毁所有资源
}

onMounted(() => initScene());
onUnmounted(() => disposeScene());
</script>

<template>
  <div ref="containerRef" class="scene-container"></div>
</template>
```

::: warning 为什么 Three.js 资源不用 ref / reactive
Three.js 的对象（Scene、Camera、Mesh 等）内部结构非常复杂，如果用 Vue 的 `reactive` 包裹，会被递归代理成深度响应式对象，**严重影响性能**，甚至可能导致 WebGL 状态混乱。正确做法是用普通 `let` 变量持有，仅用 `ref` 管理 DOM 容器引用和少量 UI 状态。
:::

## 3. 创建 Scene

Scene 是 3D 世界的容器，创建非常简单：

```js
import * as THREE from "three";

// Scene 是所有 3D 物体、灯光、辅助工具的容器
scene = new THREE.Scene();
// 设置背景色为天空蓝灰，方便和草地形成对比
scene.background = new THREE.Color(0xcfd8e3);
```

`scene.background` 可以设置为 `Color`（纯色）、`Texture`（贴图）、`CubeTexture`（立方体天空盒）等。本阶段用纯色就够了，stage-05 会替换为天空盒贴图。

## 4. 创建 PerspectiveCamera

相机有几种类型，本教程用的是**透视相机** `PerspectiveCamera`，它模拟人眼的透视效果——远处的物体看起来更小，近处的物体看起来更大，最符合日常视觉直觉。

```js
// PerspectiveCamera(fov, aspect, near, far)
//   fov:    视野角度（Field of View），单位是度
//   aspect: 宽高比 = 渲染区域宽度 / 高度
//   near:   近裁剪面，比这个距离还近的物体不会被渲染
//   far:    远裁剪面，比这个距离还远的物体不会被渲染
camera = new THREE.PerspectiveCamera(50, width / height, 0.1, 200);
// 初始位置 (12, 8, 12)：从右前上方俯瞰施工场地
camera.position.set(12, 8, 12);
// 看向 (0, 1, 0)：原点稍上方（未来房子中心）
camera.lookAt(0, 1, 0);
```

### 4.1 四个参数的取舍

| 参数 | 本阶段取值 | 取值理由 |
|------|-----------|----------|
| `fov` | 50° | 接近人眼舒适视野（45°~60°），既不畸变也不局促 |
| `aspect` | width / height | 必须随容器宽高比变化，否则画面会拉伸 |
| `near` | 0.1 | 房子细节最小 0.05m，near 设 0.1 即可看清 |
| `far` | 200 | 场地 40m，far 给 200 留足余量，避免远处被裁掉 |

::: warning near / far 不要乱设
`near` 太小会导致**深度精度冲突**（Z-fighting，远处物体表面出现闪烁条纹）；`far` 太大会导致**深度缓冲精度下降**。一般 near/far 比值不要超过 1:1000。本教程 0.1 / 200 = 1:2000，已经接近上限，但因为场景不大，实测没有问题。
:::

### 4.2 相机位置与朝向

`camera.position.set(12, 8, 12)` 把相机放在 `(12, 8, 12)`——这是右手坐标系下一个「右前上方」的位置，距离原点约 `√(144+64+144) ≈ 19m`。这个位置能让我们俯瞰整个施工场地，同时看到坐标轴的三个方向。

`camera.lookAt(0, 1, 0)` 让相机**看向** `(0, 1, 0)`——也就是原点上方 1m 处（未来房子中心地面附近）。注意 `lookAt` 会重置相机的 `rotation`，所以不要在 `lookAt` 之后再手动设 `rotation`。

## 5. 创建 WebGLRenderer

渲染器负责把 3D 场景投影到 `<canvas>` 上：

```js
// WebGLRenderer({ antialias: true })：开启抗锯齿，边缘更平滑
renderer = new THREE.WebGLRenderer({ antialias: true });
// 设置渲染尺寸 = 容器尺寸
renderer.setSize(width, height);
// 限制像素比上限为 2，避免高分屏过度渲染拖慢性能
renderer.setPixelRatio(Math.min(window.devicePixelRatio, 2));
// 把 renderer 生成的 <canvas> 挂到容器里
container.appendChild(renderer.domElement);
```

### 5.1 antialias 抗锯齿

`antialias: true` 开启 MSAA 多重采样抗锯齿，让物体边缘更平滑。代价是稍微消耗一点 GPU 性能，但对画面质感的提升非常明显，建议默认开启。

### 5.2 setPixelRatio 像素比

`window.devicePixelRatio` 是设备的物理像素比（CSS 像素 vs 物理像素）。在 Retina 屏幕（dpr=2 或 3）上，如果不用 `setPixelRatio`，画面会模糊；但如果直接 `setPixelRatio(dpr)`，在 dpr=3 的手机上会渲染 9 倍像素，性能爆炸。

折中方案是 `Math.min(devicePixelRatio, 2)`——2 倍像素已经足够清晰，又能避免极端高分屏的性能问题。

### 5.3 domElement

`renderer.domElement` 就是 renderer 内部创建的 `<canvas>`。必须把它 `appendChild` 到页面的某个容器里，否则画面不会显示。这一步很容易被初学者漏掉，导致「代码没报错但画面空白」。

## 6. 渲染循环

3D 场景不是「画一次就完」，而是**每秒画 60 次**（60fps），这样才能看到动画、交互、相机移动。实现方式是 `requestAnimationFrame`：

```js
const animate = () => {
  // 请求下一帧再次调用 animate，形成循环
  animationId = requestAnimationFrame(animate);
  // 每帧重新渲染场景（从相机视角）
  renderer.render(scene, camera);
};
animate(); // 启动循环
```

`requestAnimationFrame` 是浏览器原生的 API，它会在「下次重绘之前」调用回调函数，频率通常与显示器刷新率一致（60Hz / 120Hz / 144Hz）。它的优点是：

- **自动节流**：标签页隐藏时自动暂停，省电
- **与显示器同步**：不会出现撕裂感
- **比 setInterval 更平滑**：精度更高

::: tip 为什么要每帧渲染
即使场景里没有任何物体在动，OrbitControls 的阻尼动画、未来的开门动画、粒子效果等都需要每帧更新。养成「只要渲染 3D 就写循环」的习惯，后续加动画时不用改架构。
:::

## 7. 完整的 HouseScene.vue 骨架

把上面的代码拼起来，就是 `HouseScene.vue` 的核心骨架（本节还**没加**草地和 OrbitControls，那是后续两节的内容）：

```vue
<script setup>
import { onMounted, onUnmounted, ref } from "vue";
import * as THREE from "three";

const containerRef = ref(null);

let scene = null;
let camera = null;
let renderer = null;
let animationId = null;

function initScene() {
  const container = containerRef.value;
  const width = container.clientWidth;
  const height = container.clientHeight;

  // 1. 场景
  scene = new THREE.Scene();
  scene.background = new THREE.Color(0xcfd8e3);

  // 2. 透视相机
  camera = new THREE.PerspectiveCamera(50, width / height, 0.1, 200);
  camera.position.set(12, 8, 12);
  camera.lookAt(0, 1, 0);

  // 3. 渲染器
  renderer = new THREE.WebGLRenderer({ antialias: true });
  renderer.setSize(width, height);
  renderer.setPixelRatio(Math.min(window.devicePixelRatio, 2));
  container.appendChild(renderer.domElement);

  // 4. 渲染循环
  const animate = () => {
    animationId = requestAnimationFrame(animate);
    renderer.render(scene, camera);
  };
  animate();
}

function disposeScene() {
  if (animationId !== null) {
    cancelAnimationFrame(animationId);
    animationId = null;
  }
  if (renderer) {
    renderer.dispose();
    if (renderer.domElement.parentNode) {
      renderer.domElement.parentNode.removeChild(renderer.domElement);
    }
    renderer = null;
  }
  scene = null;
  camera = null;
}

onMounted(() => initScene());
onUnmounted(() => disposeScene());
</script>

<template>
  <div ref="containerRef" class="scene-container"></div>
</template>

<style scoped>
.scene-container {
  width: 100vw;
  height: 100vh;
  overflow: hidden;
  background: #1f1f1f;
}
</style>
```

把这个组件保存到 `src/components/HouseScene.vue`，运行 `pnpm dev`，你会看到浏览器显示一片**浅蓝灰色**——这就是 `scene.background` 的颜色。虽然场景里还什么都没有，但三件套已经跑起来了，后续所有内容都是往这个骨架里加东西。

## 8. 自适应窗口大小

如果你现在拖动浏览器窗口大小，会发现画面没有跟着变化——`renderer` 的尺寸是在 `initScene` 里设的，不会自动更新。我们需要监听 `resize` 事件，同步更新相机和渲染器：

```js
let resizeHandler = null;

function initScene() {
  // ... 前面的代码 ...

  resizeHandler = () => {
    const w = container.clientWidth;
    const h = container.clientHeight;
    // 1. 更新相机宽高比
    camera.aspect = w / h;
    // 2. 通知相机重新计算投影矩阵
    camera.updateProjectionMatrix();
    // 3. 更新渲染器尺寸
    renderer.setSize(w, h);
  };
  window.addEventListener("resize", resizeHandler);
}

function disposeScene() {
  // 别忘了卸载监听
  if (resizeHandler) {
    window.removeEventListener("resize", resizeHandler);
    resizeHandler = null;
  }
  // ... 其他销毁逻辑 ...
}
```

::: warning 为什么要 updateProjectionMatrix
`PerspectiveCamera` 内部维护一个**投影矩阵**（把 3D 坐标投影到 2D 屏幕的矩阵），它由 `fov / aspect / near / far` 计算得出。直接修改 `camera.aspect` 不会立即重算矩阵，必须调用 `updateProjectionMatrix()` 才会生效。这是初学者最常踩的坑之一。
:::

## 9. dispose 资源销毁

在单页应用里，组件会反复挂载/卸载，每次卸载都要**彻底释放 Three.js 资源**，否则会内存泄漏，浏览器越来越卡。本阶段的销毁逻辑相对简单：

```js
function disposeScene() {
  // 1. 停止渲染循环
  if (animationId !== null) {
    cancelAnimationFrame(animationId);
    animationId = null;
  }

  // 2. 移除 resize 监听
  if (resizeHandler) {
    window.removeEventListener("resize", resizeHandler);
    resizeHandler = null;
  }

  // 3. dispose 渲染器并移除 canvas
  if (renderer) {
    renderer.dispose();
    if (renderer.domElement.parentNode) {
      renderer.domElement.parentNode.removeChild(renderer.domElement);
    }
    renderer = null;
  }

  // 4. 清空场景与相机引用
  scene = null;
  camera = null;
}
```

后续阶段加入 Mesh、Geometry、Material、Controls 后，dispose 逻辑会更复杂，但核心套路不变：**先停循环、再移除事件、然后逐一 dispose、最后清空引用**。

## 本节总结

本节我们完成了 Three.js 三件套的搭建：

- 理解了 **Scene（容器）/ Camera（眼睛）/ Renderer（画家）** 三者的分工与协作流程
- 学会了在 Vue 组件里用 `onMounted` / `onUnmounted` 管理 Three.js 资源的生命周期
- 创建了 `PerspectiveCamera(50, aspect, 0.1, 200)`，位置 `(12, 8, 12)` 看向 `(0, 1, 0)`
- 创建了 `WebGLRenderer({ antialias: true })`，并用 `setPixelRatio(Math.min(dpr, 2))` 限制像素比
- 写出了 `requestAnimationFrame` 渲染循环，并加入了 `resize` 自适应和 `dispose` 资源销毁
