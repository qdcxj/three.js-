# 创建 Three.js 工程

我们要盖一栋欧式乡村小屋，第一步不是搬砖，而是**平整施工场地、搭好脚手架**。映射到 Three.js 项目里，这一步就是：用 Vite 初始化一个 Vue 3 工程，安装 three 依赖，建立清晰的目录结构。本节我们会从零开始搭出整个 `stage-01-项目启动` 工程的骨架，后续所有阶段都会在这个骨架上递增。

## 1. 为什么选择 Vite + Vue 3 + Three.js

在动手之前，先讲清楚技术选型的理由，避免「跟着抄却不知道为什么」。

### 1.1 Vite：现代前端构建工具

Vite 是 Vue 作者尤雨溪开发的构建工具，相比传统的 Webpack，它的优势在于：

- **冷启动极快**：基于浏览器原生 ES Module，开发服务器无需打包，毫秒级启动
- **HMR 热更新**：修改代码后浏览器瞬时更新，不用刷新页面，调试 3D 场景时尤其爽
- **配置简单**：开箱即用，`pnpm create vite` 一条命令就能搭好工程
- **生产构建可靠**：基于 Rollup 打包，产物体积小、Tree-shaking 友好

对于 Three.js 这种「频繁改一行代码就要看效果」的场景，Vite 的 HMR 简直是刚需。

### 1.2 Vue 3：组合式 API 的优雅

本教程使用 Vue 3.5 的 `<script setup>` 组合式 API，理由是：

- **生命周期清晰**：`onMounted` 初始化 Three.js、`onUnmounted` 销毁资源，与 Three.js 资源管理天然契合
- **响应式可选**：3D 场景内部状态用普通变量管理（避免响应式开销），UI 控件用 `ref` / `reactive`
- **单文件组件**：template + script + style 集中在一个 `.vue` 文件，便于教学

### 1.3 Three.js 0.169：稳定主流版本

本教程锁定 `three@^0.169.0`，这是一个稳定且文档丰富的版本。锁定版本号是为了保证教程代码「复制粘贴就能跑」，避免新版本 API 变动导致示例失效。

::: tip 为什么不用 React Three Fiber
React Three Fiber（R3F）确实是优秀的 React 封装方案，但它的抽象层会**屏蔽 Three.js 原生 API 的学习**。本教程的目的是让你真正掌握 Three.js 本身，所以坚持使用原生 `import * as THREE from "three"` 的写法，把 Three.js 的每一行代码都暴露给你看。学完之后再迁移到 R3F 会非常轻松。
:::

## 2. 用 pnpm 创建 Vite + Vue 3 工程

确保你的电脑已经装好 Node.js（建议 18+）和 pnpm。打开终端，执行以下命令：

```bash
# 在 lession 目录下创建项目
pnpm create vite stage-01-项目启动 --template vue

# 进入项目目录
cd stage-01-项目启动
```

`pnpm create vite` 会拉取 Vite 的脚手架模板，`--template vue` 表示使用 Vue 3 模板。执行后会生成如下初始结构：

```
stage-01-项目启动/
├── index.html
├── package.json
├── vite.config.js
├── public/
│   └── vite.svg
└── src/
    ├── main.js
    ├── App.vue
    ├── style.css
    └── components/
        └── HelloWorld.vue
```

我们可以删掉模板自带的 `style.css`、`HelloWorld.vue`、`public/vite.svg`，这些用不上。

## 3. 安装 Three.js 依赖

在项目根目录执行：

```bash
# 安装 three 作为运行时依赖
pnpm add three@^0.169.0
```

安装完成后，`package.json` 会多出一条依赖：

```json
{
  "dependencies": {
    "three": "^0.169.0",
    "vue": "^3.5.40"
  }
}
```

::: warning 关于 three 的类型声明
`three` 包自带 `build/three.module.js`，是纯 JS 文件，没有 TypeScript 类型声明。如果你用 VS Code 且需要类型提示，可以额外装 `@types/three`：

```bash
pnpm add -D @types/three
```

本教程以 JavaScript 为主，不强制要求类型声明，装不装都能跑。
:::

## 4. 完整的 package.json

本阶段最终的 `package.json` 如下，你也可以直接复制这个文件覆盖模板自带的版本：

```json
{
  "name": "stage-01-项目启动",
  "private": true,
  "version": "0.0.0",
  "type": "module",
  "scripts": {
    "dev": "vite",
    "build": "vite build",
    "preview": "vite preview"
  },
  "dependencies": {
    "three": "^0.169.0",
    "vue": "^3.5.40"
  },
  "devDependencies": {
    "@vitejs/plugin-vue": "^5.1.0",
    "vite": "^5.4.0"
  }
}
```

几个关键字段的含义：

- `"private": true`：私有项目，防止误发布到 npm
- `"type": "module"`：整个项目使用 ES Module（`import/export`），这是 Vite 的硬性要求
- `"scripts"`：定义 `pnpm dev` / `pnpm build` / `pnpm preview` 三个命令
- `@vitejs/plugin-vue`：让 Vite 能编译 `.vue` 单文件组件

## 5. vite.config.js 配置

Vite 的配置非常简洁，只需要启用 Vue 插件即可：

```js
import { defineConfig } from "vite";
import vue from "@vitejs/plugin-vue";

// Vite 配置：启用 Vue 3 单文件组件支持
export default defineConfig({
  plugins: [vue()],
});
```

后续如果要做路径别名（`@/` 指向 `src/`）、代理、分包等高级配置，都在这个文件里加。本阶段保持最简，不过度配置。

## 6. index.html 入口

Vite 的入口是项目根目录的 `index.html`，而不是 `main.js`。这是 Vite 与传统打包工具最大的不同——HTML 是入口，脚本通过 `<script type="module">` 引入：

```html
<!DOCTYPE html>
<html lang="zh-CN">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>阶段01·项目启动</title>
  </head>
  <body>
    <div id="app"></div>
    <script type="module" src="/src/main.js"></script>
  </body>
</html>
```

`<div id="app">` 是 Vue 挂载点，`/src/main.js` 是 JS 入口。注意 `type="module"` 不能省，它告诉浏览器这是一段 ES Module。

## 7. src/main.js 入口

`main.js` 的职责只有一个：创建 Vue 应用并挂载到 `#app`：

```js
import { createApp } from "vue";
import App from "./App.vue";

// 创建并挂载 Vue 应用
createApp(App).mount("#app");
```

后续如果要加 Vue Router、Pinia、Element Plus 等插件，都在这里 `app.use()` 注册。本阶段不需要任何插件。

## 8. src/App.vue 根组件

`App.vue` 只做一件事：引入并使用 `HouseScene` 组件，并设置全局全屏样式：

```vue
<script setup>
// 引入核心 3D 场景组件
import HouseScene from "./components/HouseScene.vue";
</script>

<template>
  <HouseScene />
</template>

<style>
/* 全局样式：清除默认边距，让 3D 画布占满整个视口 */
* {
  margin: 0;
  padding: 0;
  box-sizing: border-box;
}

html,
body,
#app {
  width: 100%;
  height: 100%;
  overflow: hidden;
  background: #1f1f1f;
  font-family: "Helvetica Neue", Helvetica, "PingFang SC", "Microsoft YaHei",
    sans-serif;
}
</style>
```

::: tip 为什么 `overflow: hidden`
3D 画布需要占满整个视口，如果允许滚动条出现，会出现画面错位、鼠标坐标偏移等问题。所以全局设 `overflow: hidden`，禁止滚动。
:::

## 9. 最终项目结构

完成本节后，你的项目结构应该是这样的（删掉了模板自带的无用文件）：

```
stage-01-项目启动/
├── index.html                      # Vite 入口 HTML
├── package.json                    # 依赖与脚本
├── vite.config.js                  # Vite 配置
├── README.md                       # 项目说明
└── src/
    ├── main.js                     # Vue 应用入口
    ├── App.vue                     # 根组件（全屏样式）
    └── components/
        └── HouseScene.vue          # 核心 3D 场景组件（下节开始编写）
```

注意 `HouseScene.vue` 这一刻还是空的，下一节我们会把 Scene / Camera / Renderer 三件套写进去，让浏览器第一次显示出 3D 画面。

## 10. 启动工程验证

到这里工程骨架就搭好了，先验证一下能不能跑起来：

```bash
pnpm install
pnpm dev
```

终端会输出类似这样的信息：

```
  VITE v5.4.x  ready in 320 ms

  ➜  Local:   http://localhost:5173/
  ➜  Network: use --host to expose
```

打开 `http://localhost:5173/`，你会看到一个深灰色的空白页面（因为 `HouseScene.vue` 还是空的）。这表示工程已经成功运行，下一步就可以开始写 3D 代码了。

::: warning 端口被占用怎么办
如果 5173 端口被占用，Vite 会自动切到 5174、5175……查看终端输出的实际端口即可。也可以用 `pnpm dev --port 3000` 指定端口。
:::
