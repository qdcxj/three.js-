# 整合所有模块

前面 13 个阶段，我们分别建造了地基、墙体、屋顶、门窗、灯光、相机、动画、家具、着色器、后期处理、粒子和性能优化。这些模块各自独立时都能正常工作，但**把它们拼在一起**时会遇到一系列冲突和兼容性问题。本节就是解决这些「整合摩擦」的实战指南。

## 1. 整合的核心挑战

整合不是简单的「代码拼接」，而是要解决三类问题：

| 问题类型 | 典型案例 | 解决思路 |
|----------|----------|----------|
| **初始化顺序冲突** | 着色器材质在构件之后创建，导致引用 null | 按依赖关系排定 onMounted 调用顺序 |
| **渲染管线冲突** | ShaderMaterial 与 EffectComposer 不兼容 | 统一用 onBeforeCompile 或确保 shader 输出线性色彩 |
| **资源管理冲突** | 多模块共享同一 geometry/material，dispose 重复 | track 模式 + Group traverse 统一释放 |

::: warning 整合 ≠ 拼接
最简单的整合方式是把 stage-01 到 stage-13 的代码按顺序粘贴到一个文件里。但这几乎一定会报错——变量重名、初始化顺序错乱、dispose 遗漏、shader 冲突……整合的本质是**重新设计代码组织**，让各模块在一个统一的架构下协调工作。
:::

## 2. 初始化顺序冲突

### 问题：着色器材质的创建时机

stage-10 创建了玻璃反射着色器（`glassMaterial`）和草叶波动着色器（`grassMaterial`）。stage-03 的 `createWindows` 需要引用 `glassMaterial`，stage-01 的 `createGround` 需要引用 `grassMaterial`。如果着色器在构件之后创建，就会得到 `null` 引用错误。

### 解决：着色器提前创建

在 `onMounted` 中，`createShaders` 必须在 `createGround` 和 `createWindows` 之前调用：

```js
onMounted(() => {
  createScene();
  createCamera();
  createRenderer();
  clock = new THREE.Clock();

  // ★ 着色器必须在构件之前创建
  createShaders();

  createLights();
  createShadows();

  // ★ 以下构件引用 createShaders 创建的材质
  createGround();        // 引用 grassMaterial
  createFoundation();
  // ...
  createWindows(houseGroup);  // 引用 glassMaterial
  // ...
});
```

### 问题：灯光与阴影的先后

stage-06 的 `createLights` 创建阳光，stage-06 的阴影配置需要引用 `sunLight`。如果阴影配置在灯光之前，`sunLight` 为 null。

### 解决：createShadows 在 createLights 之后

```js
const createShadows = () => {
  renderer.shadowMap.enabled = true;
  renderer.shadowMap.type = THREE.PCFSoftShadowMap;

  // ★ 此时 sunLight 已由 createLights 创建
  if (sunLight) {
    sunLight.castShadow = true;
    sunLight.shadow.mapSize.set(2048, 2048);
    sunLight.shadow.camera.near = 0.5;
    sunLight.shadow.camera.far = 60;
    sunLight.shadow.camera.left = -15;
    sunLight.shadow.camera.right = 15;
    sunLight.shadow.camera.top = 15;
    sunLight.shadow.camera.bottom = -15;
    sunLight.shadow.bias = -0.0005;
  }

  if (indoorLamp) {
    indoorLamp.castShadow = true;
    indoorLamp.shadow.mapSize.set(512, 512);
  }
};
```

::: tip 为什么 createShadows 是独立函数
把阴影配置从灯光创建中分离出来，有两个好处：一是职责清晰（`createLights` 只管创建灯，`createShadows` 只管配阴影），二是方便调参（调试阴影时只需关注一个函数）。
:::

## 3. 渲染管线冲突

### 问题：ShaderMaterial 与 EffectComposer

stage-10 使用了自定义 `ShaderMaterial`（玻璃 Fresnel 反射），stage-11 引入了 `EffectComposer`（Bloom 辉光）。两者的兼容性需要特别注意：

**冲突点 1：色彩空间。** EffectComposer 的 RenderPass 在线性空间渲染，OutputPass 负责最终的 sRGB 转换。如果 ShaderMaterial 直接输出 sRGB 颜色，经过 OutputPass 后会**二次转换**，导致颜色偏暗或偏亮。

**冲突点 2：透明度排序。** Bloom 需要提取画面中的高亮区域。如果玻璃 ShaderMaterial 的透明度设置不当，可能被 Bloom 误判为高亮源，产生不自然的辉光。

### 解决方案

**方案 A：着色器输出线性色彩。** 确保自定义 ShaderMaterial 的 fragmentShader 输出线性空间颜色，让 OutputPass 统一处理 sRGB 转换。stage-14 的玻璃着色器直接输出线性颜色值，不手动做 sRGB 转换：

```glsl
// fragmentShader —— 输出线性颜色，不做 gamma 校正
uniform vec3 uBaseColor;
uniform vec3 uReflectionColor;
varying vec3 vNormal;
varying vec3 vViewDir;
void main() {
  float fresnel = pow(1.0 - abs(dot(vNormal, vViewDir)), 3.0);
  vec3 color = mix(uBaseColor, uReflectionColor, fresnel);
  float alpha = 0.35 + fresnel * 0.4;
  gl_FragColor = vec4(color, alpha);
}
```

**方案 B：调高 Bloom 阈值。** 将 `UnrealBloomPass` 的 threshold 设为 0.85，只有真正高亮区域（如灯光、高光反射）才触发辉光，避免天空和玻璃误触：

```js
bloomPass = new UnrealBloomPass(
  new THREE.Vector2(window.innerWidth, window.innerHeight),
  0.35,  // strength：辉光强度
  0.4,   // radius：扩散半径
  0.85   // threshold：亮度阈值
);
```

**方案 C：onBeforeCompile 替代裸 ShaderMaterial。** 对于需要光照和阴影的材质（如草叶），用 `onBeforeCompile` 注入自定义代码到 `MeshStandardMaterial`，而不是用裸 `ShaderMaterial`。这样自动继承 PBR 光照管线，与 EffectComposer 完全兼容：

```js
grassMaterial = new THREE.MeshStandardMaterial({
  color: 0x4a9c2f,
  side: THREE.DoubleSide,
  roughness: 0.9,
});
grassMaterial.onBeforeCompile = (shader) => {
  shader.uniforms.uTime = { value: 0 };
  shader.vertexShader = shader.vertexShader
    .replace("#include <common>", "#include <common>\nuniform float uTime;")
    .replace("#include <begin_vertex>", `
      vec3 transformed = position;
      float heightFactor = clamp(position.y, 0.0, 1.0);
      float wave = sin(position.x * 5.0 + uTime * 2.0) * 0.08 * heightFactor;
      float wave2 = cos(position.z * 5.0 + uTime * 1.5) * 0.05 * heightFactor;
      transformed.x += wave;
      transformed.z += wave2;
    `);
  grassShaderRef = shader;
};
```

::: warning onBeforeCompile 的 uniform 更新
`onBeforeCompile` 注入的 uniform 不会自动绑定到 material 上。需要在回调中保存 shader 引用，每帧手动更新：

```js
// 每帧更新
if (grassShaderRef) grassShaderRef.uniforms.uTime.value += dt;
```

这是最容易被忽略的坑——着色器代码注入了，但 uniform 没更新，草叶不会动。
:::

## 4. 双控制器冲突

### 问题：OrbitControls 与 PointerLockControls 抢占输入

stage-07 引入了 OrbitControls（鸟瞰）和 PointerLockControls（第一人称）。两者都监听 `renderer.domElement` 的鼠标事件，如果同时启用，会互相干扰——OrbitControls 拖拽时 PointerLockControls 也在响应鼠标移动。

### 解决：互斥启用

通过 `controlMode` 状态变量控制当前活跃的控制器，切换时启用/禁用：

```js
let controlMode = "bird"; // 'bird' | 'fps'

const switchToBirdMode = () => {
  controlMode = "bird";
  orbitControls.enabled = true;          // ★ 启用鸟瞰
  if (pointerLockControls.isLocked) pointerLockControls.unlock();  // ★ 退出锁定
  camera.position.set(12, 8, 12);
  orbitControls.target.set(0, 1.5, 0);
  orbitControls.update();
  ui.controlMode = "鸟瞰";
};

const switchToFpsMode = () => {
  controlMode = "fps";
  orbitControls.enabled = false;         // ★ 禁用鸟瞰
  camera.position.set(0, 1.6, 5);        // 相机移到门口
  pointerLockControls.lock();            // ★ 请求指针锁定
  ui.controlMode = "第一人称";
};
```

渲染循环中按模式更新：

```js
const animate = () => {
  animationId = requestAnimationFrame(animate);
  const dt = clock.getDelta();

  // ★ 只有鸟瞰模式才更新 OrbitControls（第一人称由 PointerLockControls 直接操控相机）
  if (controlMode === "bird") orbitControls.update();

  updateDoor(dt);
  updateLamp(dt);
  updateDayNight(dt);
  updateParticles(dt);
  updateMovement(dt);  // WASD 仅在第一人称生效

  composer.render();
};
```

::: tip PointerLockControls 的 unlock 事件
用户按 Esc 会自动退出指针锁定，触发 `unlock` 事件。监听这个事件可以自动切回鸟瞰模式：

```js
pointerLockControls.addEventListener("unlock", () => {
  if (controlMode === "fps") switchToBirdMode();
});
```

这样用户按 Esc 就能无缝回到鸟瞰，不需要再按 G。
:::

## 5. 昼夜循环与多系统联动

### 问题：昼夜循环影响多个系统

stage-08 的昼夜循环不仅改变阳光颜色和强度，还需要联动：
- 天空盒着色器的 `uTopColor` / `uBottomColor`
- 场景背景色 `scene.background`
- 雾色 `scene.fog.color`
- 玻璃着色器的 `uReflectionColor`（反射天空色）

### 解决：统一的 updateDayNight 函数

在一个函数中集中更新所有受昼夜影响的系统：

```js
const updateDayNight = (dt) => {
  cycleTime = (cycleTime + dt) % DAY_PERIOD;
  const t = cycleTime / DAY_PERIOD;
  const dayFactor = (Math.cos(t * Math.PI * 2) + 1) / 2;  // 0=夜, 1=昼

  // 阳光颜色与强度
  _tmpSunColor.copy(NIGHT_SUN_COLOR).lerp(DAY_SUN_COLOR, dayFactor);
  sunLight.color.copy(_tmpSunColor);
  sunLight.intensity = NIGHT_SUN_INTENSITY +
    (DAY_SUN_INTENSITY - NIGHT_SUN_INTENSITY) * dayFactor;

  // 环境光
  ambientLight.intensity = NIGHT_AMBIENT +
    (DAY_AMBIENT - NIGHT_AMBIENT) * dayFactor;

  // 天空（背景 + 着色器球 + 雾）
  _tmpSkyTop.copy(NIGHT_SKY_TOP).lerp(DAY_SKY_TOP, dayFactor);
  _tmpSkyBottom.copy(NIGHT_SKY_BOTTOM).lerp(DAY_SKY_BOTTOM, dayFactor);
  scene.background.copy(_tmpSkyBottom);
  if (skyMaterial) {
    skyMaterial.uniforms.uTopColor.value.copy(_tmpSkyTop);
    skyMaterial.uniforms.uBottomColor.value.copy(_tmpSkyBottom);
  }
  if (scene.fog) scene.fog.color.copy(_tmpSkyBottom);

  // 阳光位置划弧
  const angle = t * Math.PI * 2;
  sunLight.position.set(
    Math.cos(angle) * 12,
    Math.sin(angle) * 12 + 2,
    8
  );

  // 玻璃反射色跟随天空
  if (glassMaterial) {
    glassMaterial.uniforms.uReflectionColor.value.copy(_tmpSkyTop);
  }

  // UI 时段
  if (dayFactor > 0.75) ui.phase = "白天";
  else if (dayFactor > 0.4) ui.phase = "黄昏/黎明";
  else ui.phase = "夜晚";
};
```

::: tip 临时对象复用
注意 `_tmpSunColor` / `_tmpSkyTop` / `_tmpSkyBottom` 是模块顶部的复用对象，不是每帧 `new THREE.Color()`。这是 stage-13 学过的 GC 优化——避免每帧创建临时对象导致垃圾回收卡顿。
:::

## 6. dispose 的完整性

### 问题：整合后 dispose 更复杂

整合后的场景有更多类型的资源需要释放：
- 基础 Mesh（track 收集）
- doorGroup 子级（需要 traverse）
- LOD 子级（levels 数组中的高/低细节模型）
- 着色器材质（glassMaterial / grassMaterial / skyMaterial）
- 粒子系统（smokeGeometry / smokeMaterial）
- 后期处理（composer）
- 控制器（orbitControls / pointerLockControls）

### 解决：分区域 dispose

```js
const disposeScene = () => {
  // 1. 停止循环 + 移除事件
  if (animationId) cancelAnimationFrame(animationId);
  window.removeEventListener("resize", handleResize);
  window.removeEventListener("keydown", onKeyDown);
  window.removeEventListener("keyup", onKeyUp);

  // 2. doorGroup 子级（门板 geometry/material）
  if (doorGroup) {
    doorGroup.traverse((obj) => {
      if (obj.geometry) obj.geometry.dispose();
      if (obj.material) {
        if (Array.isArray(obj.material))
          obj.material.forEach((m) => { if (m.map) m.map.dispose(); m.dispose(); });
        else { if (obj.material.map) obj.material.map.dispose(); obj.material.dispose(); }
      }
    });
    if (doorGroup.parent) doorGroup.parent.remove(doorGroup);
    doorGroup = null;
  }

  // 3. disposables（含 LOD 子级处理）
  disposables.forEach((obj) => {
    if (obj.geometry) obj.geometry.dispose();
    if (obj.material) { /* ... 批量释放 ... */ }
    // LOD 的多层级子对象
    if (obj.isLOD) {
      for (let i = 0; i < obj.levels.length; i++) {
        const level = obj.levels[i];
        if (level && level.object) {
          level.object.traverse((child) => {
            if (child.geometry) child.geometry.dispose();
            if (child.material) child.material.dispose();
          });
        }
      }
    }
    if (obj.parent) obj.parent.remove(obj);
  });
  disposables.length = 0;

  // 4. 粒子
  if (smokeGeometry) { smokeGeometry.dispose(); smokeGeometry = null; }
  if (smokeMaterial) { smokeMaterial.dispose(); smokeMaterial = null; }

  // 5. 着色器材质
  if (glassMaterial) { glassMaterial.dispose(); glassMaterial = null; }
  if (grassMaterial) { grassMaterial.dispose(); grassMaterial = null; }
  if (skyMaterial) { skyMaterial.dispose(); skyMaterial = null; }

  // 6. 后期处理
  if (composer) { composer.dispose(); composer = null; }

  // 7. 控制器
  if (orbitControls) { orbitControls.dispose(); orbitControls = null; }
  if (pointerLockControls) {
    if (pointerLockControls.isLocked) pointerLockControls.unlock();
    pointerLockControls = null;
  }

  // 8. 渲染器
  if (renderer) {
    renderer.dispose();
    renderer.forceContextLoss?.();
    renderer = null;
  }

  // 9. 清空引用
  scene = null;
  camera = null;
  clock = null;
};
```

::: warning dispose 的顺序很重要
1. 先停渲染循环（`cancelAnimationFrame`），否则 dispose 过程中渲染循环还在跑，会访问已释放的资源导致崩溃
2. 先释放子级资源，再释放渲染器（`renderer.dispose()` 是最后一步）
3. `renderer.forceContextLoss()` 强制丢失 WebGL 上下文，确保 GPU 显存彻底释放
:::

## 7. 整合验证清单

整合完成后，用以下清单验证是否真正「完整可交付」：

| 验证项 | 检查方法 | 通过标准 |
|--------|----------|----------|
| 编译通过 | `pnpm build` | 无报错 |
| 运行无异常 | `pnpm dev` + 浏览器控制台 | 无 Console Error |
| 所有交互生效 | 依次按 O/L/F/G/WASD | 每个键都有响应 |
| 昼夜循环正常 | 观察 30 秒 | 天空/阳光/阴影持续变化 |
| Bloom 效果正常 | 夜晚开灯 | 灯光有柔和辉光 |
| 粒子正常冒烟 | 观察烟囱 | 持续有烟雾上升 |
| 草叶波动 | 观察草地 | 草叶有轻微摇摆 |
| FPS ≥ 50 | 看 FPS 面板 | 桌面端 ≥ 50 FPS |
| 卸载无泄漏 | 组件卸载后重进 | Console 无 WebGL 警告 |

## 8. 本节总结

| 整合挑战 | 解决方案 | 关键代码 |
|----------|----------|----------|
| 初始化顺序 | 按依赖关系排定 onMounted 调用链 | createShaders → createGround |
| Shader 与后期兼容 | 着色器输出线性色 + onBeforeCompile | grassMaterial.onBeforeCompile |
| 双控制器冲突 | controlMode 互斥 + unlock 事件监听 | orbitControls.enabled = false |
| 昼夜多系统联动 | 统一 updateDayNight 集中更新 | _tmpSkyTop.lerp |
| dispose 完整性 | 分区域释放 + LOD traverse | obj.isLOD → levels[i].object |

::: tip 整合的本质
整合的本质是**协调**——让 13 个独立模块在一个统一的架构下和平共处。关键不是「写了多少代码」，而是「解决了多少冲突」。每解决一个冲突，你的工程能力就上一个台阶。
:::
