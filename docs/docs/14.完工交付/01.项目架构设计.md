# 项目架构设计

当你的 Three.js 项目从几百行增长到上千行，从单一几何体扩展到包含灯光、着色器、后期处理、粒子、交互的完整应用时，**架构设计**就成了决定项目可维护性的关键。本节不教新 API，而是教你如何**组织代码**，让最终交付的小屋源码结构清晰、易于维护、方便扩展。

## 1. 为什么需要架构设计

回想 stage-01 的 HouseScene.vue：所有代码都在一个 `initScene()` 函数里，不到 150 行，一目了然。但到了 stage-14，代码膨胀到近 950 行，如果还把所有逻辑塞在一个函数里，会变成一团乱麻：

- 找不到某段代码在哪（「玻璃着色器写在哪了？」）
- 修改一个功能容易碰坏另一个（「改灯光把渲染循环搞坏了」）
- dispose 时遗漏资源（「这个 geometry 忘了释放」）
- 新功能不知道加在哪（「LOD 应该放在哪个函数里？」）

架构设计的目标是让代码**自文档化**：看到函数名就知道它做什么，看到调用顺序就知道执行流程。

::: tip 架构设计的三个原则
1. **单一职责**：每个函数只做一件事，`createWalls` 只负责墙，不管灯光
2. **顺序明确**：函数按「基础 → 内容 → 增强 → 交互」的顺序调用，依赖关系一目了然
3. **资源可追踪**：所有需要 dispose 的资源统一收集，卸载时批量释放
:::

## 2. 函数分区架构

stage-14 的 HouseScene.vue 采用**函数分区**架构，按职责将代码拆分为 19 个函数，分为 5 个层次：

```
┌─────────────────────────────────────────────────────────┐
│  第一层：基础三件套                                       │
│  createScene() → createCamera() → createRenderer()      │
├─────────────────────────────────────────────────────────┤
│  第二层：着色器与灯光                                     │
│  createShaders() → createLights() → createShadows()     │
├─────────────────────────────────────────────────────────┤
│  第三层：场景内容                                         │
│  createGround() → createFoundation()                    │
│  createWalls() → createRoof() → createDoor()            │
│  createWindows() → createChimney() → createFurniture()  │
├─────────────────────────────────────────────────────────┤
│  第四层：增强效果                                         │
│  createParticles() → createPostprocessing()             │
├─────────────────────────────────────────────────────────┤
│  第五层：交互与生命周期                                   │
│  createControls() → setupInteraction() → animate()      │
│  disposeScene()                                          │
└─────────────────────────────────────────────────────────┘
```

### 第一层：基础三件套

`createScene` / `createCamera` / `createRenderer` 是整个应用的基石。它们之间没有依赖，但在 `onMounted` 中按顺序调用：

```js
import * as THREE from "three";

const createScene = () => {
  scene = new THREE.Scene();
  scene.background = new THREE.Color(0x87ceeb);
  scene.fog = new THREE.Fog(0x87ceeb, 30, 90);
  // 天空盒：大球内表面贴渐变着色器
  const skyGeo = new THREE.SphereGeometry(100, 32, 16);
  const skyMaterial = new THREE.ShaderMaterial({
    side: THREE.BackSide,
    depthWrite: false,
    uniforms: {
      uTopColor: { value: new THREE.Color(0x4a90d9) },
      uBottomColor: { value: new THREE.Color(0xb0d4f1) },
    },
    vertexShader: `
      varying vec3 vWorldPos;
      void main() {
        vWorldPos = position;
        gl_Position = projectionMatrix * modelViewMatrix * vec4(position, 1.0);
      }
    `,
    fragmentShader: `
      uniform vec3 uTopColor;
      uniform vec3 uBottomColor;
      varying vec3 vWorldPos;
      void main() {
        float h = normalize(vWorldPos).y;
        float t = clamp(h * 0.5 + 0.5, 0.0, 1.0);
        gl_FragColor = vec4(mix(uBottomColor, uTopColor, t), 1.0);
      }
    `,
  });
  const skyMesh = new THREE.Mesh(skyGeo, skyMaterial);
  scene.add(track(skyMesh));
};

const createCamera = () => {
  camera = new THREE.PerspectiveCamera(
    50,
    window.innerWidth / window.innerHeight,
    0.1,
    200
  );
  camera.position.set(12, 8, 12);
  camera.lookAt(0, 0, 0);
};

const createRenderer = () => {
  renderer = new THREE.WebGLRenderer({
    canvas: canvasRef.value,
    antialias: true,
  });
  renderer.setSize(window.innerWidth, window.innerHeight);
  renderer.setPixelRatio(Math.min(window.devicePixelRatio, 2));
  renderer.outputColorSpace = THREE.SRGBColorSpace;
  renderer.toneMapping = THREE.ACESFilmicToneMapping;
  renderer.toneMappingExposure = 1.0;
};
```

::: warning createRenderer 的色调映射
`renderer.toneMapping = THREE.ACESFilmicToneMapping` 在这里设置，但实际由 `OutputPass` 在后期处理链末端执行。如果不用后期处理，渲染器自身的 toneMapping 生效；用了 EffectComposer 后，RenderPass 会禁用渲染器的 toneMapping，由 OutputPass 接管。这是 stage-11 学过的知识点。
:::

### 第二层：着色器与灯光

着色器必须在场景内容之前创建，因为玻璃和草叶材质要被 `createWindows` 和 `createGround` 引用。灯光和阴影紧随其后：

```js
const createShaders = () => {
  // 玻璃反射着色器（Fresnel）
  glassMaterial = new THREE.ShaderMaterial({
    transparent: true,
    depthWrite: false,
    side: THREE.DoubleSide,
    uniforms: {
      uBaseColor: { value: new THREE.Color(0xa8d0ff) },
      uReflectionColor: { value: new THREE.Color(0xffffff) },
    },
    vertexShader: `
      varying vec3 vNormal;
      varying vec3 vViewDir;
      void main() {
        vec4 worldPos = modelMatrix * vec4(position, 1.0);
        vNormal = normalize(normalMatrix * normal);
        vViewDir = normalize(cameraPosition - worldPos.xyz);
        gl_Position = projectionMatrix * viewMatrix * worldPos;
      }
    `,
    fragmentShader: `
      uniform vec3 uBaseColor;
      uniform vec3 uReflectionColor;
      varying vec3 vNormal;
      varying vec3 vViewDir;
      void main() {
        float fresnel = pow(1.0 - abs(dot(vNormal, vViewDir)), 3.0);
        vec3 color = mix(uBaseColor, uReflectionColor, fresnel);
        float alpha = 0.35 + fresnel * 0.4;
        gl_FragColor = vec4(color, alpha);
      }
    `,
  });

  // 草叶波动着色器（onBeforeCompile 注入 MeshStandardMaterial）
  grassMaterial = new THREE.MeshStandardMaterial({
    color: 0x4a9c2f,
    side: THREE.DoubleSide,
    roughness: 0.9,
  });
  grassMaterial.onBeforeCompile = (shader) => {
    shader.uniforms.uTime = { value: 0 };
    shader.vertexShader = shader.vertexShader
      .replace("#include <common>", "#include <common>\nuniform float uTime;")
      .replace(
        "#include <begin_vertex>",
        `vec3 transformed = position;
         float heightFactor = clamp(position.y, 0.0, 1.0);
         float wave = sin(position.x * 5.0 + uTime * 2.0) * 0.08 * heightFactor;
         float wave2 = cos(position.z * 5.0 + uTime * 1.5) * 0.05 * heightFactor;
         transformed.x += wave;
         transformed.z += wave2;`
      );
    grassShaderRef = shader;
  };
};
```

::: tip 为什么用 onBeforeCompile 而非裸 ShaderMaterial
草叶使用 InstancedMesh 渲染，需要 `instanceMatrix` 属性。裸 `ShaderMaterial` 不会自动声明 `instanceMatrix`，需要手动处理。而 `onBeforeCompile` 在 `MeshStandardMaterial` 基础上注入自定义代码，自动继承 InstancedMesh 支持、PBR 光照和阴影接收——一举多得。
:::

### 第三层：场景内容

这一层是房子的主体结构，按「从下到上」的建造顺序组织：

```js
// onMounted 中的调用顺序
createGround();        // 草地 + 草叶
createFoundation();    // 地基 + 台阶

const houseGroup = new THREE.Group();
houseGroup.name = "House";
createWalls(houseGroup);     // 墙体(含洞)
createRoof(houseGroup);      // 尖屋顶
createDoor(houseGroup);      // 木门
createWindows(houseGroup);   // 玻璃窗
createChimney(houseGroup);   // 烟囱 + 地板
createFurniture(houseGroup); // 家具 + 装饰树
scene.add(houseGroup);
```

注意所有建筑构件都接收 `houseGroup` 参数，把自己加到这个 Group 下，而不是直接加到 scene。这样整个房子是一个统一的 Object3D 树，便于整体移动、旋转或销毁。

### 第四层：增强效果

粒子和后期处理在场景内容之后创建，因为它们需要引用已存在的 scene 和 camera：

```js
const createPostprocessing = () => {
  composer = new EffectComposer(renderer);
  composer.addPass(new RenderPass(scene, camera));
  bloomPass = new UnrealBloomPass(
    new THREE.Vector2(window.innerWidth, window.innerHeight),
    0.35, // strength
    0.4,  // radius
    0.85  // threshold
  );
  composer.addPass(bloomPass);
  composer.addPass(new OutputPass());
  composer.setPixelRatio(Math.min(window.devicePixelRatio, 2));
};
```

### 第五层：交互与生命周期

最后是控制器、事件和渲染循环：

```js
const createControls = () => {
  orbitControls = new OrbitControls(camera, renderer.domElement);
  orbitControls.enableDamping = true;
  orbitControls.dampingFactor = 0.05;
  orbitControls.target.set(0, 1.5, 0);
  orbitControls.update();

  pointerLockControls = new PointerLockControls(camera, renderer.domElement);
  pointerLockControls.addEventListener("unlock", () => {
    if (controlMode === "fps") switchToBirdMode();
  });
};

const setupInteraction = () => {
  window.addEventListener("keydown", onKeyDown);
  window.addEventListener("keyup", onKeyUp);

```

## 3. 资源管理：track 模式

Three.js 最容易踩的坑是内存泄漏。stage-14 采用 `track` 模式统一收集需要 dispose 的资源：

```js
const disposables = [];
const track = (obj) => {
  disposables.push(obj);
  return obj;
};

// 使用：创建资源时立即 track
const ground = new THREE.Mesh(groundGeo, groundMat);
scene.add(track(ground));  // 加入场景的同时收集到 disposables

// 销毁时遍历释放
const disposeScene = () => {
  disposables.forEach((obj) => {
    if (obj.geometry) obj.geometry.dispose();
    if (obj.material) {
      if (Array.isArray(obj.material)) {
        obj.material.forEach((m) => {
          if (m.map) m.map.dispose();
          m.dispose();
        });
      } else {
        if (obj.material.map) obj.material.map.dispose();
        obj.material.dispose();
      }
    }
    if (obj.parent) obj.parent.remove(obj);
  });
  disposables.length = 0;
};
```

::: warning track 模式的边界
`track` 收集的是 Object3D（Mesh / Points / Light 等），它会自动 dispose 这些对象的 geometry 和 material。但有两种情况需要手动处理：

1. **Group 子级**：如 `doorGroup` 内的门板，需要单独 `traverse` 释放
2. **共享资源**：如多个 Mesh 共用同一个 geometry 或 material，dispose 一次即可，但 track 会收集多次。实际项目中可以用 Set 去重

stage-14 的 `doorGroup` 就是手动 traverse 释放的例子。
:::

## 4. 配置化设计

好的架构会把「数据」和「逻辑」分离。stage-14 把颜色、尺寸、周期等常量提取到模块顶部：

```js
// 昼夜循环颜色常量
const DAY_SUN_COLOR = new THREE.Color(0xfffaf0);
const NIGHT_SUN_COLOR = new THREE.Color(0x6f8fff);
const DAY_SKY_TOP = new THREE.Color(0x4a90d9);
const NIGHT_SKY_TOP = new THREE.Color(0x05081a);
const DAY_AMBIENT = 0.55;
const NIGHT_AMBIENT = 0.12;
const DAY_SUN_INTENSITY = 1.4;
const NIGHT_SUN_INTENSITY = 0.25;
const DAY_PERIOD = 30; // 一天周期 30 秒

// 复用的临时对象（避免每帧 new 造成 GC 压力）
const _tmpSunColor = new THREE.Color();
const _tmpSkyTop = new THREE.Color();
```

这样做的好处：

- **一目了然**：所有可调参数集中在一处，方便调参
- **避免 GC**：临时 Color 对象复用，不每帧 `new`
- **易于扩展**：想改昼夜周期长度？改一个常量就行

::: tip 配置化的进阶
在更大的项目中，可以把这些常量提取到单独的 `config.js` 文件，甚至做成 JSON 配置文件，让非程序员（如策划、设计师）也能调整参数。这是从「代码驱动」走向「数据驱动」的关键一步。
:::

## 5. onMounted 调用顺序

整个初始化流程在 `onMounted` 中按层次顺序调用，依赖关系一目了然：

```js
onMounted(() => {
  // 第一层：基础三件套
  createScene();
  createCamera();
  createRenderer();
  clock = new THREE.Clock();

  // 第二层：着色器与灯光（着色器先于构件，灯光先于阴影）
  createShaders();
  createLights();
  createShadows();

  // 第三层：场景内容
  createGround();
  createFoundation();

  // 房子组装（Group 统一管理）
  const houseGroup = new THREE.Group();
  houseGroup.name = "House";
  createWalls(houseGroup);
  createRoof(houseGroup);
  createDoor(houseGroup);
  createWindows(houseGroup);
  createChimney(houseGroup);
  createFurniture(houseGroup);
  scene.add(houseGroup);

  // 第四层：增强效果
  createParticles();
  createPostprocessing();

  // 第五层：交互与启动
  createControls();
  setupInteraction();
  fpsPrevTime = performance.now();
  window.addEventListener("resize", handleResize);
  animate();
});
```

::: warning 调用顺序的依赖关系
1. `createShaders` 必须在 `createWindows` / `createGround` 之前，因为后者引用 `glassMaterial` / `grassMaterial`
2. `createLights` 必须在 `createShadows` 之前，因为后者配置前者的阴影参数
3. `createPostprocessing` 必须在场景内容之后，因为它引用 `scene` 和 `camera`
4. `createControls` 必须在 `createRenderer` 之后，因为控制器绑定 `renderer.domElement`
:::

## 6. 本节总结

| 架构原则 | 实践方法 | 收益 |
|----------|----------|------|
| 函数分区 | 19 个 createXxx / setupXxx / updateXxx 函数 | 结构清晰，职责单一 |
| 层次分明 | 基础 → 着色器 → 内容 → 增强 → 交互 | 依赖关系一目了然 |
| 资源追踪 | track() 统一收集 disposables | dispose 不遗漏 |
| 配置化 | 颜色/尺寸/周期常量提取到顶部 | 调参集中，避免 GC |
| Group 组织 | 房子构件统一挂到 houseGroup | 整体管理，便于销毁 |

::: tip 架构是演进的
stage-14 的架构不是一开始就设计好的，而是从 stage-01 的单函数逐步演进到 19 个函数。**不要过度设计**：stage-01 用一个 `initScene` 就够了，stage-14 才需要分区。架构应该与项目复杂度匹配，而不是为架构而架构。
:::
