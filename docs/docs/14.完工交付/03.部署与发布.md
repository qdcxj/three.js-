# 部署与发布

小屋造好了，代码跑通了，但它还只存在于你的本地电脑上。**部署与发布**是把它送到互联网上，让全世界都能访问的最后一步。本节教你用 `pnpm build` 打包 Three.js 项目，并部署到 Vercel、Netlify、GitHub Pages 三大主流静态托管平台。同时建立性能预算意识，确保交付的小屋在线上也能流畅运行。

## 1. pnpm build 打包

### 生产构建

Three.js 项目本质是一个 Vite + Vue 3 的前端项目，打包方式与普通前端项目一致：

```bash
cd lession/stage-14-完工交付
pnpm install      # 安装依赖
pnpm build        # 生产打包
```

打包完成后，`dist/` 目录就是可部署的静态文件：

```
dist/
├── index.html              # 入口 HTML
└── assets/
    ├── index-xxxxx.js      # JS bundle（含 three.js + Vue + HouseScene）
    └── index-xxxxx.css     # CSS 样式
```

::: tip 构建产物大小
stage-14 的构建产物约 630KB（gzip 后 170KB）。其中 three.js 占绝大部分。对于 3D 应用来说这是正常水平。如果需要进一步优化，可以用动态 `import()` 拆分 three.js，或者用 Tree Shaking 只引入用到的模块。
:::

### 构建优化：Code Splitting

默认情况下 Vite 会把所有 JS 打包成一个 chunk。对于 Three.js 项目，可以通过手动分包把 three.js 单独拆出，利用浏览器缓存：

```js
// vite.config.js
import { defineConfig } from "vite";
import vue from "@vitejs/plugin-vue";

export default defineConfig({
  plugins: [vue()],
  build: {
    rollupOptions: {
      output: {
        manualChunks: {
          three: ["three"],          // three.js 单独打包
          vendor: ["vue"],           // vue 单独打包
        },
      },
    },
    chunkSizeWarningLimit: 800,      // 提高警告阈值到 800KB
  },
});
```

这样修改后，构建产物变成：

```
dist/assets/
├── three-xxxxx.js        # three.js（~600KB，几乎不变，可长期缓存）
├── vendor-xxxxx.js       # vue（~50KB）
└── index-xxxxx.js        # 业务代码（~30KB，频繁变化）
```

用户第二次访问时，three.js 和 vue 从浏览器缓存加载，只需重新下载业务代码。

### 本地预览构建产物

部署前先在本地预览构建产物，确保线上效果一致：

```bash
pnpm preview        # 启动本地预览服务器 → http://localhost:4173
```

## 2. 部署到 Vercel

Vercel 是最简单的部署方式，连接 GitHub 仓库后自动部署。

### 方式一：CLI 部署

```bash
# 安装 Vercel CLI
npm i -g vercel

# 在项目根目录执行
cd lession/stage-14-完工交付
vercel

# 按提示操作：
# ? Set up and deploy "stage-14-完工交付"? Y
# ? Which scope do you want to deploy to? (选择你的账号)
# ? Link to existing project? N
# ? What's your project's name? stage-14-house
# ? In which directory is your code located? ./
# ? Want to modify these settings? N
```

部署完成后，Vercel 会给一个 `https://stage-14-house-xxx.vercel.app` 的线上地址。

### 方式二：GitHub 自动部署

1. 把项目推到 GitHub 仓库
2. 登录 [vercel.com](https://vercel.com)，点击 `New Project`
3. 导入 GitHub 仓库
4. Framework Preset 选 `Vite`
5. Build Command 填 `pnpm build`
6. Output Directory 填 `dist`
7. 点击 `Deploy`

之后每次 `git push`，Vercel 自动重新部署。

::: tip Vercel 的优势
- 零配置：自动识别 Vite 项目
- 全球 CDN：访问速度快
- 预览部署：每个 PR 自动生成预览地址
- 免费额度：个人项目完全够用
:::

## 3. 部署到 Netlify

Netlify 与 Vercel 类似，也是流行的静态托管平台。

### 方式一：拖拽部署

1. 执行 `pnpm build` 生成 `dist/` 目录
2. 登录 [app.netlify.com](https://app.netlify.com)
3. 把 `dist/` 文件夹拖到 Netlify 的拖拽区域
4. 自动部署完成，获得线上地址

### 方式二：Git 持续部署

1. 在 Netlify 控制台点击 `Add new site` → `Import an existing project`
2. 连接 GitHub 仓库
3. 配置：
   - Build command: `pnpm build`
   - Publish directory: `dist`
4. 点击 `Deploy site`

可以在项目根目录创建 `netlify.toml` 固定配置：

```toml
# netlify.toml
[build]
  command = "pnpm build"
  publish = "dist"

[[headers]]
  for = "/*"
  [headers.values]
    # 启用 gzip 压缩
    Content-Encoding = "gzip"
    # 缓存静态资源
    Cache-Control = "public, max-age=31536000, immutable"
```

## 4. 部署到 GitHub Pages

GitHub Pages 适合开源项目，完全免费。

### 配置 Vite 的 base 路径

GitHub Pages 的 URL 是 `https://username.github.io/repo-name/`，需要设置 Vite 的 `base`：

```js
// vite.config.js
export default defineConfig({
  plugins: [vue()],
  base: "/stage-14-house/",  // 替换为你的仓库名
});
```

### GitHub Actions 自动部署

在仓库根目录创建 `.github/workflows/deploy.yml`：

```yaml
name: Deploy to GitHub Pages

on:
  push:
    branches: [main]

permissions:
  contents: read
  pages: write
  id-token: write

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v2
        with:
          version: 9
      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: pnpm
      - run: pnpm install
      - run: pnpm build
      - uses: actions/upload-pages-artifact@v3
        with:
          path: dist

  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
    steps:
      - uses: actions/deploy-pages@v4
```

推送到 `main` 分支后，GitHub Actions 自动构建并部署。在仓库的 `Settings → Pages` 中可以看到部署地址。

::: warning GitHub Pages 的限制
- 仅支持静态文件（不能有服务端逻辑）
- 仓库必须是 public（免费账号）
- 单次部署大小限制 1GB
- 每月流量限制 100GB
:::

## 5. 性能预算

部署到线上后，需要关注性能指标。一个交付级 3D 应该达到以下标准：

### 桌面端性能预算

| 指标 | 目标 | 检测方法 |
|------|------|----------|
| 首屏加载 | < 3 秒 | Lighthouse / WebPageTest |
| JS Bundle (gzip) | < 200KB | `pnpm build` 输出 |
| 运行 FPS | ≥ 50 | 应用内 FPS 面板 |
| DrawCall | < 300 | `renderer.info.render.calls` |
| 内存稳定 | 切换场景后几何体/纹理数不增长 | `renderer.info.memory` |

### 移动端性能预算

| 指标 | 目标 | 优化手段 |
|------|------|----------|
| 运行 FPS | ≥ 30 | 降低 pixelRatio / 简化着色器 |
| 首屏加载 | < 5 秒 | Code Splitting / 懒加载 |
| 内存占用 | < 100MB | 减少纹理尺寸 / 降低几何体精度 |

### 移动端适配

在 HouseScene.vue 中，可以根据设备性能动态调整渲染参数：

```js
const createRenderer = () => {
  renderer = new THREE.WebGLRenderer({
    canvas: canvasRef.value,
    antialias: true,
    powerPreference: "high-performance",
  });

  // 移动端降低像素比，减少 GPU 负载
  const isMobile = /Android|iPhone|iPad/i.test(navigator.userAgent);
  const maxRatio = isMobile ? 1.5 : 2;
  renderer.setPixelRatio(Math.min(window.devicePixelRatio, maxRatio));

  renderer.setSize(window.innerWidth, window.innerHeight);
  renderer.outputColorSpace = THREE.SRGBColorSpace;
  renderer.toneMapping = THREE.ACESFilmicToneMapping;
};
```

::: tip 性能预算的意义
性能预算不是「尽量优化」，而是「设定红线」。一旦某项指标超标，就停下来优化，而不是继续加功能。这能避免「功能越做越多，性能越来越差」的恶性循环。
:::

## 6. 最终效果总结

经过 14 个阶段的建设，最终交付的欧式乡村小屋具备：

### 视觉效果

- **草地波动**：1500 片 InstancedMesh 草叶在着色器驱动下随风摇摆
- **玻璃反射**：4 扇窗户通过 Fresnel 着色器在边缘呈现天空色反射
- **昼夜交替**：30 秒一个周期，天空、阳光、阴影、雾色平滑过渡
- **Bloom 辉光**：夜晚室内灯光散发柔和光晕
- **烟囱冒烟**：150 个粒子持续升腾、消散
- **软阴影**：PCFSoftShadowMap 让阴影边缘自然柔和

### 交互体验

- **鸟瞰浏览**：鼠标拖拽旋转、滚轮缩放，俯瞰整栋小屋
- **第一人称**：按 F 进入沉浸式漫游，WASD 移动，鼠标转头
- **开关门**：按 O 触发门轴旋转动画，平滑过渡
- **开关灯**：按 L 控制室内灯和壁灯，渐亮渐灭
- **自动昼夜**：无需操作，场景自动在白天/黄昏/夜晚间循环

### 工程质量

- **代码分区**：19 个函数按职责组织，结构清晰
- **完整 dispose**：组件卸载时释放全部 GPU 资源
- **性能优化**：InstancedMesh 草叶 + LOD 装饰树 + FPS 面板
- **响应式 UI**：实时显示 FPS / 时段 / 门灯状态 / 视角模式
