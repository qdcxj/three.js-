# GLTF 加载器：把外部模型搬进场景

stage-08 之前，我们小屋里的所有构件——墙、屋顶、门、烟囱——都是用 `BoxGeometry` / `CylinderGeometry` / `ExtrudeGeometry` 一块块手写的。这对教学足够，但在真实项目里，没人会手写一把雕花椅子或一个带骨骼的角色。建模师在 Blender / Maya / 3ds Max 里把模型建好，导出成文件，前端用**加载器（Loader）**把它读进 Three.js 场景。在所有格式里，**glTF** 是 Web 3D 当之无愧的事实标准，本节我们就把 `GLTFLoader` 彻底讲透。

## 一、为什么是 glTF

glTF 的全称是 **GL Transmission Format**，由 Khronos 组织（同时维护 OpenGL / Vulkan）维护，被业界称为"3D 界的 JPEG"。它专为网络传输设计，相比老牌的 OBJ / FBX 有压倒性优势：

| 格式 | 体积 | 材质 | 动画/骨骼 | 二进制资源 | Three.js 支持 |
|------|------|------|----------|-----------|--------------|
| **glTF / glb** | 小（可 Draco 压缩再缩 90%） | PBR 完整（金属度/粗糙度/法线/ emissive） | 完整支持 | 内嵌或单文件 | 官方一等公民 `GLTFLoader` |
| OBJ | 大 | 仅基础颜色（Kd/map） | 不支持 | 外部 .mtl/.png | `OBJLoader`（功能弱） |
| FBX | 大 | 私有二进制 | 支持但解析慢 | 私有 | `FBXLoader`（不稳定） |
| STL | 中 | 无 | 无 | 单文件 | `STLLoader`（仅几何体） |

::: tip 一句话选型
新项目无脑选 glTF。需要小体积就上 Draco 压缩（见 02 节）。只在对接老资产（3D 打印的 STL、老 CAD 的 OBJ）时才考虑其他加载器。
:::

glTF 有两种存盘形式：

- **`.gltf`**：JSON 文本 + 外部 `.bin`（二进制几何数据）+ 外部 `.png`（贴图），多文件，便于版本控制diff
- **`.glb`**：把 JSON + bin + 贴图全部打包进**一个二进制文件**，体积更小、加载更快、网络请求更少

两者 `GLTFLoader` 都能直接读，生产环境推荐 `.glb`。

## 二、GLTFLoader 的四回调签名

所有 Three.js 加载器都遵循同一个范式：`load(url, onLoad, onProgress, onError)`。`GLTFLoader` 的特别之处在于 `onLoad` 回调拿到的不是一个 `Mesh`，而是一个 `GLTF` 对象——里面有 `scene`（场景图）、`animations`（动画数组）、`asset`（版本元信息）等。

```js
import * as THREE from "three";
import { GLTFLoader } from "three/examples/jsm/loaders/GLTFLoader.js";

const loader = new GLTFLoader();

loader.load(
  "/models/sofa.glb",
  // onLoad：加载完成，gltf 是 { scene, animations, asset, parser, ... }
  (gltf) => {
    const model = gltf.scene; // 一个 THREE.Group，里面挂着所有 Mesh
    scene.add(model);
  },
  // onProgress：加载中，xhr 有 loaded / total（total 可能为 0，如 gzip 时）
  (xhr) => {
    if (xhr.total) {
      console.log(`进度：${((xhr.loaded / xhr.total) * 100).toFixed(1)}%`);
    }
  },
  // onError：加载失败（404 / 跨域 / 解析错误）
  (err) => {
    console.error("模型加载失败", err);
  }
);
```

::: warning 加载是异步的
`load()` 立即返回，模型在回调里才可用。这意味着渲染循环必须"兼容模型尚未到达"——先渲染空场景，回调触发后模型自动出现。千万不要在 `load()` 后立刻写 `model.position.set(...)`，那时 `model` 还不存在。
:::

如果你更喜欢 `async/await` 风格，`GLTFLoader` 也提供了 `loadAsync`：

```js
import * as THREE from "three";
import { GLTFLoader } from "three/examples/jsm/loaders/GLTFLoader.js";

const loader = new GLTFLoader();
try {
  const gltf = await loader.loadAsync("/models/sofa.glb");
  scene.add(gltf.scene);
} catch (err) {
  console.error("加载失败", err);
}
```

`loadAsync` 内部仍是 `load`，只是把回调包成了 Promise。注意 `onProgress` 在 `loadAsync` 里拿不到——需要进度条就用回 `load`。

## 三、gltf.scene 是一个 Group

`onLoad` 拿到的 `gltf.scene` 是一个 `THREE.Group`，建模软件里的"场景图"被原样保留：模型可能由几十个 Mesh 嵌套组成（椅子→椅腿、座板、靠背各自一个 Mesh），父子关系、变换矩阵都跟 Blender 里一致。

直接 `scene.add(gltf.scene)` 能用，但通常要做三件事：

1. **遍历开阴影**：导出的 Mesh 默认 `castShadow=false`，要逐个打开
2. **改材质**：有时模型贴图太亮/太暗，或想把 `MeshStandardMaterial` 换成 `MeshPhysicalMaterial` 加透射
3. **尺寸/位置适配**：模型往往"巨大或微小且原点偏"，要归一化

```js
import * as THREE from "three";
import { GLTFLoader } from "three/examples/jsm/loaders/GLTFLoader.js";

const loader = new GLTFLoader();
loader.load("/models/sofa.glb", (gltf) => {
  const model = gltf.scene;

  // 1) 遍历所有 Mesh，开阴影
  model.traverse((obj) => {
    if (obj.isMesh) {
      obj.castShadow = true;
      obj.receiveShadow = true;
    }
  });

  // 2) （可选）改材质：把粗糙度统一调高一点，避免模型反光太强
  model.traverse((obj) => {
    if (obj.isMesh && obj.material.isMeshStandardMaterial) {
      obj.material.roughness = Math.max(obj.material.roughness, 0.6);
    }
  });

  scene.add(model);
});
```

::: tip traverse vs children
`traverse` 会递归遍历整棵子树（所有后代），`children` 只看直接子级。模型一般嵌套很深，几乎总是用 `traverse`。
:::

## 四、尺寸与位置适配：Box3 归一化

从不同来源拿到的模型，尺度千差万别：Blender 默认单位是米，3ds Max 可能是厘米，SketchUp 甚至可能是英寸。一个"1.8 米的沙发"导出后可能在 Three.js 里变成 180 单位长（即 180 米），直接 add 进场景会把整个小屋撑爆。

标准做法是用 `THREE.Box3` 算出模型的**轴对齐包围盒（AABB）**，得到尺寸和中心，再缩放 + 平移就位。

```js
import * as THREE from "three";
import { GLTFLoader } from "three/examples/jsm/loaders/GLTFLoader.js";

const loader = new GLTFLoader();
loader.load("/models/sofa.glb", (gltf) => {
  const model = gltf.scene;

  // 计算包围盒
  const box = new THREE.Box3().setFromObject(model);
  const size = box.getSize(new THREE.Vector3());
  const center = box.getCenter(new THREE.Vector3());

  // 目标尺寸：让沙发最长边 = 2.0 米（HOUSE_SPEC 沙发长度）
  const maxDim = Math.max(size.x, size.y, size.z);
  const targetMax = 2.0;
  const scale = targetMax / maxDim;
  model.scale.setScalar(scale);

  // 缩放后包围盒变了，重新算中心，把模型底面放到 y=0、中心放到 x=0
  const box2 = new THREE.Box3().setFromObject(model);
  const center2 = box2.getCenter(new THREE.Vector3());
  const minY = box2.min.y;
  model.position.x -= center2.x;
  model.position.y -= minY; // 底面贴地
  model.position.z -= center2.z;

  // 最后整体平移到目标位置（沙发放在 (0, 0.35, 1.5)，y=0.35 是地板顶面）
  model.position.x += 0;
  model.position.y += 0.35;
  model.position.z += 1.5;

  model.traverse((obj) => {
    if (obj.isMesh) {
      obj.castShadow = true;
      obj.receiveShadow = true;
    }
  });

  scene.add(model);
});
```

::: warning 别忘了重新算包围盒
`scale` 改变后包围盒也变了。如果只算一次 box 就平移，会发现模型"没贴地"或"偏一边"——因为你用的是缩放前的中心。上面代码里 `box2` 是关键。
:::

## 五、本阶段源码里的 GLTFLoader 演示

本阶段源码快照 `HouseScene.vue` 的家具是程序化搭建的（见 03 节），但额外含一个 `tryLoadGltfDemo()` 函数演示真实加载流程——它尝试从 threejs 官方 CDN 加载一个示例模型放到屋顶当装饰，离线时静默回退到程序化家具。核心代码如下：

```js
import * as THREE from "three";
import { GLTFLoader } from "three/examples/jsm/loaders/GLTFLoader.js";

const tryLoadGltfDemo = (houseGroup) => {
  const loader = new GLTFLoader();
  // threejs 官方示例模型 CDN（需要联网；离线时 onError 触发，回退到程序化家具）
  const MODEL_URL =
    "https://threejs.org/examples/models/gltf/DamagedHelmet/glTF/DamagedHelmet.gltf";

  loader.load(
    MODEL_URL,
    (gltf) => {
      const model = gltf.scene;
      model.scale.setScalar(0.6);
      model.position.set(0, 5.6, 0);
      model.rotation.y = Math.PI * 0.15;
      model.traverse((obj) => {
        if (obj.isMesh) {
          obj.castShadow = true;
          obj.receiveShadow = true;
        }
      });
      houseGroup.add(model);
    },
    (xhr) => {
      // onProgress：可选，演示用
    },
    (err) => {
      // onError：离线或 CDN 不可达，静默回退（程序化家具已先行布置）
      console.warn("GLTF 演示模型加载失败，已回退到程序化家具", err);
    }
  );
};
```

::: tip 为什么演示用 onError 回退
真实项目的模型资产放在自己的 CDN/OSS，几乎不会失败。但本教程源码快照必须**离线可运行**（读者可能断网阅读），所以采取"程序化家具兜底 + GLTF 在线尝试"双轨策略：联网时多一个 GLTF 装饰，断网时只有程序化家具，两种情况都能跑。这是写教程/演示代码的常见技巧。
:::

## 六、跨域与 MIME 类型

加载外部模型常踩两个坑：

1. **CORS 跨域**：模型放在 CDN 或 OSS 上，必须配置 `Access-Control-Allow-Origin`，否则浏览器拒绝读取。本地开发时把模型放 `public/models/` 同源最稳
2. **MIME 类型**：`.glb` 必须以 `model/gltf-binary` 返回，`.gltf` 必须 `application/json`。静态服务器配置错（如把 .glb 当 `application/octet-stream`）有时也能读，但个别浏览器会拒绝

::: tip Vite 静态资源
Vite 项目把模型放 `public/models/sofa.glb`，运行时通过 `/models/sofa.glb` 访问即可，Vite 自带静态服务会正确处理 MIME。生产构建时 `public/` 原样拷贝到 `dist/`，路径不变。
:::

## 七、本节总结

- **glTF 是 Web 3D 的事实标准**：体积小、PBR 材质全、支持动画骨骼、Three.js 官方一等公民。`.gltf` 多文件、`.glb` 单二进制，生产优先 `.glb`
- **四回调签名**：`load(url, onLoad, onProgress, onError)`，`onLoad` 拿到的是 `{ scene, animations, ... }` 而非 Mesh。`loadAsync` 是 Promise 包装但拿不到进度
- **`gltf.scene` 是 Group**：用 `traverse` 递归遍历所有 Mesh，统一开阴影、改材质
- **尺寸适配三步**：`Box3.setFromObject` 算包围盒 → `scale.setScalar(target/max)` 归一化 → 重新算包围盒后平移就位（底面贴地 + 中心归零 + 整体平移到目标位置）
- **离线兜底**：教程/演示代码可用"程序化家具先行布置 + GLTF 在线尝试 + onError 回退"双轨策略，保证断网也能跑
