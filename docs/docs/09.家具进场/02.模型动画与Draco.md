# 模型动画与 Draco：让模型动起来、把模型压更小

01 节我们把静态模型搬进了场景。但真实资产往往不是死的——一个角色模型可能带"走路/跑步/跳跃"三条动画，一台风扇模型可能带"叶片旋转"动画，一扇门模型可能带"开合"动画。这些动画在 Blender 里做好后**烘焙进 glTF 文件**，前端用 `AnimationMixer` 播放即可。本节先讲怎么播放模型内嵌动画，再讲怎么用 `DRACOLoader` 加载压缩过的 glb——把几十兆的模型压到几兆，是移动端/弱网必备技能。

## 一、AnimationMixer / AnimationClip / AnimationAction 三件套

Three.js 的动画系统有三个核心类，关系如下：

| 类 | 作用 | 类比 |
|----|------|------|
| `THREE.AnimationClip` | 一条完整动画（如"走路"），由多条 `KeyframeTrack` 组成 | 一段录像 |
| `THREE.AnimationMixer` | 播放控制器，绑定到一个 `Object3D`（模型），管理时间轴 | 录像机 |
| `THREE.AnimationAction` | 对某条 clip 的"播放句柄"，控制 play/stop/pause/speed/loop | 播放按钮 |

`gltf.animations` 是一个 `AnimationClip[]` 数组，每个元素对应建模师在 Blender 里做的一条动画。我们用 `mixer.clipAction(clip)` 拿到对应的 `AnimationAction`，再 `.play()` 就能播。

```js
import * as THREE from "three";
import { GLTFLoader } from "three/examples/jsm/loaders/GLTFLoader.js";

let mixer = null; // 模块级变量，渲染循环里要 update 它
const clock = new THREE.Clock();

const loader = new GLTFLoader();
loader.load("/models/character.glb", (gltf) => {
  const model = gltf.scene;
  scene.add(model);

  // 创建 mixer，绑定到整个模型
  mixer = new THREE.AnimationMixer(model);

  // 假设 gltf.animations[0] 是"走路"动画
  const clips = gltf.animations;
  if (clips.length > 0) {
    const walkClip = clips[0];
    const action = mixer.clipAction(walkClip);
    action.play(); // 开始循环播放
  }
});

// 渲染循环里必须 update mixer，传帧间隔 dt
function animate() {
  requestAnimationFrame(animate);
  const dt = clock.getDelta();
  if (mixer) mixer.update(dt); // 关键：驱动动画时间轴前进
  renderer.render(scene, camera);
}
animate();
```

::: warning 忘了 mixer.update 会怎样
动画完全不动。`AnimationMixer` 不会自己推进时间，必须每帧调用 `mixer.update(dt)`。这跟 stage-08 的 `controls.update()` 是一个套路——Three.js 里所有"随时间变化"的东西都要在渲染循环里手动 update。
:::

## 二、播放控制：暂停、变速、单次播放

`AnimationAction` 提供丰富的播放控制 API：

```js
import * as THREE from "three";

const action = mixer.clipAction(walkClip);

// 基础
action.play();            // 播放
action.stop();            // 停止并重置
action.reset();           // 重置到初始状态
action.paused = true;     // 暂停（保留进度）
action.paused = false;    // 恢复

// 变速：timeScale > 1 加速，< 1 减速，< 0 倒放
action.timeScale = 1.5;   // 1.5 倍速
action.timeScale = -1;    // 倒放

// 循环模式
action.loop = THREE.LoopRepeat;     // 循环（默认）
action.loop = THREE.LoopOnce;       // 播一次就停
action.loop = THREE.LoopPingPong;   // 来回播放
action.repetitions = 3;             // LoopRepeat 时循环 3 次后停

// 淡入淡出（适合多个动画切换，如走路→跑步）
action.fadeIn(0.3);   // 0.3 秒淡入
action.fadeOut(0.3);  // 0.3 秒淡出

// 跳到指定时间（秒）
action.startAt(2.0);  // 延迟 2 秒后开始
```

::: tip 多动画切换
模型带多条动画时（如 idle/walk/run），同时只播一条。切换时用 `oldAction.fadeOut(0.2); newAction.reset().fadeIn(0.2).play();` 做 0.2 秒平滑过渡，避免硬切带来的"跳帧"感。这是角色动画的标准写法。
:::

## 三、查看模型里有哪些动画

不知道 `gltf.animations` 里每条动画叫什么？打印出来：

```js
loader.load("/models/character.glb", (gltf) => {
  gltf.animations.forEach((clip, i) => {
    console.log(`动画 ${i}: ${clip.name}, 时长 ${clip.duration.toFixed(2)}s`);
    // 输出示例：
    //   动画 0: idle, 时长 2.50s
    //   动画 1: walk, 时长 1.20s
    //   动画 2: run, 时长 0.80s
  });
});
```

也可以用 clip 的名字找：

```js
import * as THREE from "three";

const walkClip = THREE.AnimationClip.findByName(gltf.animations, "walk");
if (walkClip) {
  mixer.clipAction(walkClip).play();
}
```

## 四、Draco 压缩：把模型压到 1/10

glTF 本身已经比 OBJ/FBX 小很多，但几何数据（顶点坐标、法线、UV）仍是大头。Google 开源的 **Draco** 算法能把几何数据压缩 90%+——一个 50MB 的沙发模型压缩后可能只有 3MB，移动端弱网友好。

代价是：解压需要 wasm 解码器，加载时多一步。Three.js 用 `DRACOLoader` 处理。

```js
import * as THREE from "three";
import { GLTFLoader } from "three/examples/jsm/loaders/GLTFLoader.js";
import { DRACOLoader } from "three/examples/jsm/loaders/DRACOLoader.js";

// 1) 创建 DRACOLoader，指定 wasm 解码器路径
const dracoLoader = new DRACOLoader();
// 解码器 wasm 文件在 three 包里自带，复制到 public/draco/ 或直接用 CDN
dracoLoader.setDecoderPath("/draco/");
// 可选：用 wasm 而非 js 解码（更快，但需要浏览器支持 wasm，现代浏览器都支持）
dracoLoader.setDecoderConfig({ type: "wasm" });

// 2) 把 dracoLoader 挂到 GLTFLoader
const loader = new GLTFLoader();
loader.setDRACOLoader(dracoLoader);

// 3) 之后用法完全一样，GLTFLoader 内部遇到压缩几何体会自动调 dracoLoader 解压
loader.load("/models/sofa_draco.glb", (gltf) => {
  scene.add(gltf.scene);
});
```

::: warning 解码器路径
`setDecoderPath` 指向的是 wasm 文件所在目录（以 `/` 结尾），不是文件本身。Three.js 包里自带解码器文件，路径是 `three/examples/jsm/libs/draco/`，你可以把它复制到项目的 `public/draco/` 让它同源访问。也可以用官方 CDN：`https://www.gstatic.com/draco/v1/decoders/`。
:::

::: tip 哪些模型适合 Draco
Draco 压缩的是**几何数据**，对**贴图无效**（贴图另存 .jpg/.png）。所以高面数模型（角色、雕刻、扫描资产）压缩收益巨大，低面数模型（一个 Box）压缩反而可能变大。一般建议面数 > 1 万的模型才上 Draco。
:::

## 五、Draco 模型怎么导出

Draco 压缩不是前端做的，是建模师在 Blender 导出 glTF 时勾选压缩选项：

1. Blender → File → Export → glTF 2.0 (.glb)
2. 右侧导出面板 → Compression → 勾选 **Draco mesh compression**
3. 调整 Compression Level（0-10，越高越小越慢）和 Quantization（顶点/法线/UV 的精度位数，越低越小越失真）

导出后的 .glb 就是 Draco 压缩的，前端必须用 `DRACOLoader` 才能加载，否则会报"几何体解码失败"。

::: warning 不用 DRACOLoader 加载压缩模型会怎样
`onError` 触发，报错类似 `Error: Draco 解码器未配置` 或 `Unknown primitive mode`。看到这类错误第一反应就是检查模型是否 Draco 压缩、有没有 `setDRACOLoader`。
:::

## 六、AnimationMixer 的生命周期与多模型动画

`AnimationMixer` 内部维护着时间轴、动作状态机和属性绑定缓存，体积不小。当模型从场景移除（如切换关卡、卸载角色）时，对应的 mixer 也要显式释放，否则会造成内存泄漏——这是真实项目里最容易踩的坑。

```js
import * as THREE from "three";

// 一个模型一个 mixer，用 Map 维护对应关系
const mixers = new Map(); // key: model.uuid, value: { mixer, actions }

function playModel(model, clips) {
  const mixer = new THREE.AnimationMixer(model);
  const actions = clips.map((clip) => mixer.clipAction(clip));
  mixers.set(model.uuid, { mixer, actions });
  actions[0]?.play();
}

// 渲染循环里遍历所有 mixer 各自 update
function animate() {
  requestAnimationFrame(animate);
  const dt = clock.getDelta();
  mixers.forEach(({ mixer }) => mixer.update(dt));
  renderer.render(scene, camera);
}

// 卸载模型时清理对应的 mixer
function disposeModel(model) {
  const entry = mixers.get(model.uuid);
  if (entry) {
    entry.actions.forEach((a) => a.stop()); // 停掉所有 action
    entry.mixer.uncacheRoot(model);         // 释放绑定缓存
    mixers.delete(model.uuid);
  }
  scene.remove(model);
  model.traverse((obj) => {
    if (obj.geometry) obj.geometry.dispose();
    if (obj.material) {
      (Array.isArray(obj.material) ? obj.material : [obj.material]).forEach(
        (m) => {
          if (m.map) m.map.dispose();
          m.dispose();
        }
      );
    }
  });
}
```

::: tip uncacheRoot vs dispose
`AnimationMixer` 没有 `dispose()` 方法，正确清理方式是 `mixer.uncacheRoot(model)`——它会清掉 mixer 内部为该模型缓存的所有属性绑定（PropertyBinding）和关键帧采样结果。只 `stop()` action 不清缓存，长时间运行仍会泄漏。
:::

::: warning 一个 mixer 绑一个模型
不要试图用一个 mixer 同时驱动多个独立模型。`new AnimationMixer(model)` 的参数决定了动画轨道绑定的根对象，clip 里的轨道名（如 `hips.position`）是相对这个根查找的。多模型共享 mixer 会导致轨道绑定到错误的模型上。多模型就建多个 mixer，用 `Map` 或数组管理。
:::

## 七、KTX2 贴图压缩（顺带提一下）

除了 Draco 压几何，还有 KTX2 压贴图——把 .png/.jpg 转成 .ktx2 格式，GPU 直接读取无需解码，显存占用降一个数量级。配合 Draco 是移动端模型加载的最优解：

```js
import * as THREE from "three";
import { GLTFLoader } from "three/examples/jsm/loaders/GLTFLoader.js";
import { DRACOLoader } from "three/examples/jsm/loaders/DRACOLoader.js";
import { KTX2Loader } from "three/examples/jsm/loaders/KTX2Loader.js";

const ktx2Loader = new KTX2Loader();
ktx2Loader.setTranscoderPath("/ktx2/");
ktx2Loader.detectSupport(renderer); // 需要传 renderer 检测 GPU 能力

const loader = new GLTFLoader();
loader.setDRACOLoader(new DRACOLoader().setDecoderPath("/draco/"));
loader.setKTX2Loader(ktx2Loader);
```

本教程不深入 KTX2，知道有这回事即可。真实项目做到移动端优化时再回来查。

## 八、本节总结

- **三件套**：`AnimationClip`（一段动画）+ `AnimationMixer`（播放器，绑模型）+ `AnimationAction`（播放句柄，控制 play/stop/speed/loop）
- **播放流程**：`gltf.animations` 是 clip 数组 → `new AnimationMixer(model)` → `mixer.clipAction(clip).play()` → 渲染循环里 `mixer.update(dt)`
- **播放控制**：`timeScale` 变速、`loop = THREE.LoopOnce` 单次、`fadeIn/fadeOut` 平滑切换
- **Draco 压缩**：几何数据压 90%+，建模师在 Blender 导出时勾选，前端用 `DRACOLoader.setDecoderPath("/draco/")` + `loader.setDRACOLoader(dracoLoader)` 解压
- **解码器路径**：指向 wasm 文件所在**目录**（以 `/` 结尾），可用 three 自带的或 gstatic CDN
- **KTX2** 是贴图压缩的进阶方案，移动端优化时与 Draco 搭配使用
