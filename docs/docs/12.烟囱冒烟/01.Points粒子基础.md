# Points 粒子基础

如果说 `Mesh` 是用三角形拼出实体物体的"表面"，那么 `THREE.Points` 就是用一个个**点**拼出离散的视觉集合。烟囱口的烟雾、庭院里的落叶、夜空的繁星、燃烧的火焰——这些场景里的"物体"本身没有体积，它们更像是一堆发光的小点。本节我们从最基础的概念讲起，认识粒子系统的三件套：`Points`、`BufferGeometry`、`PointsMaterial`，并亲手为小屋的烟囱顶创建第一批粒子。

## 为什么不用 Mesh

让我们先想一个朴素的问题：要模拟 200 缕烟雾，为什么不能创建 200 个 `Mesh`？

| 方案 | DrawCall 数 | 200 粒子开销 | 适合场景 |
|------|------------|-------------|----------|
| 200 个 Mesh | 200 次 | 200 套 geometry/material，CPU 提交压力大 | 少量实体物体 |
| 1 个 Points | **1 次** | 共享 1 套材质，1 次提交全部绘制 | 大量离散点 |

`Mesh` 每个对象都要独立提交一次绘制调用（DrawCall），200 个就是 200 次。而 `Points` 把所有粒子的位置塞进**同一个几何体**，GPU 一次调用就能画完全部 200 个点，性能差距可达百倍。这就是粒子系统存在的根本理由。

::: tip DrawCall 是什么
DrawCall 是 CPU 向 GPU 发出的一次绘制命令。每次 DrawCall 都有固定开销，因此"合并 DrawCall"是 3D 性能优化的核心目标之一。粒子系统天生就是一次 DrawCall 绘制成百上千个点。
:::

## THREE.Points 三件套

`THREE.Points` 的构造函数接收两个参数，与 `Mesh` 非常相似：

```js
import * as THREE from "three";

// 语法
new THREE.Points(geometry, material)
```

| 参数 | 类型 | 说明 |
|------|------|------|
| `geometry` | `BufferGeometry` | 提供每个粒子的位置（以及可选的颜色、大小） |
| `material` | `PointsMaterial` | 粒子材质，控制颜色、大小、纹理、透明度等 |

三者的协作关系可以这样理解：

- **BufferGeometry** 是"花名册"：记录每个粒子在哪个位置（`position` 属性）
- **PointsMaterial** 是"画笔"：决定每个点画多大、什么颜色、贴什么图
- **Points** 是"画师"：拿着花名册和画笔，一次性把所有点画到屏幕上

::: warning Points 不是 Mesh
`THREE.Points` 与 `THREE.Mesh` 同样继承自 `Object3D`，可以设置 `position`、`rotation`、`scale`，但渲染方式完全不同。`Mesh` 填充每个三角面，而 `Points` 只在几何体的**每个顶点位置**画一个点。也就是说，几何体有多少个顶点，就有多少个粒子。
:::

## BufferGeometry 与 position 属性

粒子的位置由 `BufferGeometry` 提供。我们用 `Float32Array` 构造一个位置数组，再用 `setAttribute` 把它绑定到 `position` 属性上。每个粒子占 3 个分量（x、y、z）。

### 为烟囱顶创建 200 个粒子位置

下面这段代码是本阶段烟雾粒子的初始化核心：在烟囱顶 `(2, 5.3, -1.5)` 附近随机散布 200 个粒子起点。

```js
import * as THREE from "three";

// 粒子数量
const SMOKE_COUNT = 200;
// 烟囱顶中心（与 HOUSE_SPEC 一致）
const SMOKE_ORIGIN = new THREE.Vector3(2, 5.3, -1.5);

// 用 Float32Array 存储位置，每个粒子 3 个分量（x, y, z）
const smokePositions = new Float32Array(SMOKE_COUNT * 3);

// 在烟囱顶附近 ±0.3 的方块内随机散布粒子起点
for (let i = 0; i < SMOKE_COUNT; i++) {
  const i3 = i * 3; // 每个粒子在数组中的起始索引
  smokePositions[i3]     = SMOKE_ORIGIN.x + (Math.random() - 0.5) * 0.3; // x
  smokePositions[i3 + 1] = SMOKE_ORIGIN.y + Math.random() * 0.2;         // y
  smokePositions[i3 + 2] = SMOKE_ORIGIN.z + (Math.random() - 0.5) * 0.3; // z
}

// 创建几何体并写入 position 属性
const geometry = new THREE.BufferGeometry();
// 参数：属性名、数据数组、每个顶点的分量数（位置是 xyz，所以是 3）
geometry.setAttribute("position", new THREE.BufferAttribute(smokePositions, 3));
```

::: tip 为什么用 Float32Array
`Float32Array` 是 JavaScript 的类型化数组（TypedArray），它在内存中连续存放 32 位浮点数，可以直接传给 GPU 缓冲区，无需转换。相比普通 `Array`，它更省内存、上传更快，是 Three.js 几何属性的标准数据载体。
:::

### 索引计算小技巧

注意上面循环里的 `i3 = i * 3`。因为每个粒子占 3 个浮点数，第 `i` 个粒子的 x、y、z 分别位于数组的 `i*3`、`i*3+1`、`i*3+2` 位置。这个 `i3` 写法在粒子代码里会反复出现，务必牢记。

## PointsMaterial 粒子材质

`PointsMaterial` 是专门为粒子设计的材质，它的关键参数如下：

| 参数 | 类型 | 作用 |
|------|------|------|
| `size` | number | 单个粒子的尺寸（世界单位，受 `sizeAttenuation` 影响） |
| `map` | Texture | 粒子贴图，决定每个点的形状（默认是方块） |
| `color` | Color | 粒子颜色（与贴图相乘） |
| `transparent` | boolean | 是否开启透明 |
| `opacity` | number | 整体不透明度（0~1） |
| `depthWrite` | boolean | 是否写深度缓冲（粒子通常设 false） |
| `sizeAttenuation` | boolean | 是否近大远小（透视） |
| `vertexColors` | boolean | 是否启用每粒子独立颜色 |

### 最朴素的方块粒子

先用最简单的方式创建材质，看看默认效果：

```js
const material = new THREE.PointsMaterial({
  size: 0.3,
  color: 0xd3d3d3, // 灰白烟色
  transparent: true,
  opacity: 0.6,
});

const smokePoints = new THREE.Points(geometry, material);
scene.add(smokePoints);
```

运行后你会看到烟囱顶有一团**灰色的小方块**。这能算烟雾吗？显然不能——方块边缘锐利、毫无柔和感。问题就出在没有贴图：默认情况下，`PointsMaterial` 把每个粒子画成一个实心方块。

::: warning 方块伪影
不贴图的粒子默认是方块，这在模拟烟雾、星光、火花时极其违和。解决办法是给 `map` 传一张**边缘透明**的贴图，让方块变成圆形或自定义形状。下一节我们会用 Canvas 程序化生成这张贴图。
:::

## 程序化生成圆形贴图

我们不想为了一张圆形贴图去网上下载图片。Three.js 允许用 Canvas API 现场画一张图，再包装成 `CanvasTexture` 给材质用。这就是"程序化纹理"——代码即美术。

下面这段代码画了一个径向渐变的圆：中心全白不透明，边缘全透明。把它贴到粒子上，方块就变成了柔和的圆点。

```js
/**
 * 生成圆形烟雾贴图：径向渐变从中心半透明白到边缘全透明
 * 关键：边缘必须透明，否则粒子会显示成"方块"而不是"圆点"
 * @returns {THREE.CanvasTexture}
 */
const makeSmokeTexture = () => {
  const size = 64;
  const c = document.createElement("canvas");
  c.width = size;
  c.height = size;
  const ctx = c.getContext("2d");

  // 径向渐变：中心 rgba(255,255,255,1) → 边缘 rgba(255,255,255,0)
  const grad = ctx.createRadialGradient(
    size / 2, size / 2, 0,
    size / 2, size / 2, size / 2
  );
  grad.addColorStop(0.0, "rgba(255,255,255,1)");
  grad.addColorStop(0.4, "rgba(255,255,255,0.6)");
  grad.addColorStop(1.0, "rgba(255,255,255,0)");
  ctx.fillStyle = grad;
  ctx.fillRect(0, 0, size, size);

  const tex = new THREE.CanvasTexture(c);
  tex.needsUpdate = true;
  return tex;
};
```

把这张贴图传给材质：

```js
const material = new THREE.PointsMaterial({
  size: 0.3,
  map: makeSmokeTexture(), // 圆形渐变贴图
  transparent: true,
  opacity: 0.6,
  depthWrite: false, // 不写深度，避免粒子相互切割
  color: 0xd3d3d3,
  sizeAttenuation: true,
  blending: THREE.NormalBlending,
});
```

现在再运行，烟囱顶就是一团柔和的灰白圆点了。

::: tip depthWrite 为何设 false
粒子是半透明的，如果开启深度写入，靠近相机的粒子会把远处粒子"挡住"（写入深度缓冲），导致半透明叠加出现切割伪影。设为 `false` 后，粒子之间不会互相遮挡，半透明颜色能正确混合，烟雾才有"层次感"。
:::

## 组装第一批粒子

把上面三部分合起来，就是一个最小可运行的粒子系统。下面是 `HouseScene.vue` 中 `addSmokeParticles` 的简化骨架：

```js
const addSmokeParticles = () => {
  // 1. 位置数组
  const positions = new Float32Array(SMOKE_COUNT * 3);
  for (let i = 0; i < SMOKE_COUNT; i++) {
    const i3 = i * 3;
    positions[i3]     = SMOKE_ORIGIN.x + (Math.random() - 0.5) * 0.3;
    positions[i3 + 1] = SMOKE_ORIGIN.y + Math.random() * 0.2;
    positions[i3 + 2] = SMOKE_ORIGIN.z + (Math.random() - 0.5) * 0.3;
  }

  // 2. 几何体 + position 属性
  const geo = new THREE.BufferGeometry();
  geo.setAttribute("position", new THREE.BufferAttribute(positions, 3));

  // 3. 材质 + 圆形贴图
  const mat = new THREE.PointsMaterial({
    size: 0.3,
    map: makeSmokeTexture(),
    transparent: true,
    opacity: 0.6,
    depthWrite: false,
    color: 0xd3d3d3,
    sizeAttenuation: true,
  });

  // 4. Points 对象加入场景
  const smokePoints = new THREE.Points(geo, mat);
  smokePoints.frustumCulled = false; // 禁用视锥剔除，避免粒子升出包围盒后消失
  scene.add(smokePoints);
};
```

::: warning frustumCulled 的坑
`Object3D` 默认开启视锥剔除：物体若在相机视锥外就不渲染。粒子的包围盒是根据初始位置计算的，当烟雾升高超出原始包围盒时，整团粒子可能突然消失。设 `frustumCulled = false` 可避免这个诡异现象。
:::

## 资源释放

粒子系统创建了 `geometry`、`material`、`texture` 三类 GPU 资源，组件卸载时必须全部释放，否则会内存泄漏。在 `disposeScene` 中：

```js
// 释放粒子贴图（map 不在常规 track 列表里，单独 dispose）
if (smokeTexture) {
  smokeTexture.dispose();
  smokeTexture = null;
}
// 粒子对象从场景移除
if (smokePoints) {
  if (smokePoints.parent) smokePoints.parent.remove(smokePoints);
  smokePoints = null;
}
// geometry / material 走统一的 disposables 释放流程
```

::: tip 完整 dispose 清单
粒子系统的资源释放要覆盖四类对象：`geometry`（几何体）、`material`（材质）、`material.map`（贴图）、`Points` 对象本身（从场景移除）。漏掉任何一项都会造成显存泄漏，长时间运行后帧率骤降。
:::

## 本节总结

本节我们搭建了粒子系统的认知地基：

- `THREE.Points` 用**一次 DrawCall** 渲染大量离散点，性能远超创建等量 Mesh
- `BufferGeometry` 通过 `position` 属性（`Float32Array`）提供每个粒子的位置
- `PointsMaterial` 控制粒子的大小、颜色、贴图、透明度，`depthWrite: false` 是半透明粒子的关键
- 默认粒子是方块，需要用程序化 `CanvasTexture` 生成边缘透明的圆形贴图才能变柔和
- 别忘了 `frustumCulled = false` 和完整 `dispose`
